# 文字列内埋め込み要素の展開

## 概要

YAYAでは変数や関数を文字列内に埋め込み、その結果を指定した位置に挿入できる。

## 2種類の展開方式

### 1. 範囲付き展開

**構文:** `%( )` で要素を囲む

カッコ内はコードとして評価される。変数だけでなく式もサポートする：

```
"This is a %(variable)."
"The sum is %(1+2+3)."
```

**特徴:**
- 複雑な式や数学演算をサポート
- 文字列内にダブルクォートを含めることができない
- 辞書読み込み時に静的に解析されるため、`DICLOAD` で動的に読み込まれた関数は認識されない
- 動的な評価が必要な場合は `EVAL` 関数を使用する

**演算子優先度:** カッコが評価順序を制御する。深いネストほど先に実行される。必要なら `%((expression))` のように余分なカッコを使う。

### 2. 名称最長一致展開

**構文:** カッコなしで `%` のみ使用

`%` の後に続く最長の変数名または関数名にマッチする：

```
object = "world"
"This is a %object."  // 結果: "This is a world."
```

**特徴:**
- 展開対象は現在定義されている変数・関数によって変わる
- `%[i]` 構文（0始まりインデックス）で展開結果を再利用できる：
  `"First: %planet, Second: %city, reuse first: %[0]"`
- 実行時に名前解決するため、範囲付き展開より大幅に遅い
- パフォーマンスが重要なコードには推奨しない

**注意:** `%[i]` 構文は名称最長一致展開でのみ機能し、範囲付き展開では使えない。

### 名前を読み込み時に確定する

名称最長一致展開は、実行した時点で存在する変数で名前を探す。そのため、URL などの `%` を含む文字列が、ある時点から急に置き換わることがある。

```
"https://example.com/?p=100%off"  // 変数 o や of が作られると、その値に置き換わる
```

設定ファイルに `embed.lazy, off` と書くと（Tc604-1以降）、カッコなしの `%` の後の名前を辞書の読み込み時に確定する。

- 名前は、ユーザー関数・システム関数と、辞書の式に名前が書かれたグローバル変数（`EVAL` などで実行した式も含む）の最長一致で決める。セーブファイルから復元しただけの変数や、`LETTONAME` で作っただけの変数は対象にならない。こうした変数を埋め込むときは `%(名前)` と書く
- 確定した変数がまだ値を持っていないときは、空文字列になる（`%名前` のまま残らない）
- どの名前とも一致しなかったものは、`%` を含めてそのまま文字列として扱う。英字や全角文字で始まるものには警告 W0031 を出す。`%E3` のような 16 進数 2 桁（URL エンコード）や、数字・記号で始まるものは警告しない
- ローカル変数（`%_name`）は、従来どおり実行時に名前を探す
- `%[i]` の番号は、文字列のまま残ったものも 1 つと数える（`embed.lazy` の設定で番号は変わらない）
