# 配列

## 概要

`[ ]` 演算子で配列要素にアクセスする。YAYAは2種類の配列をサポートする：**簡易配列**（コンマ区切り文字列を扱う）と**汎用配列**（混合型コレクション）。

## 簡易配列

コンマをデリミタとして文字列内で解釈する：

```
_a = "this,is,a,pen"
_a[1]  // "is" を出力
```

**カスタムデリミタ:** インデックスの後に指定できる：

```
"This is a island."[2,"is"]  // " a " を出力
```

**ネストアクセス:** デリミタを段ごとに変えられる：

```
_ar = "taro|male,ayame|female,hotaru|female"
_ar[2][1,"|"]  // "female" を出力
```

**代入:** 元の変数の要素を変更できる：

```
_a[3] = "eraser"       // 要素を置き換える
_m[5,"/"] = "daisen"   // 必要に応じてデリミタで拡張する
```

`SETDELIM()` 関数でデフォルトデリミタをコンマ以外に変更できる。

## 汎用配列

カッコとコンマ記法で混合型の値を格納する：

```
i = (100,"test",-1.5)
```

**単一要素の初期化** は `IARRAY` と組み合わせて行う：

```
i = (IARRAY,100)
```

**要素操作:**
- **追加:** `i = (i,"add")` または `i ,= ("add",123,0.0)`
- **削除:** `i[2] = IARRAY`
- **挿入:** `i = ("first",i)` または `i[2] ,= "insertion"`

**演算:** 配列とスカラー値の演算は要素ごとに適用される：

```
pref = ("gunnma","ohsaka")
pref += "-ken"  // すべての要素に "-ken" が追加される
```

配列同士の演算はすべての組み合わせを生成する：

```
pref1 = ("gunma","osaka")
pref2 = ("-ken","-fu")
pref1 + pref2  // 4つの結果を生成
```

**要素の比較:** 配列同士を `==` で比べると、要素ごとに比べる。Tc600-3以降では、要素が**両方とも VOID** のときも等しいとみなす（それまでは偽だった）。

## 入れ子と多次元代入（Tc600-3以降）

配列の要素にハッシュを入れたり、ハッシュの値に配列を入れたりできる。読み出しは `_a[1]["x"]`、代入は `_a[1]["x"] = 5` のように `[ ]` を続けて書く。

```
_a = (0, IHASH("x", 1), 2)
_a[1]["x"]        // 1
_a[1]["x"] = 5    // 多次元代入
```

多次元代入では、途中の要素が文字列なら簡易配列として書き換える：

```
_a = ("p,q", "r")
_a[0][1] = "Q"    // _a[0] は "p,Q"
```

ただし、汎用配列の中に新しく汎用配列を入れる手段は無い。`,` 演算子も `_a[1] = (8,9)` も、配列を展開して差し込む。代入先の要素がすでに配列やハッシュのときだけは、展開せずに丸ごと置き換える（Tc603-1以降。[内側の配列やハッシュを丸ごと書き換える](13-nesting.md#内側の配列やハッシュを丸ごと書き換える)）。

詳細は [値の入れ子と多次元代入](13-nesting.md) を参照。

## 範囲指定

両方の配列型で範囲インデックス `[a,b]` を使った取得・代入ができる：

```
name = ("さくら","せりこ","奈留","まゆら")
i = name[1,3]            // 要素1〜3
name[3,4] = "奎子"
animal[0,2,"！"]         // デリミタ付き範囲
```

## 範囲外の要素

範囲外の要素を読むと、簡易配列でも汎用配列でも、未定義の変数と同じく **VOID** になる（Tc574-8 / Tc603-1以降）。範囲指定の読み出しが範囲外のときは、空の範囲（簡易配列なら空文字列、汎用配列なら空の配列）になる。

```
_a = (1, 2)
_a[9]            // VOID
_a[9] == ""      // 1
_a[9] == 0       // 1
_a[9] + 1        // 1 （整数）
GETTYPE(_a[9])   // 0
_a[5, 6]         // 空の配列
"a,b"[5, 6]      // ""
```

- VOID は文字列としては空文字列、数値としては 0 として扱われる。`== ""` や `if _a[9]` の結果は、空文字列だったときと変わらない
- 関数の最後の行などで範囲外の要素をそのまま書いても、出力の候補にはならない（未定義の変数と同じ。空文字列だったときは空文字列が候補になっていた）
- 数値に `[ ]` を付けたとき（`5[1]`）は、要素が1つの配列とみなす。0 番目はその数値、それ以外は VOID
- 末尾より先の要素へ代入すると（`_a[9] = 1`）、間は VOID で埋められる。埋める個数の上限は 16,777,216 個で、超える代入（`_a[2000000000] = 1` など）はメモリ不足として扱われ、E0100 で実行が中断されて `shiori.OnMemoryError` が呼ばれる（Tc603-4以降。それまでは上限が無く、メモリを使い尽くすことがあった）
- 範囲外の要素への複合代入（`_a[9] += 1`）も VOID として計算するので、整数の 1 になる（600 系では Tc602-10 から。500 系では Tc574-8 から）
- Tc574-7 / Tc602-13 までは、汎用配列の範囲外は空文字列、簡易配列の範囲外は VOID と、配列の種類で結果が違っていた。そのため `_a[9] == 0` は偽、`_a[9] + 1` は文字列 `"1"`、`GETTYPE(_a[9])` は 3 だった。簡易配列の範囲指定が範囲外のときは VOID、数値の範囲指定が範囲外のときも VOID だった

## 並列出力

`parallel` キーワードで配列要素を別々の出力候補に変換する：

```
foo { parallel ("A","B","C") }  // A、B、Cのいずれかを出力
```

`void` キーワードは出力候補を生成せずに結果を破棄する。
