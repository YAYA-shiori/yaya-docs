# REQUESTLIB
**Category:** 外部ライブラリ

## Signature
```
REQUESTLIB( path , string )
```

## Parameters
| Parameter | Description |
|-----------|-------------|
| path | DLL location. A relative path from the location of YAYA, or an absolute path. |
| string | The string to pass to the request function |

## Returns
- Success: The string generated by the request function
- Failure: VOID (returns nothing)

## Description
Calls the request function of a previously loaded external library and gets its result. The external library DLL must have the same interface as YAYA (exports load/unload/request functions).

From Tc604-1 onward, specifying a SAORI-basic executable loaded with [LOADLIB](LOADLIB.md) causes YAYA to launch the executable and return a SAORI/1.0 response ([details](LOADLIB.md#saori-basic)).

### Interaction with threads
If you call a slow external library from a thread started with [THREADSTART](THREADSTART.md), SSP can continue processing `request` calls and other threads while it waits.

- An external library can only be called by one thread at a time, so calls to the same library are executed in sequence. If another thread is calling the same library, the call waits for it to finish. Different libraries can be called simultaneously
- If another thread calls [UNLOADLIB](UNLOADLIB.md) on a library that is currently being called, the library is not unloaded (warning W0013)
- The external library is called from the `THREADSTART` thread. SAORI implementations that require calls from a particular thread, such as those using COM or windows, may not work when called from a worker thread
- A call cannot be interrupted while in progress. [THREADSTOP](THREADSTOP.md) takes effect after the call returns

## Compatibility
- YAYA: Available since the initial release
- AYA: Available since version 5.8
- Tc604-1: Added support for SAORI-basic executables
- Tc608-1: Allowed other threads to run while waiting (when a `THREADSTART` thread is running). Calls to the same library are now executed in sequence
