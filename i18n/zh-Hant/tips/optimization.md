### 加快啟動速度

使用 AYA 的人格通常都有啟動速度慢的缺點，許多人也因此感到困擾。這裡將介紹與加快啟動有關的簡單調校方法。

#### 安裝了許多人格的環境啟動速度很慢

如今安裝的人格總數膨脹到四位數左右，安裝數達到三位數的環境想必也不少。
……這倒是沒什麼問題，但本體通知的人格資訊也會變得非常龐大，AYA 解析起來很費力，因而產生麻煩的問題。

#### 簡單的 Tips

**踩雷程度**：★★☆☆☆

解決方法很簡單，只要把 aya_shiori3.dic 前段的幾個 #define 定義

```
#define IGLIST_MAX 0
#define REQUEST_LINES_LIMIT 30
```

修改成這樣即可。

**IGLIST_MAX**：AYA 有一項功能，不依賴本體，而是在內部不斷搜尋已安裝人格的資訊。這個設定用來表示是否啟用該功能，設為 0 表示停用，-1 表示不限制。若不需要，停用也完全沒有問題。

**REQUEST_LINES_LIMIT**：本體與人格之間會以多行字串進行通訊。這項設定的用意，是限制解析時處理的行數，避免解析大量通知時耗費太多時間。

另外，如果人格需要處理已安裝的人格／對話方塊等資訊，修改這些設定可能會造成問題。

#### 提供給想再多試一點的人：Tips

**踩雷程度**：★★★★☆

……那麼，獻給還是無法忍受的人！這個 Tips 會直接停用取得人格資訊的功能。

在 aya_shiori3.dic 大約第 600 行之後，應該會有 On_installedghostname。請將它全部註解掉。

```
    (ごにょごにょ)

```

大概就是像這樣。

### 隨機對話出現得很慢

……但是，這個也太慢了吧……

這是提供給某些特殊需求者的加速 Tips。

#### 使用單引號加速

**踩雷程度**：★★★★☆

隨機對話大概是寫在 aya_aitalk.dic 裡吧。

```
RandomTalk
{
   "ごにょごにょ"
}
```

大概像這樣。

用 " " 括起來，直接寫入一大串 Sakura Script；但其實新版 AYA 除了 " " 以外，也可以使用 ' '。

為什麼這會有關係呢！在解釋之前，先舉個修改後的例子。<br>
總之，如果你不想管原理、只想馬上使用，直接複製貼上這段就好。

```
RandomTalk
{
    TOSTR(EVAL(CHR(0x22)+RandomTalkEx()+CHR(0x22)))
}

RandomTalkEx
{
    'ごにょごにょ'
}
```

沒錯，只要把原本的 RandomTalk 改個名稱（這裡改成了 RandomTalkEx），將內容文字的括法改成 ' '，再加上有奇怪指令的 RandomTalk 就行了。((外層的 TOSTR 應該可以省略，不過為了以防萬一才加上去。介意的話就把它拿掉吧。))

……接下來說明其中的原理。

AYA5 新版導入的 ' '，意思是**不展開 %()**。<br>
詳細內容請參閱 AYA 的手冊；透過 %hogehoge 或 %(hogehoge) 等方式，將變數、函式或運算式等嵌入內容的功能，在用 ' ' 括起來時會全部停用。

原本使用 " " 時，必須解析所有嵌入處理並求出結果；使用 ' ' 時，被括起來的部分只會視為一般字串，因此幾乎不需要進行任何處理。

請回想一下 AYA 的行為：函式內的所有內容都會被求值，然後從中選出一個結果（隨機選擇，或依選項選擇其中一個）。

……先不管這段複雜的說明，簡單來說，**如果寫了好幾百則隨機對話，就得執行好幾百次 %() 處理**，應該不難想像這會拖慢速度。((知道 AYA 實際內部處理方式的人可能會提出指正，不過這裡只採用容易理解的說法))

那麼，改名為 RandomTalkEx 的部分就說明完了；但如果維持目前的寫法，%() 的內容就不會正確嵌入。解決方法就是：

```
TOSTR(EVAL(CHR(0x22)+RandomTalkEx()+CHR(0x22)))
```

TOSTR 是「將內容視為字串」的指令，但在這裡沒有什麼特別的含意。**關鍵在於 EVAL 及括號內的內容**。

EVAL 是「將括號括起來傳入的內容，當成 AYA 腳本執行」的指令。而 CHR(0x22) 就是 "。

……大概已經看出發生什麼事了。EVAL 執行的腳本會是：

```
" + RandomTalkExの結果 + "
```

這樣就會組成一個進行 %() 嵌入處理的運算式。<br>
原本必須反覆執行好幾百次的 %() 處理，現在只要透過這個 EVAL 包起來的部分執行一次，就能達到加速效果。
