# 函式

## 概要

YAYA 中的「函式」是指，

- 接受 0 個以上的引數
- 從 0 個以上的「輸出候選」中選出 1 個輸出並傳回

的一組處理。

引數的數量儲存在變數 `_argc` 中，各個引數則儲存在變數 `_argv[n]` 中。n 是從 0 開始的引數編號。

輸出候選是指直接寫在函式內的字串、數值、變數名稱等，沒有左值（`=` 左側）的一組項目。若有多個輸出候選，YAYA 會從中選出 1 個，作為函式的輸出（傳回值）。

若存在多個同名函式，便會發生錯誤（尤其是以既有的人格為基礎進行改編時，請特別注意）。

以下的「基本結構」，是通用語言 DLL 中的 YAYA 所使用的「函式」。若不太了解，可以先略過。

## 基本結構

以下展示在執行 `request` 時，傳回字串 `"Hello World"` 的程式碼全文。

```
request
{
    "Hello World"
}
```

載入 YAYA 的模組執行 `HGLOBAL request(HGLOBAL h, long *len)` 時，便會執行這段指令碼並傳回 `"Hello World"`。`load` 和 `unload` 也相同。不過，`load` 和 `unload` 不會傳回值，因此即使寫入輸出字串也沒有意義。在 `load` 中撰寫初始化處理，例如為變數設定初始值；在 `unload` 中則撰寫相反的收尾處理。

只需要撰寫必要的函式，不需要的部分可以省略。例如在上面的範例中沒有撰寫 `load` 和 `unload`，但這不會造成錯誤，只是不會執行任何動作。舉個極端的例子，即使完全沒有辭典檔案，也不會發生錯誤。在這種情況下，`load` 和 `unload` 不會執行任何動作，`request` 則會傳回空字串。

`load` 和 `request` 各有一個引數，可以透過變數取得。變數名稱為 `_argc` 和 `_argv`，與 C 語言 `main` 函式的介面類似。

### _argc

引數的數量。在 `load` 和 `request` 中，引數是一個字串，因此值為 1。`unload` 沒有引數，因此此值為 0。

### _argv

儲存引數本身。這是一個具有 `_argc` 個元素的陣列，可使用運算子 `[i]` 存取各個元素。索引 i 從 0 開始。例如，若 `_argc` 為 1，便可以使用 `_argv[0]`，引數會儲存在其中。

以下作為基礎篇的總結，展示在 `load` 中將 `"Hello"` 存入變數 `str`，並在 `request` 中將作為引數傳入的字串與 `str` 結合後傳回的程式碼。

```
load
{
    str = "Hello"
}

request
{
    str + " " + _argv[0] + "!"
}
```

將處理對象字串設為 `"World"` 並執行 `request`，結果會得到 `"Hello World!"`。

## 格式

以下是相關規則。

- 空白行（只有換行的行）、`//` 之後的內容，以及以 `/*` 和 `*/` 括住的區域，都會視為註解
- 若一行以斜線（`/`）結尾，下一行會接在該行後面
- 行首以及單字之間都可以自由加入空白字元。空白字元包括空格和定位字元
- 若要將多個敘述集中寫在同一行，可以用分號（`;`）分隔

也就是說，前面提到的 Hello World 程式碼可以集中寫成一行，如下所示。

```
request{"Hello World"}
```

也可以像下面這樣撰寫（但不建議這種寫法）。

```
req/
uest          {
"/
Hello World"  }
```

`/` 後一行（將接在前一行後的新行）開頭的空白字元會視為縮排字元，並予以移除。因此，以下字串的結合結果是 `"ABCDEFG"`，而不是 `"ABCD　　EFG"`。

```
"ABCD/
    EFG"
```

關於第 4 條規則。以下的 `request` 會計算 1+2 的答案，並以日文句子傳回。

```
request
{
    answer = 1 + 2
    "答えは" + answer + "です。"
}
```

使用分號後，可以像下面這樣撰寫。

```
request
{
    answer = 1 + 2; "答えは" + answer + "です。"
}
```

即使多寫分號也沒有問題。多餘的分號會被忽略，不會影響執行。因此，如果習慣 C 語言的格式，也可以在每一行結尾都加上分號。

## 使用者自訂函式的定義與執行

除了 `load`、`unload` 和 `request` 之外，也可以建立任意名稱的函式。只要寫出建立的函式名稱，就可以執行該函式。

```
request
{
    hello
}

hello
{
    "Hello World"
}
```

上面是最簡單的範例，`request` 最後會傳回 `"Hello World"`。以下展示一個稍微複雜一些，但會得到相同結果的範例。

```
request
{
    combine("Hello", "World")
}

combine
{
    _argv[0] + " " + _argv[1]
}
```

在函式名稱後面加上 `( )`，並在其中以逗號分隔列出值，這些值便會作為引數傳給對應的函式。也就是說，值會儲存在變數 `_argv` 和 `_argc` 中，並可在該函式內參照。在這個範例中，`combine` 函式內的 `_argc` 為 2、`_argv[0]` 為 `"Hello"`、`_argv[1]` 為 `"World"`。

### 不可用於函式名稱的名稱

函式名稱可以自由命名，但以下名稱會導致錯誤。

- 以數字 0〜9 開頭
    - 可能會被解讀為數值常數
- 以底線（`_`）開頭
    - 以底線開頭的名稱會用於區域變數
- 包含以下字元：空白　`!`　`"`　`#`　`$`　`%`　`&`　`(`　`)`　`*`　`+`　`,`　`-`　`/`　`:`　`;`　`<`　`=`　`>`　`?`　`@`　`[`　`]`　`` ` ``　`{`　`|`　`}`　`~`
    - 最好不要使用底線以外的符號
- 與保留字完全相同
    - 英文字母大寫加底線的名稱會用於系統函式
    - 也請避免使用 `for`、`while`、`if` 等用於控制結構的名稱

### 遞迴呼叫

函式可以遞迴呼叫。以下以最常見的階乘計算為例。

```
request
{
    factorial(5)
}

factorial
{
    if !_argv[0]
        1
    else
        factorial(_argv[0] - 1)*_argv[0]
}
```

`request` 會傳回 120。

## 選擇方式

```
request
{
    "Hello World"
    "こんにちは世界"
    "Hallo Welt"
}
```

像這樣列出時，這些內容會被視為同等的「輸出候選」，輸出結果會是其中一個。可以指定以下任一種選擇方式。不過，`void` 和 `array` / `pool_array` 僅用於特殊用途。

| 方式 | 說明 |
|------|------|
| 未指定 / `random` | 隨機選擇（預設） |
| `nonoverlap` | 盡可能不選擇與緊鄰前一次相同的候選 |
| `sequential` | 按照寫出的順序輸出，輸出到最後一個後再回到第一個 |
| `array` | 傳回結合所有輸出候選的通用陣列 |
| `void` | 不輸出任何內容 |
| `all`（Tc567-1） | 將所有候選結合成一個字串 |
| `last`（Tc567-1） | 選擇最後一個候選 |

在函式名稱後面加上 `: nonoverlap` 之類的內容，即可指定選擇方式。

```
request : nonoverlap
{
    "Hello World"
    "こんにちは世界"
    "Hallo Welt"
}
```

```
request : sequential
{
    "Hello World"
    "こんにちは世界"
    "Hallo Welt"
}
```

有些函式的輸出候選數量會因每次執行而異。例如，以下函式的候選數會依變數 `i` 的值，變為 2 個或 4 個。

```
request : sequential
{
    if i {
        "1"
        "2"
    }
    "3"
    "4"
}
```

候選數量變動時，`nonoverlap` 和 `sequential` 的循環順序會重設，並從頭開始。只有在這種情況下，才可能與前一次重複輸出相同的值。

### array

將所有輸出候選結合成通用陣列，並將其作為函式的傳回值。

```
request : array
{
    "This is a pen."
    ("A","B","C")
    3.14
}
```

輸出結果會是通用陣列 `("This is a pen.", "A", "B", "C", 3.14)`。

### void

不會輸出任何內容。在以下範例中，`request` 不會輸出 3 個候選中的任何一個。

```
request : void
{
    "Hello World"
    "こんにちは世界"
    "Hallo Welt"
}
```

請注意，這不是「什麼都不執行」，而是「不輸出任何內容」。內部寫入的函式或運算式仍會處理。

```
increment_i : void
{
    i++
    i
}
```

上述函式 `increment_i` 會將 `i` 加 1。若未指定 `void`，此函式會傳回加法結果；指定 `void` 時則不會傳回值，只會執行加法。

### all

於 Tc567-1 實作。將所有選擇候選結合成一個字串。

### last

於 Tc567-1 實作。從選擇候選中，選擇最後一個候選作為輸出。

## 修飾子

**`_pool`**：將附加 `_pool` 的區塊內部候選拆開，與外側候選放在同一層選擇。可以附加在函式本身（`OnTest : _pool`），也可以附加在區塊（`_pool : {`）。

一般而言，巢狀區塊整體會算作 1 個候選。以下範例中，`"x"` 的選中機率為 1/2，`"y"` 和 `"z"` 則各為 1/4：

```
OnTest
{
  "x"
  {
    "y"
    "z"
  }
}
```

附加 `_pool` 後，內側區塊的候選會拆開，`"x"` `"y"` `"z"` 的選中機率便會各為 1/3：

```
OnTest : _pool
{
  "x"
  {
    "y"
    "z"
  }
}
```

- 無論巢狀幾層，都會拆開（若在第三層加入 `"z"` `"w"`，4 個候選的選中機率便會各為 1/4）
- `if` `elseif` `else` 內的內容也會拆開。條件為假而不執行的區塊，其候選不會加入。若寫成 `if 條件 { "b" "c" }`，則只有條件為真時，`"b"` `"c"` 才會以與外側候選相同的機率被選中
- `while` `for` `foreach` 內的候選會在每次迴圈時各加入 1 個（執行 2 次的 `for` 中的 `"y"` 會算作 2 個候選）
- 以 `nonoverlap : {` 這種方式指定選擇方式的區塊不會拆開，仍會作為 1 個候選
- 與選擇方式搭配時，寫成 `_pool_nonoverlap` `_pool_sequential` 等形式（可以省略 `_`）。未指定方式時會使用 `random_pool`（也可以只寫 `pool`），以隨機方式選擇。也可以寫成 `nonoverlap_pool`、`sequential_pool`、`array_pool` 等形式。避免重複或選擇順序的處理會套用至拆開後的所有候選
- 附加在區塊時，只會作用於該區塊內部。外側區塊的候選則會將該區塊視為 1 個候選
- 同一個區塊或函式不能同時指定 `_pool` 和 `melt_`

```
OnTest : _pool_nonoverlap
{
  "通常のセリフ"
  if is_rainy {
    "雨の日のセリフ1"
    "雨の日のセリフ2"
  }
}
```

`is_rainy` 為真時，3 句對話會以相同機率選出，且不會連續重複。為假時則只會選擇 `"通常のセリフ"`。

**`melt_`**：使用通用陣列產生平行輸出效果。附加在區塊時，若該區塊選出的輸出是通用陣列，便會拆開其元素，並加入緊鄰外側區塊的輸出候選中（效果與 [`parallel`](05-arrays.md) 相同）。也可以與選擇方式搭配，例如 `melt_nonoverlap`。若內側區塊未指定選擇方式，也會沿用此選擇方式。

```
OnTest
{
    "test"
    "test2"
    melt_nonoverlap : {
        ("red","green","blue")
    }
}
```

結果：會選擇 "test"、"test2"、"red"、"green"、"blue" 中的任一項。

附加在函式本身時，由於沒有外側區塊，會先拆開通用陣列候選，再進行選擇（Tc574-9 / Tc603-2 之後）。以 `return` 傳回的通用陣列不會拆開。

```
OnTest : melt_nonoverlap
{
    "test"
    "test2"
    ("red","green","blue")
}
```

結果：與上述相同，會從 5 個候選中選擇，並避免重複。

在 Tc574-8 / Tc603-1 以前，附加在函式本身的 `melt_` 不會生效，通用陣列會直接作為 1 個候選。此外，附加在內側第二層或更深層區塊的 `melt_`，會加入函式最外層區塊的候選，而不是緊鄰外側區塊的候選。

## 巢狀結構

```
request
{
    {
        "Hello World"
        "こんにちは世界"
    }

    "Hallo Welt"
}
```

`{ }` 可以階層式地任意巢狀。其運作方式與最上層的 `{ }` 相同，會從所包含的候選項中選出一項並輸出。不過，選擇方式僅限隨機抽取，不能像最上層那樣指定 `nonoverlap` 或 `sequential`（Tc564-1 之後，可透過下方的「巢狀結構中的選擇方式」指定）。

在上面的範例中，不論有沒有 `{ }`，結果看起來或許都一樣，但其實並非如此。沒有 `{ }` 時，每個項目的輸出機率都相同，為 1/3。但在上面的範例中，會先從 `"Hello World"` 和 `"こんにちは世界"` 中選出一項，接著再從該結果與剩下的 `"Hallo Welt"` 中抽取輸出。因此，`"Hello World"` 和 `"こんにちは世界"` 的出現率為 1/4，`"Hallo Welt"` 則為 1/2。

### 巢狀結構中的選擇方式

Tc564-1 之後，可以為每個巢狀結構加上前一節所述的選擇方式。

```
request
{
    nonoverlap : {
        "Hello World"
        "こんにちは世界"
    }

    "Hallo Welt"
}
```

若要指定在 `if` 敘述等之後接續的 `{ }`，可以用 `;` 分隔，如下所示，或加入換行。

```
request
{
    if 1 ; nonoverlap : {
        "Hello World"
        "こんにちは世界"
    }

    "Hallo Welt"
}
```

```
request
{
    if 1
    nonoverlap : {
        "Hello World"
        "こんにちは世界"
    }

    "Hallo Welt"
}
```

## 輸出確定子

```
request
{
    "Hello"
    "Perfect"
    "Peaceful"
    --
    " Wor"
    --
    "ld"
    "th"
}
```

`--` 稱為輸出確定子，候選項會以此為界分組。接著，各組選出的結果會合併成一個字串。因此，執行上面的 `request` 時，會輸出下列其中一種結果。

```
"Hello World"
"Perfect World"
"Peaceful World"
"Hello Worth"
"Perfect Worth"
"Peaceful Worth"
```

`--` 必須單獨寫在一行。不能像 `"Hello" / "Perfect" -- …` 這樣寫在同一行；`/` 會被視為除法。

與 `nonoverlap`、`sequential`、`array` 搭配使用時，會套用到函式可能產生的所有組合（而非以群組為單位）。

例如，`sequential`：

```
request : sequential
{
    "1"
    "2"
    "3"
    --
    "A"
    "B"
}
```

會依照下列順序產生輸出。

```
"1A" "2A" "3A" "1B" "2B" "3B" "1A" "2A" …
```

`array`：

```
request : array
{
    "1"
    "2"
    "3"
    --
    "A"
    "B"
}
```

會輸出通用陣列 `("1A","1B","2A","2B","3A","3B")`。

YAYA 除了字串之外，也能處理數值等資料，但輸出確定子在合併時會將它們全部轉換成字串，再以字串的形式合併。
