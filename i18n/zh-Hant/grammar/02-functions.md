# 函式

## 概要

YAYA 中的「函式」是指，

- 接受 0 個以上的引數
- 從 0 個以上的「輸出候選」中選出 1 個輸出並傳回

的一組處理。

引數的數量會儲存在變數 `_argc` 中，各引數則會儲存在變數 `_argv[n]` 中。n 是從 0 開始的引數編號。

輸出候選是指直接寫在函式中的字串、數值、變數名稱等不具有左值（`=` 左側）的項目。若有多個輸出候選，YAYA 會從中選出 1 個作為函式的輸出（傳回值）。

如果存在多個同名函式，就會發生錯誤（尤其是以既有的人格為基礎進行改編時，請特別注意）。

以下的「基本結構」是指 YAYA 作為通用語言 DLL 時所使用的「函式」。如果不太明白，可以先略過。

## 基本結構

以下顯示一段程式碼，其整體會在執行 `request` 時傳回字串 `"Hello World"`。

```
request
{
    "Hello World"
}
```

載入 YAYA 的模組執行 `HGLOBAL request(HGLOBAL h, long *len)` 時，便會執行這段指令碼，並傳回 `"Hello World"`。`load` 和 `unload` 也相同。不過，`load` 和 `unload` 不會傳回值，因此即使寫入輸出字串也沒有意義。`load` 可用來撰寫將初始值指派給變數等初始化處理，而 `unload` 則可撰寫相反的清理程式碼。

只要撰寫必要的函式即可，不需要的函式可以省略。例如上面的範例沒有撰寫 `load` 和 `unload`，但這不會造成錯誤，只是不執行任何操作而已。極端來說，即使完全沒有辭典檔案也不會發生錯誤。此時 `load` 和 `unload` 不會執行任何操作，而 `request` 會傳回空字串。

`load` 和 `request` 各有一個引數，可以透過變數取得。變數名稱是 `_argc` 和 `_argv`，與 C 語言 `main` 函式的介面類似。

### _argc

引數的數量。`load` 和 `request` 的引數是一個字串，因此此值為 1。`unload` 沒有引數，因此此值為 0。

### _argv

儲存引數的實際內容。這是一個具有 `_argc` 個元素的陣列，可使用運算子 `[i]` 存取各個元素。索引 i 從 0 開始。例如，`_argc` 為 1 時可以使用 `_argv[0]`，引數會儲存在其中。

以下作為基礎篇的總結，示範一段程式碼：在 `load` 中將 `"Hello"` 儲存到變數 `str`，並在 `request` 中將作為引數傳入的字串與 `str` 串接後傳回。

```
load
{
    str = "Hello"
}

request
{
    str + " " + _argv[0] + "!"
}
```

若將處理對象字串設為 `"World"` 並執行 `request`，結果會是 `"Hello World!"`。

## 格式

有以下規則。

- 空行（只有換行的行）、`//` 之後的內容，以及以 `/*` 和 `*/` 括住的區域，都會被視為註解
- 若一行的結尾是斜線（`/`），下一行會接在該行後面
- 行首以及單字之間可以自由加入空白字元。空白字元包括空格和定位字元
- 若要將多個陳述式塞在同一行，可以用分號（`;`）分隔

也就是說，前面列出的 Hello World 程式碼可以像下面這樣塞在同一行。

```
request{"Hello World"}
```

寫成下面這樣也可以執行（不過不建議這樣寫）。

```
req/
uest          {
"/
Hello World"  }
```

`/` 下一行（會接在前一行後面的行）開頭的空白字元會被視為縮排字元，並予以移除。因此，以下字串的串接結果是 `"ABCDEFG"`，而不是 `"ABCD　　EFG"`。

```
"ABCD/
    EFG"
```

接著說明第 4 個規則。以下的 `request` 會計算 1+2 的答案，並將結果組成日文句子傳回。

```
request
{
    answer = 1 + 2
    "答えは" + answer + "です。"
}
```

使用分號可以寫成下面這樣。

```
request
{
    answer = 1 + 2; "答えは" + answer + "です。"
}
```

即使分號寫得過多也沒有問題。多餘的分號會被忽略，不會影響執行。因此，如果你習慣 C 語言的格式，也可以在每一行的結尾都加上分號。

## 使用者自訂函式的定義與執行

除了 `load`、`unload` 和 `request` 之外，也可以建立任意名稱的函式。只要寫出已建立的函式名稱，就可以執行該函式。

```
request
{
    hello
}

hello
{
    "Hello World"
}
```

上面是最簡單的範例，`request` 最後會傳回 `"Hello World"`。以下示範一個稍微複雜、但能得到相同結果的範例。

```
request
{
    combine("Hello", "World")
}

combine
{
    _argv[0] + " " + _argv[1]
}
```

在函式名稱後加上 `( )`，並在其中以逗號分隔列出值，這些值就會作為引數傳遞給相應的函式。也就是說，值會儲存在變數 `_argv` 和 `_argc` 中，並可在該函式內參照。在此範例中，`combine` 函式內的 `_argc` 為 2、`_argv[0]` 為 `"Hello"`、`_argv[1]` 為 `"World"`。

### 不可用作函式名稱的名稱

函式名稱可以自由命名，但使用以下名稱會發生錯誤。

- 以數字 0〜9 開頭
    - 可能會被解讀為數值常數
- 以底線（`_`）開頭
    - 以底線開頭的名稱會用於區域變數
- 包含以下字元：空白　`!`　`"`　`#`　`$`　`%`　`&`　`(`　`)`　`*`　`+`　`,`　`-`　`/`　`:`　`;`　`<`　`=`　`>`　`?`　`@`　`[`　`]`　`` ` ``　`{`　`|`　`}`　`~`
    - 最好不要使用底線以外的符號
- 與保留字完全相同
    - 英文字母大寫加上底線的名稱會用於系統函式
    - 也應避免使用 `for`、`while`、`if` 等控制結構使用的名稱

### 遞迴呼叫

函式可以遞迴呼叫。以下以最常見的階乘計算為例。

```
request
{
    factorial(5)
}

factorial
{
    if !_argv[0]
        1
    else
        factorial(_argv[0] - 1)*_argv[0]
}
```

`request` 會傳回 120。

## 選擇方式

```
request
{
    "Hello World"
    "こんにちは世界"
    "Hallo Welt"
}
```

像這樣列出時，這些項目會被視為平等的「輸出候選」，輸出會是其中一個。選擇方式可以指定為下列其中一種。不過，`void` 和 `array` / `pool_array` 僅用於特殊用途。

| 方式 | 說明 |
|------|------|
| 未指定 / `random` | 隨機選擇（預設） |
| `nonoverlap` | 盡可能避免選到與緊接前一次相同的候選 |
| `sequential` | 依照記述順序輸出，輸出到最後一個後便回到第一個 |
| `array` | 傳回合併所有輸出候選後的通用陣列 |
| `void` | 不輸出任何內容 |
| `all`（Tc567-1） | 將所有候選合併為一個字串 |
| `last`（Tc567-1） | 選擇最後一個候選 |

選擇方式可加在函式名稱後方指定，例如 `: nonoverlap`。

```
request : nonoverlap
{
    "Hello World"
    "こんにちは世界"
    "Hallo Welt"
}
```

```
request : sequential
{
    "Hello World"
    "こんにちは世界"
    "Hallo Welt"
}
```

有些函式的輸出候選數量會隨著每次執行而改變。例如，下列函式的候選數會依變數 `i` 的值變為 2 個或 4 個。

```
request : sequential
{
    if i {
        "1"
        "2"
    }
    "3"
    "4"
}
```

候選數量改變時，`nonoverlap` 和 `sequential` 的循環順序會初始化，並從頭開始。僅在這種情況下，才可能會重複輸出與前一次相同的值。

### array

將合併所有輸出候選後的通用陣列作為函式的傳回值。

```
request : array
{
    "This is a pen."
    ("A","B","C")
    3.14
}
```

輸出會是通用陣列 `("This is a pen.", "A", "B", "C", 3.14)`。

### void

不會輸出任何內容。以下範例中的 `request` 不會輸出 3 個候選中的任何一個。

```
request : void
{
    "Hello World"
    "こんにちは世界"
    "Hallo Welt"
}
```

請注意，這不是「什麼都不執行」，而是「什麼都不輸出」。內部記述的函式和運算式仍會處理。

```
increment_i : void
{
    i++
    i
}
```

上述函式 `increment_i` 會將 `i` 加 1。未指定 `void` 時，此函式會傳回加總結果；指定 `void` 後則不會傳回值，只會執行加總。

### all

於 Tc567-1 實作。將所有選擇候選合併為一個字串。

### last

於 Tc567-1 實作。從選擇候選中選出最後一個候選作為輸出。

## 修飾符

**`_pool`**：將加上 `_pool` 的區塊內部區塊的候選，與外側候選排列在同一層選擇。可加在函式本身（`OnTest : _pool`）或區塊（`_pool : {`）上。

一般而言，巢狀區塊會整體視為一個候選。以下範例中，`"x"` 的機率為 1/2，`"y"` 和 `"z"` 的機率各為 1/4：

```
OnTest
{
  "x"
  {
    "y"
    "z"
  }
}
```

加上 `_pool` 後，內側區塊的候選會分散開來，`"x"`、`"y"`、`"z"` 的機率都會變成 1/3：

```
OnTest : _pool
{
  "x"
  {
    "y"
    "z"
  }
}
```

- 無論巢狀多少層，都會分散開來（若在第 3 層加入 `"z"` 和 `"w"`，則 4 個候選的機率各為 1/4）
- `if`、`elseif`、`else` 內的內容也會分散開來。條件為假而不會執行的區塊，其候選不會加入。若寫成 `if 條件 { "b" "c" }`，則只有在條件為真時，`"b"` 和 `"c"` 才會以與外側候選相同的機率被選中
- `while`、`for`、`foreach` 內的候選會在每次重複時各加入一個（執行 2 次的 `for` 內的 `"y"` 會算作 2 個候選）
- 像 `nonoverlap : {` 這樣寫了選擇方式的區塊不會分散，仍會維持為一個候選
- 與選擇方式組合時，寫成 `_pool_nonoverlap`、`_pool_sequential` 等形式（可省略 `_`）。未指定方式時會使用 `random_pool`（也可以只寫 `pool`），並以隨機方式選擇。也可以寫成 `nonoverlap_pool`、`sequential_pool`、`array_pool` 等形式。避免重複或選擇順序的處理會套用到分散後的所有候選
- 加在區塊上時，僅適用於該區塊內部。外側區塊的候選會將該區塊視為一個候選
- 同一個區塊或函式不能同時指定 `_pool` 和 `melt_`

以下示範有無 `_pool` 時選擇機率的變化。在下列函式中，不加 `_pool` 時，`"Hello World"` 的機率為 50%，`"こんにちは世界"` 和 `"Hallo Welt"` 的機率各為 25%。若寫成 `: random_pool`（也可以只寫 `_pool`），則 3 個候選的機率各為 33.3%。`if 1` 永遠為真。

```
request : random
{
    "Hello World"
    if 1 {
        "こんにちは世界"
        "Hallo Welt"
    }
}
```

```
OnTest : _pool_nonoverlap
{
  "通常のセリフ"
  if is_rainy {
    "雨の日のセリフ1"
    "雨の日のセリフ2"
  }
}
```

當 `is_rainy` 為真時，會以相同機率選擇 3 種對話，且不會連續選到相同的對話。為假時，則只有 `"通常のセリフ"`。

**`melt_`**：使用通用陣列產生並列輸出的效果。加在區塊上時，若該區塊所選的輸出是通用陣列，便會將其元素分散，並加入緊鄰外側區塊的輸出候選中（效果與 [`parallel`](05-arrays.md) 相同）。可與選擇方式組合，例如 `melt_nonoverlap`。未指定選擇方式的內側區塊也會沿用此設定。

```
OnTest
{
    "test"
    "test2"
    melt_nonoverlap : {
        ("red","green","blue")
    }
}
```

結果："test"、"test2"、"red"、"green"、"blue" 中的任一項。

加在函式本身時，由於沒有外側區塊，會先分散通用陣列的候選，再進行選擇（Tc574-9 / Tc603-2 以後）。以 `return` 傳回的通用陣列不會分散。

```
OnTest : melt_nonoverlap
{
    "test"
    "test2"
    ("red","green","blue")
}
```

結果：從與上例相同的 5 個候選中選擇，並避免重複。

在 Tc574-8 / Tc603-1 以前，加在函式本身的 `melt_` 不會生效，通用陣列會原樣視為一個候選。此外，加在第 2 層或更內側區塊的 `melt_`，會加入函式最外側區塊的候選，而非緊鄰外側區塊的候選。

## 巢狀結構

```
request
{
    {
        "Hello World"
        "こんにちは世界"
    }

    "Hallo Welt"
}
```

`{ }` 可以階層式地任意層巢狀書寫。其運作方式與最上層的 `{ }` 相同，會從包含的候選項目中選出一個並輸出。不過，選擇方式只能是隨機抽選，無法像最上層一樣指定 `nonoverlap` 或 `sequential`（Tc564-1 以後，可使用下方的「巢狀結構中的選擇方式」指定）。

在上面的例子中，無論有沒有 `{ }`，結果似乎都相同，但其實並非如此。沒有 `{ }` 時，各項輸出的機率都相同，為 1/3。但在上面的例子中，會先從 `"Hello World"` 和 `"こんにちは世界"` 中選出一個，接著再從選出的結果與剩下的 `"Hallo Welt"` 中抽選輸出。也就是說，`"Hello World"` 和 `"こんにちは世界"` 的出現率各為 1/4，`"Hallo Welt"` 則為 1/2。

### 巢狀結構中的選擇方式

Tc564-1 以後，可以為每個巢狀結構新增前一節所述的選擇方式。

```
request
{
    nonoverlap : {
        "Hello World"
        "こんにちは世界"
    }

    "Hallo Welt"
}
```

若要指定給緊接在 `if` 敘述等之後的 `{ }`，可以使用 `;` 分隔，如下所示，或新增換行。

```
request
{
    if 1 ; nonoverlap : {
        "Hello World"
        "こんにちは世界"
    }

    "Hallo Welt"
}
```

```
request
{
    if 1
    nonoverlap : {
        "Hello World"
        "こんにちは世界"
    }

    "Hallo Welt"
}
```

## 輸出確定子

```
request
{
    "Hello"
    "Perfect"
    "Peaceful"
    --
    " Wor"
    --
    "ld"
    "th"
}
```

`--` 稱為輸出確定子，候選項目會以此為界分組。接著，各組選出的結果會合併成一個字串。因此，執行上面的 `request` 時，會輸出下列其中一種結果。

```
"Hello World"
"Perfect World"
"Peaceful World"
"Hello Worth"
"Perfect Worth"
"Peaceful Worth"
```

`--` 必須單獨寫在一行。不能像 `"Hello" / "Perfect" -- …` 這樣寫在同一行，且 `/` 會被視為除法。

與 `nonoverlap`、`sequential`、`array` 組合使用時，會針對函式可能產生的所有組合（而非各組）運作。

例如，`sequential`：

```
request : sequential
{
    "1"
    "2"
    "3"
    --
    "A"
    "B"
}
```

會依照下列順序產生輸出。

```
"1A" "2A" "3A" "1B" "2B" "3B" "1A" "2A" …
```

`array`：

```
request : array
{
    "1"
    "2"
    "3"
    --
    "A"
    "B"
}
```

會輸出一個通用陣列 `("1A","1B","2A","2B","3A","3B")`。

YAYA 除了字串之外也能處理數值等資料，但輸出確定子在合併時會將它們全部轉換為字串，再以字串形式合併。
