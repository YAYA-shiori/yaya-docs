# 運算

## 基本

可以使用與 C 語言相同的格式進行四則運算、比較運算、指派等運算。運算順序會根據各運算子所設定的優先度決定。此外，以括號 `( )` 括住的部分會最優先運算。

## 運算子優先度（由高至低）

| 優先度 | 運算子 | 說明 |
|--------|--------|------|
| 1 | `( )` `[ ]` | 括號 |
| 2 | `!` | 否定 |
| 3 | `++` `--` | 加 1 / 減 1 |
| 4 | `*` `/` `%` | 乘除、取餘數 |
| 5 | `+` `-` | 加減 |
| 6 | `==` `!=` `>=` `<=` `>` `<` `_in_` `!_in_` | 比較 |
| 7 | `&&` | 邏輯 AND |
| 8 | `\|\|` | 邏輯 OR |
| 9 | `=` `:=` | 指派 |
| 10 | `+=` `-=` `*=` `/=` `%=` `+:=` `-:=` `*:=` `/:=` `%:=` `,=` | 運算後指派 |
| 11 | `,` | 列舉通用陣列元素（最低優先度） |

- 帶有冒號（`:`）的指派運算子是為了維持舊版相容性而保留的，在功能上與不帶冒號的運算子相同
- `++` `--` `!` 是一元運算子
- `&` 是附加在函式引數前面的前置符號（[回饋運算子](#フィードバック演算子)），並非二元運算子，因此不列於此表
- 逗號運算子（`,`）與方括號 `[ ]` 的詳細說明請參閱[陣列](05-arrays.md)

## 比較與真假

`_in_` 和 `!_in_` 是用於檢查字串是否包含的運算子。若左運算元的字串包含於右運算元的字串中，`_in_` 會傳回 1；若不包含，則傳回 0。`!_in_` 則相反。

```
foo
{
    "or" _in_ "World"
}
```

上面的函式 `foo` 會傳回 1。

比較運算子的結果為真時會傳回整數 1，為假時則傳回 0。這些運算子也能正確用於字串，值的大小則以字典順序比較決定。

邏輯上的真假依下列方式判斷。

- 假：整數 0、實數 0.0、空字串、空的通用陣列
- 真：上述以外的所有值

非指派運算的結果會直接作為輸出。

```
foo
{
    (3+2)*4
}
```

這個函式 `foo` 會輸出 20。

## 左結合

連續出現優先順序相同的運算子時，一律由左向右結合。例如：

```
1+2-3
```

會依照 `1+2` → `3-3` 的順序計算。

```
i = j = 10
```

這會如何運作呢？在 C 語言中，指派運算子由右向左結合，因此會將 10 指派給 `i` 和 `j`。但在 YAYA 中，運算子一律由左向右結合，因此會依照 `i = j` → `j = 10` 的順序計算。因此，`i` 不會取得 10。

```
i = (j = 10)
```

這樣寫的話，`i` 也會取得 10。

## 型別強制（Type Coercion）

運算對象的運算元型別不一致時，結果型別如下。

- 整數與實數運算：結果為實數
- 整數 / 實數與字串相加：數值會先轉換為字串，再與另一個字串連接
- 整數 / 實數與字串比較大小：數值會先轉換為字串，再依字典順序比較大小
- 整數 / 實數與字串運算（加法、比較大小以外）：無法運算，但不會發生錯誤。結果為空字串

同一個運算式中可以混用不同型別。必要時會依照上述規則進行型別轉換。

```
"10+2は" + (10+2) + "です。"
```

首先會將 `10+2` 當作整數計算，得到結果 12。其餘部分都是與字串相加，因此 12 會轉換為字串，並以字串形式連接。

### 雜湊的運算（Tc600-3 以後）

- `+`：若另一個運算元是純量或雜湊，會將兩者轉換為字串後連接（`IHASH("a",1) + 1` 會得到 `"a=11"`）。若另一個運算元是陣列，則會逐一與陣列的各個元素連接
- `-` `*` `/` `%`（包含複合指派）：會發出警告 W0024。無法得到有意義的結果
- `==`：若兩者都是雜湊，元素數量、鍵與值全部相同時為真。雜湊與非雜湊比較時一律為假

詳細資訊請參閱[雜湊](12-hash.md#値としての振る舞い)。

## 以括號 ( ) 控制運算順序

以括號 `( )` 括住的部分，會被視為具有最高的運算優先順序。`( )` 可以重複套用任意次，層數越深，優先順序越高。簡單來說，就是「先計算括號內的部分」。這是理所當然的規則，但依照數學式的寫法，有時也會變得有些複雜。請看以下範例。

```
answer = (_i = 10) + (2*(_i + 10))
```

如果不充分理解運算規則，就很難正確回答會指派什麼值給 `answer`。指派給 `answer` 的不是預期的 50，而是 30。

最先計算的是括號層數最深的部分，也就是 `_i + 10`。此時變數 `_i` 尚不存在。未定義的變數在與數值運算時會視為 0，因此 `_i + 10` 會是 10，`2*(_i + 10)` 會是 20。之後才會評估 `(_i = 10)`，結果為 10，總和 30 便會指派給 `answer`。

依照我們的預期，應該先執行 `_i = 10` 的指派。在這種情況下，可以像下面這樣過度增加括號，藉此控制運算順序。

```
answer = (((_i = 10))) + (2*(_i + 10))
```

如此一來，指派部分的優先順序就會大幅提高，這次便會得到正確的結果（50）。

另外，你或許會認為只要用兩層括號括住指派部分就夠了，但這是錯的。兩層括號會與 `_i + 10` 的深度相同，而 `=` 和 `+` 相比，`+` 的優先順序較高，因此 `_i + 10` 會先被計算。

## 回饋運算子

回饋運算子 `&` 是一種用法與其他運算子完全不同的獨特運算子。

```
request
{
    _i = 1
    foo(&_i)
}

foo
{
    _argv[0] = 100
}
```

呼叫函式時，若要將變數作為引數傳入，可以在變數前面加上 `&`。加上 `&` 的變數會與被呼叫函式 `_argv` 中對應的元素建立關聯。也就是說，改寫 `_argv` 時，呼叫端對應變數的值也會一併改寫。在上述範例中，執行 `foo` 時，`_i` 的值會改寫為 100。

回饋運算子可以在任意位置使用任意多次。

```
request
{
    foo(1, 2, &_value, "Hello", &_value2)

    _value + _value2
}

foo
{
    _argv[2] = _argv[0] + _argv[1]
    _argv[4] = _argv[3] + " World"
}
```

函式 `request` 會輸出 `"3Hello World"`。這是理所當然的，回饋運算子只能加在變數上。

也可以傳入陣列元素。Tc600-4 之後，也可以傳入雜湊或巢狀元素中的元素（[多維指派](13-nesting.md#多次元代入)）。

```
func(&_a[1])            // func の中で _argv[0] を書き換えると _a[1] が変わる
func(&_h["sub"]["x"])   // 同じく _h["sub"]["x"] が変わる（Tc600-4以降）
```

將陣列變數作為引數傳入時，元素會在 `_argv` 中展開排列。寫回時會以展開後的位置為基準。

```
_a = (1, 2)
func(_a, &_x)           // _argv は (1, 2, _x の値)。_argv[2] を書き換えると _x が変わる
func(&_a)               // _argv の _a の要素数ぶんが、配列として _a に戻る
```

在 Tc603-3 之前，寫回的位置仍是引數的位置（第幾個引數），因此若在前面傳入陣列，可能會將值寫回其他元素，或因 `_argv` 超出範圍而中斷執行。若被呼叫的函式縮短了 `_argv`，則不會寫回已不存在的引數。

即使第一個引數以括號括住（`func((1, 2), &_x)` 或 `func((_a), &_x)`），行為也與未加括號時相同（Tc603-5 之後）。在 Tc603-4 之前，此時無法正確辨識引數分隔符，因此 `&` 的寫回不會生效。此外，傳給系統函式的引數也會和未加括號時一樣，各自成為個別引數。例如，`ARRAYSIZE((_a), 1)` 會傳回 `_a` 的元素數量，而 `TOSTR((1), (2))` 會得到 `"12"`（在此之前，第一個與第二個引數會合併成一個陣列，`ARRAYSIZE` 會得到比元素數量多 1 的值，而 `TOSTR` 會得到 `"1,2"`）。

## 向後相容性

冒號指派運算子（`":="`）為了向後相容而保留，但其行為與不帶冒號的運算子相同。
