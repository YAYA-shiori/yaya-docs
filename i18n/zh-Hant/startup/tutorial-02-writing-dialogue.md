# 教學 2：試著撰寫對話

## 開啟包含辭典檔案的資料夾

啟動範本人格後，點擊開發面板最下方的「開啟」按鈕。接著選擇「GHOST」，就會開啟一個放有 yaya.dll 等各種檔案的資料夾。裡面副檔名為「.dic」的檔案就是 YAYA 的辭典檔案。

這些辭典檔案中寫著「人格會說什麼話、會如何行動」。接下來，我們會逐步編輯這些內容，試著製作人格。

## 看看辭典內容

首先，用文字編輯器開啟主辭典 `dic_main.dic`。在大約第 150 行的位置，應該會看到如下的內容。

```
//起動
OnBoot
{
	"\1\s[10]\0\s[0]こんにちは。\e"
}
```

這裡是「人格啟動時會說的台詞」。第一次看到時，除了「こんにちは。」以外，應該都不知道是什麼意思，所以我們來逐一解開這些神祕符號。

| 要素 | 說明 |
|------|------|
| `OnBoot` | 函式名稱。此例中填入的是「人格啟動時會呼叫」的 SHIORI Event 名稱。也就是說，這代表「接下來 `{ }` 裡的內容是人格啟動時的事件」。如果改成 `OnClose`，就會變成「人格結束時的事件」 |
| `{ }` | 函式內容。寫下函式名稱後，用這兩個符號括起來，形成「函式名稱{函式內容}」 |
| `" "` | 對話或 Sakura Script 一定要用這個符號括起來。沒有用 `" "` 或 `' '` 括起來的字串，會被視為變數名稱或函式名稱，而不是對話（`" "` 和 `' '` 的差異，以及變數名稱的意思會在後面說明） |
| `\0` | 這是 Sakura Script，表示「接下來由 0 號主角（也稱為櫻側）說話或變換表情」。接著寫的文字會顯示在 0 號角色的對話方塊中。寫在 `\1` 後面的文字則會顯示在 1 號搭檔角色（也稱為汎側）的對話方塊中 |
| `\s[0]` | 顯示 0 號表面的 Sakura Script。表面是指立繪的種類。像 `\s[1]` 或 `\s[2]` 這樣改變編號，就能變成悲傷的表情或笑臉等（不過，這個範本的預設外殼只有 0 號和 10 號圖片，因此即使寫成 `\s[1]` 或 `\s[2]`，也不會有任何變化） |
| `\e` | 表示對話結束的 Sakura Script。即使不加似乎也沒有問題，不過以防萬一，還是放在對話的最後。幾乎就像咒語一樣的存在 |

如需了解 OnBoot 等事件的詳細資訊，請參閱[CROW・SSP 參考資料](http://crow.aqrs.jp/reference/all/Shiori/index.html)。基本上，這份參考資料中列出的 SHIORI Event，都能以和 OnBoot 類似的方式撰寫。

### 關於 Sakura Script

Sakura Script 也通用於 YAYA 以外的 SHIORI，因此本手冊不會再進一步說明。Sakura Script 還有各式各樣的指令，請到參考資料網站逐步學習「實際上想使用的指令」（一開始就想全部記住，腦袋會塞不下）。

- [CROW 參考資料 - SakuraScript](http://crow.aqrs.jp/reference/crow/SakuraScript/index.html)
- [UKADOC Project Sakura Script 清單](https://ssp.shillest.net/ukadoc/manual/list_sakura_script.html)
- [Disc-2 SakuraScript 清單](http://disc2.s56.xrea.com/manual/list_sakura_script.htm)（資訊有點舊）

在開發面板的「輸入指令碼」中撰寫對話並送出，就可以練習撰寫 Sakura Script。

![在「輸入指令碼」中送出 `\0\s[0]やっほー！\e` 的畫面](../attachment/img_tutorial_02_001.png)
送出後如果看起來沒有問題，就把內容實際寫進辭典，確認人格能否正常對話（OnBoot 事件中的對話，可以先結束人格，再重新啟動來確認）。

## 試著用各種方式撰寫對話

### 讓對話隨機選出

每次啟動都說一樣的問候語很無聊，因此試著增加到 3 種。

```
OnBoot
{
	"\0\s[0]こんにちはー。\e"
	"\0\s[0]おっすー。\e"
	"\0\s[0]やっほー。\e"
}
```

**YAYA 在 `{ }` 中有多個用 `" "` 或 `' '` 括起來的字串時，會從中隨機選出一個。**

如果想寫在同一行，可以用 `;` 取代換行來分隔。

```
OnBoot
{
	"\0\s[0]こんにちはー。\e" ; "\0\s[0]おっすー。\e" ; "\0\s[0]やっほー。\e"
}
```

如果覺得反覆寫 `\0\s[0]` 和 `\e` 很麻煩，可以像下面這樣寫。

```
OnBoot
{
	"\0\s[0]"
	--
	"こんにちはー。"
	"おっすー。"
	"やっほー。"
	--
	"\e"
}
```

**用 `--` 分隔後，每個區段都會各自隨機選出一個用 `" "` 或 `' '` 括起來的字串，並將它們串接後顯示。**

這種寫法也可以用 `;` 分隔，寫在同一行（但不太容易閱讀）。

```
OnBoot
{
	"\0\s[0]" ; -- ; "こんにちはー。" ; "おっすー。" ; "やっほー。" ; -- ; "\e"
}
```

!!! warning "`--` 的寫法"
    `--` 必須單獨寫在一行，或在前後以 `;` 分隔。像 `"こんにちは。" -- "おっすー。"` 這樣既沒有 `;` 也沒有換行就連在一起寫，會發生錯誤。

再舉一個例子。

```
OnBoot
{
	"きょうは"  //←<1>この2つのどっちかが選ばれる
	"明日は"    //←<2>
	--
	"晴れ"      //←(1)この4つの中のどれかが選ばれる
	"雨"        //←(2)
	"曇り"      //←(3)
	"雷"        //←(4)
	--
	"です。"    //←1コしかないので必ずコレが選ばれる
}
```

這樣寫的話，就會隨機產生以下這類對話：

- 「きょうは雨です。」
- 「明日は曇りです。」
- 「きょうは晴れです。」
- 「明日は雷です。」
- 「明日は晴れです。」

對話的變化就會增加。

不過，這是真正的隨機選擇，因此也可能連續選到相同的單字。若想避免這種情況，可以在函式名稱後面加上 ` : nonoverlap`。如此一來，同一句話就不會連續被選到。

```
OnBoot : nonoverlap
{
	"\0\s[0]"
	--
	"こんにちはー。"
	"おっすー。"
	"やっほー。"
	--
	"\e"
}
```

如果想按照順序選出內容，請加上 ` : sequential`。詳細資訊請參閱[函式的選擇方式](../grammar/02-functions.md#選択方式)。

### 試著建立原創函式

上面寫的、

```
OnBoot
{
	"\0\s[0]きょうは"
	"\0\s[0]明日は"
	--
	"晴れ"
	"雨"
	"曇り"
	"雷"
	--
	"です。\e"
}
```

可以改寫成以下形式。

```
OnBoot
{
	"\0\s[0]きょうは"
	"\0\s[0]明日は"
	--
	天気一覧
	--
	"です。\e"
}

天気一覧
{
	"晴れ"
	"雨"
	"曇り"
	"雷"
}
```

像這樣，也可以建立獨立的原創函式，再呼叫它來撰寫內容。這樣寫有什麼好處呢？

```
OnBoot
{
	"\0\s[0]きょうは"
	"\0\s[0]明日は"
	--
	天気一覧
	--
	"です。\e"
}

OnGhostChanged
{
	"\0\s[0]昨日は"
	--
	天気一覧
	--
	"だったよ。\e"
}

天気一覧
{
	"晴れ"
	"雨"
	"曇り"
	"雷"
}
```

像這樣，可以從多個函式呼叫同一個函式，因此能重複使用。

```
OnBoot
{
	"\0\s[0]きょうは%(天気一覧)です。\e"
}

天気一覧
{
	"晴れ"
	"雨"
	"曇り"
	"雷"
}
```

若要在 `" "` 的內容中呼叫函式，可以像這樣寫成 `%(函式名稱)`（[展開字串內嵌元素](../grammar/06-string-embedding.md)）。

### 建立原創函式時的注意事項

函式名稱（以上例來說是「天気一覧」）可以使用英文或日文，但必須遵守以下規則。

- 函式名稱不能以半形數字開頭（`5test` 不行，`test5` 或 `te5st` 則可以）
- 開頭不能加上 `_`（會被誤認為區域變數）
- 不能包含空白　`!`　`"`　`#`　`$`　`%`　`&`　`(`　`)`　`*`　`+`　`,`　`-`　`/`　`:`　`;`　`<`　`=`　`>`　`?`　`@`　`[`　`]`　`` ` ``　`{`　`|`　`}` 之中的任何字元
- 等等

詳情請參閱[函式的使用者自訂函式定義與執行](../grammar/02-functions.md#ユーザー関数の定義と実行)。

## 讓辭典更容易閱讀

### 試著加入空白或換行

只要遵守先寫函式名稱，再用 `{ }` 括住內容的寫法規則，

```
OnBoot {
	"\1\s[10]\0\s[0]こんにちは。\e"
}
```

或是寫成

```
OnBoot { "\1\s[10]\0\s[0]こんにちは。\e" }
```

或是寫成

```
OnBoot{"\1\s[10]\0\s[0]こんにちは。\e"}
```

都可以。`OnBoot` 和 `{` 之間等處的空白與換行，可以加入，也可以不加。也可以使用定位字元。請整理成自己容易閱讀、容易撰寫的形式。

基本上，`" "` 外面的空白、定位字元與換行都會被忽略，因此也可以寫成以下形式。

```
OnBoot
	{

		"\1\s[10]\0\s[0]こんにちは。\e"

							}
```

也就是說，

```
【ここ】OnBoot【ここ】{【ここ】"\0\s[0]いっちばーん。\e"【ここ】}【ここ】
```

其中的【ここ】都可以加入任意數量的空白（半形空白、全形空白、定位字元）或換行。YAYA 的辭典可以利用這個機制，整理得整齊易讀。

### 註解

使用註解後，該部分就不會作為辭典載入。當你想「加入備忘或說明」或「暫時隔離已寫好的辭典中的一部分」時，這個功能很方便。使用方法只要在要註解的行首加入 `//` 即可。

```
// 起動イベント
OnBoot
{
	"\0\s[0]こんにちはー。\e"
}
```

也可以放在以下位置。也就是說，從 `//` 開始到行尾的所有內容都會被註解。

```
OnBoot
{
	"\0\s[0]こんにちはー。\e"// 起動トーク
}
```

用 `/*` 和 `*/` 括住也可以註解。這種方式可以一次註解多行，因此行數很多時會比較方便。缺點是較難分辨註解部分的起訖位置。

```
/*
起動イベント
一番最初に起動したとき呼ばれる
*/
OnBoot
{
	"\0\s[0]こんにちはー。\e"
}
```

請多加註解，讓自己日後回頭查看辭典時，能立刻想起各部分的用途。

### 不可以做的事

請注意，若做了以下這類事情，就會發生錯誤，導致人格完全無法運作。

```
OnBoot
{
	"\0\s[0]改行\n
	します。\e"
}
```

如果在用 `" "` 或 `' '` 括住的字串中途換行，就會發生錯誤。這時只要在行尾加入 `/`，就能換行。

```
OnBoot
{
	"\0\s[0]改行\n/
	します。\e"
}
```

此外，從 YAYA Tc535-1 開始，也可以使用[文件字串](../grammar/03-values-and-variables.md#ヒアドキュメント)的寫法。

也不能寫出兩個以上名稱相同的函式。務必只寫一個。

```
//起動
OnBoot
{
	"\1\s[10]\0\s[0]こんにちは。\e"
}

OnBoot
{
	"\1\s[10]\0\s[0]やっほー！\e"
}
```

只要確實遵守這些規則，無論在任何辭典檔案的任何位置撰寫函式都沒有問題（不過，最好盡量不要寫在系統辭典的 `yaya_shiori3.dic` 中）。

## 人格完全沒有反應！這是錯誤嗎？該怎麼辦！

先冷靜下來，找出錯誤的原因。

### 自行檢查

之前人格明明都能正常運作，因此錯誤原因當然是在之後撰寫的辭典中。仔細檢查辭典中自己修改過的部分。常見問題包括忘了補上括號。

如果仍然找不到原因，可以暫時將可疑的部分註解，再重新啟動人格。如果人格因此正常啟動，那部分就是錯誤原因。

### 使用 YAYA 專用除錯工具

上次準備的「玉」。詳情請參閱[使用玉檢查辭典錯誤](../tips/tama-error-check.md)。

### 查看執行記錄

開啟與 yaya.dll 位於相同層級的 `yaya.txt`。其中有如下項目。

```
//log, ayame.log	// ログを指定されたファイルに記録
```

將最左側的 `//` 刪除，並覆寫儲存，改成如下內容：

```
log, ayame.log	// ログを指定されたファイルに記録
```

再次啟動人格後，就會輸出 `ayame.log`，請查看內容。

### 查看指令碼記錄

想知道傳送給人格的是什麼 Sakura Script 時，這個功能就很有用。使用方法是「在 SSP 中按右鍵點選人格 → 功能 → 指令碼記錄」。
