# 從 Satori 移行

主要是寫給只用過 Satori 作為 SHIORI，卻也想試試 YAYA 的人。

## 前言

### 從 Satori 改用 YAYA 的優點

YAYA 擅長處理程式設計相關的工作，因此當人格的對話以外的部分變得雜亂、難以編寫時，使用 YAYA 會輕鬆許多。

不過，這並非 YAYA 獨有的特性，[Kawari](http://www.towano.net/wk_kwr/) 也是一個選擇。如果不介意停止更新，也可以考慮其他 SHIORI（但即使發現問題，也無法期待會有人修正）。建議先了解各種 SHIORI 的特性，再選擇自己用起來順手的 SHIORI。

### 關於 YAYA 的常見疑問

#### 聽說 YAYA 是給理工腦使用的 SHIORI……

也有幾個人表示：「我是文組，之前只用過 Satori，但 YAYA 很合我的習慣，用起來很順手。」也就是說，YAYA 是否適合你，和你是不是理工科背景無關，主要取決於是否合你的習慣。實際用過才知道。

#### 只有做過程式設計或 C 語言的人才能使用嗎？

至少，寫下這篇文章的人既沒做過程式設計，也沒寫過 C 語言。

#### 比 Satori 難吧？

要看要製作什麼樣的人格。若是以對話為主的簡單人格，Satori 比較輕鬆；但如果是動作複雜的人格，Satori 反而可能成為比 YAYA 更難理解的 SHIORI。尤其大量使用迴圈或陣列時，很可能會覺得用 Satori 撰寫很吃力。

#### 真的很吃效能嗎？

沒聽說特別吃效能。至少比 Satori 輕。明明是簡單的 YAYA 製人格卻覺得很吃效能時，很可能是開啟了「執行記錄輸出設定」或「不限制取得已安裝人格清單」。

參考網站或許有幫助：[檔案讀寫究竟有多慢（有追加內容） | すくりや](http://nikolat.herokuapp.com/ukagaka/time-file-io/)（最下方的總結）

#### 只有 YAYA 能操作檔案或使用正規表示式嗎？

其他 SHIORI 也可以透過 SAORI 做到。例如，透過 [YAYA as SAORI](../other/yaya-as-saori.md) 將 YAYA 當作 SAORI 使用，就能像 YAYA 一樣操作檔案或使用正規表示式。也就是說，不必只為了這些功能而選擇 YAYA。

#### 能夠製作出 Satori 絕對做不出來的人格嗎？

如上所述，大致上所有事情都能透過使用 SAORI 或設法撰寫內容，在 Satori 中實現。不過，辭典是否容易撰寫、內容會變得多長，以及撰寫完成的辭典日後是否容易閱讀等方面，仍會有所不同。

### 注意事項

- Satori 會自動插入等待、換行、範圍切換標籤等內容，但 YAYA 必須全部**使用 Sakura Script 自行撰寫**。選項也必須一律使用 Sakura Script 撰寫
- YAYA 基本上除了對話以外，都使用半形字元撰寫
- Satori 即使沒有範本人格，只要準備好 `satori.dll` 並參閱手冊，通常也能設法使用；但 YAYA 很難從零開始自行建立 SHIORI/3.0 設定指令碼等內容（也就是人格運作時的齒輪部分），因此幾乎必須使用範本。至少，最好沿用 SHIORI/3.0 設定指令碼（在[SimpleYAYA範本](../other/simple-yaya-template.md)中即為 `yaya_shiori3.dic`）
- Satori 會自動讀取副檔名為 `.txt` 且檔名以 `dic` 開頭的辭典檔案，但 YAYA **只會讀取在 `yaya.txt` 中設定的辭典**。相對地，YAYA 也有能讀取任何副檔名的辭典，以及能將辭典放在任意目錄的優點
- 與 Satori 相同，事件可以寫在任何辭典中
- 無法切換各資料夾的辭典讀取狀態（多重人格的做法請參閱[多重人格模式](../tips/multiple-personality-mode.md)，但這不是切換讀取資料夾的方式）
- Satori 可以直接使用 SAORI-basic，但在 YAYA 中，Tc604-1 以前的版本必須透過名為 `proxy_ex.dll` 的 SAORI 才能使用。YAYA 不需要像在 Satori 中那樣於 `satori_conf.txt` 撰寫 saori 定義（詳情請參閱[SAORI 的使用方式](../tips/saori-usage.md)）

### 建議事先準備的項目

- **文字編輯器**：基本上任何一款都可以，不過建議下載[編輯器語法上色檔](../tips/editor-color-files.md)中介紹的文字編輯器，以及相對應的語法上色檔。這樣能讓內容更容易閱讀。若設定成開啟副檔名為 `.dic` 的檔案時自動上色，就更方便了
- **範本人格**：從[YAYA 製作人格](creating-ghost.md)中選擇適合自己的範本。如前所述，幾乎是必備項目

## 試著撰寫 YAYA 的辭典

以下內容可能不適用於[哈囉 YAYA 世界（紺野ややめ）](http://ms.shillest.net/yayame.xhtml)和 SimpleYAYA 範本以外的範本（尤其是標題帶有「☆」的項目）。

以啟動事件為例。

### 基本

在 Satori 中會這樣寫。

```
＊OnBoot
：いっちばーん。
```

在 YAYA 中則如下所示。

```
OnBoot
{
	"\0\s[0]いっちばーん。\e"
}
```

當中有許多不太明白的符號，接下來逐一說明。

| 符號 | 說明 |
|------|------|
| `OnBoot` | 開頭要寫的名稱，表示啟動事件。這部分和 Satori 相同。在 YAYA 中稱為函式名稱。[CROW・SSP參考資料 - Shiori](http://crow.aqrs.jp/reference/all/Shiori/index.html)中列出的事件名稱，都可以直接在 YAYA 中使用。「起動」「終了」「初回」等日文事件名稱是 Satori 專用的事件名稱，因此即使在 YAYA 中使用，也不會直接被呼叫 |
| `{ }` | 寫好事件名稱後，使用這兩個符號括住事件內容。**在 YAYA 中撰寫 SHIORI Event 時，必須使用「事件名稱{事件內容}」**。若沒有正確括住，就會發生錯誤，導致人格無法啟動 |
| `" "` | 對話等字串必須以這些符號括住。**這點和 Satori 不同，未以這些符號括住的文字會被視為變數名稱或函式名稱**。另外，以 `' '` 取代 `" "` 括住字串時，裡面的變數不會展開。一般使用 `" "` 即可 |
| `\0` | Sakura Script，表示「接下來由 0 號角色（櫻側）說話或改變表情」。後面寫的文字會顯示在 0 號角色的對話方塊中。若要讓 1 號搭檔角色說話，則使用 `\1`。在 Satori 中，這兩者的切換只需使用「：」 |
| `\s[0]` | 顯示 0 號表面的 Sakura Script。在 Satori 中會寫成（０）。在 Satori 中可以省略最前面的（０），但在 YAYA 中若不加入這段，就會直接顯示對話開始前的表面 |
| `\e` | 表示對話結束的 Sakura Script。即使不加似乎也沒有問題，但為求保險，還是在對話的最後加上 |

與 Satori 不同，YAYA 不會自動加入等待時間。若要加入，請使用 Sakura Script。Sakura Script 也通用於 YAYA 以外的 SHIORI，因此本手冊不會詳細說明。除此之外還有許多內容，請在參考網站上挑選「想實際試用的項目」，「一點一點」地搭配 YAYA 學習即可（若一開始就想全部學會，腦袋會爆掉）。

- [CROW參考資料 - SakuraScript](http://crow.aqrs.jp/reference/crow/SakuraScript/index.html)
- [Disc-2 SakuraScript列表](http://disc2.s56.xrea.com/manual/list_sakura_script.htm)

只要遵守先寫事件名稱、用 `{ }` 括住內容等寫法規則，也可以像下面這樣寫：

```
OnBoot {
"\0\s[0]いっちばーん。\e"
}
```

也可以像下面這樣寫：

```
OnBoot { "\0\s[0]いっちばーん。\e" }
```

`OnBoot` 和 `{` 之間的空白與換行，可以加也可以不加。也可以加入定位字元。請選擇自己看得清楚、寫得順手的寫法。

```
OnBoot{"\0\s[0]いっちばーん。\e"}
```

基本上，`" "` 以外的空白、定位字元和換行都會被忽略，因此也可以寫成下面這樣。

```
OnBoot
	{

		"\0\s[0]いっちばーん。\e"

							}
```

總而言之，

```
【ここ】OnBoot【ここ】{【ここ】"\0\s[0]いっちばーん。\e"【ここ】}【ここ】
```

就是說，可以在【ここ】的位置任意加入空白（半形空格、全形空格、定位字元）或換行。YAYA 可以利用這項機制，自由整理辭典。這是 YAYA 的辭典比 Satori 更容易閱讀的原因之一。

### 換行

在 Satori 中會這樣寫。

```
＊OnBoot
：改行
します。
```

在 Satori 中，辭典內的換行會直接成為對話中的換行，但**在 YAYA 中，若不使用 Sakura Script 換行，顯示在對話方塊時就不會換行**。請在想換行的位置加入 `\n`。

```
OnBoot
{
	"\0\s[0]改行\nします。\e"
}
```

如果你覺得「這樣辭典裡沒有換行，不太容易看懂」，可以改成下面這樣。

```
OnBoot
{
	"\0\s[0]改行\n/
	します。\e"
}
```

像這樣在行尾加入 `/`，就能換行。請在喜歡的位置加入使用。

```
OnBoot
{
	"\0\s[0]/
	改行\n/
	します。/
	\e"
}
```

錯誤範例：

```
OnBoot
{
	"\0\s[0]改行\n
	します。\e"
}
```

**請注意，如果在用 `" "` 或 `' '` 括起來的部分中換行，卻沒有在行尾加入 `/`，就會發生錯誤。**

### 隨機選擇單字或句子

在 Satori 中，如果寫了許多相同的事件，就會從中隨機選擇。

```
＊OnBoot
：こんにちはー。

＊OnBoot
：おっすー。

＊OnBoot
：やっほー。
```

但在 YAYA 中這樣做會發生錯誤，導致無法啟動。**YAYA 不能撰寫兩個以上名稱相同的事件。** 替代做法是在 `{ }` 中以換行分隔，排列 `" "`。

```
OnBoot
{
	"\0\s[0]こんにちはー。\e"
	"\0\s[0]おっすー。\e"
	"\0\s[0]やっほー。\e"
}
```

**在 YAYA 中，如果 `{ }` 裡有多個以 `" "` 或 `' '` 括起來的字串，就會從中隨機選出其中一個。**

也可以用 `;` 分隔取代換行，將內容整理成一行。

```
OnBoot
{
	"\0\s[0]こんにちはー。\e" ; "\0\s[0]おっすー。\e" ; "\0\s[0]やっほー。\e"
}
```

如果覺得重複撰寫 `\0\s[0]` 或 `\e` 很麻煩，可以像下面這樣寫。

```
OnBoot
{
	"\0\s[0]"
	--
	"こんにちはー。"
	"おっすー。"
	"やっほー。"
	--
	"\e"
}
```

**用 `--` 分隔時，會分別從每個區段中隨機選出一個以 `" "` 或 `' '` 括起來的字串，並將它們串接後顯示。**

有點不容易理解，以下舉例說明。

```
てんき
{
	"きょうは"  //←<1>この2つのどっちかが選ばれる
	"明日は"    //←<2>
	--
	"晴れ"      //←(1)この4つの中のどれかが選ばれる
	"雨"        //←(2)
	"曇り"      //←(3)
	"雷"        //←(4)
	--
	"です。"    //←1コしかないので必ずコレが選ばれる
}
```

這樣寫的話，

- 「きょうは雨です。」
- 「明日は曇りです。」
- 「きょうは晴れです。」
- 「明日は雷です。」
- 「明日は晴れです。」

每次呼叫時，都會隨機產生這類句子。

由於是隨機選擇，也可能連續選到相同的單字。你可能會想：「有辦法像 Satori 一樣避免重複嗎？」答案是可以。

```
OnBoot : nonoverlap
{
	"\0\s[0]"
	--
	"こんにちはー。"
	"おっすー。"
	"やっほー。"
	--
	"\e"
}
```

在事件名稱後面加上 ` : nonoverlap`，就不會連續選到相同的句子。如果想依序選擇，則使用 ` : sequential`（[函式的選擇方式](../grammar/02-functions.md#選択方式)）。

順帶一提，在 Satori 中，可以像下面這樣寫，將寫在其他位置的單字群組呼叫到對話中。

```
＊
：（季節）はいいね～
：どの季節でも言ってるジャン

＠季節
春
夏
秋
冬
```

在 YAYA 中要做相同的事，可以像下面這樣寫。

```
Talk
{
	"\0\s[0]%(季節)はいいね～\w9\1\s[10]どの季節でも言ってるジャン\e"
}

季節
{
	"春"
	"夏"
	"秋"
	"冬"
}
```

在對話中寫成 `%(季節)` 或 `%季節`，就能呼叫名為「季節」的函式（[展開字串內嵌入的元素](../grammar/06-string-embedding.md)）。

在 Satori 中，單字群組會以「＠季節」表示，會包含換行的句子則以「＊季節」表示；但**YAYA 不區分單字和句子，因此無論是單字還是句子，都寫成「季節{ }」**。`OnBoot` 等 SHIORI 事件和單字群組都以「函式」的形式撰寫，因此寫法完全相同。

當然，也可以像上面的天氣對話那樣，寫成下面這樣。

```
Talk
{
	"\0\s[0]"
	--
	"春"
	"夏"
	"秋"
	"冬"
	--
	"はいいね～\w9\1\s[10]どの季節でも言ってるジャン\e"
}
```

如果想在其他對話中也使用「季節」這個單字群組，使用一開始介紹的方式會比較好。

### 變數

變數也是 Satori 中熟悉的功能。許多人可能會用它來處理使用者名稱、啟動次數、啟動時間或好感度。在 Satori 中只有一種變數，但 YAYA 有多種類型。先來說明這方面的內容。

#### 字串與數值

YAYA 的變數有字串和數值兩種類型（精確來說有整數、實數、字串三種類型）。

```
変数 = 1
```

這樣指派後，變數的內容就是數值 `1`。

```
変数 = "1"
```

像這樣用 `" "` 或 `' '` 括起來指派後，變數的內容就會是字串 `"1"`。

與 Satori 不同，全形的「１」「２」「３」…不能作為數值，會被視為字串。**如果是字串變數，就無法將其當作數值比較或計算。** 例如，將數值 `1` 和 `2` 相加，結果會是 `3`；但將字串 `"1"` 和 `"2"` 相加，1 和 2 會接在一起，變成 `"12"`。其他還有許多不同之處，請多加留意。

變數可以隨時自由地在字串和數值之間轉換，不必擔心。請依用途轉換。

- 將變數轉換為字串變數：`変数 = TOSTR(変数)`
- 將變數轉換為數值變數：`変数 = TOINT(変数)`

也有能自動判斷並轉換為整數、實數或字串的 [TOAUTO](../functions/TOAUTO.md)。

#### 全域變數與區域變數的差異

在名稱前加上 `_` 就會成為區域變數，不加則會成為全域變數。

```
_変数名
変数名
```

簡單來說，「暫時使用、很快就會消失」的是區域變數，「只要不刪除就會一直保留」的是全域變數。Satori 的變數全都是全域變數。在 YAYA 中，除了使用者名稱、好感度等必須一直保留的變數之外，建議使用區域變數。

區域變數可以使用多久呢？也就是「只能在目前的 `{ }` 內，以及比目前更深的巢狀階層中使用。生命週期會到離開該 `{ }` 為止」（摘自[值與變數](../grammar/03-values-and-variables.md#スコープとライフタイム)）。

用文字不太容易說明，以下舉一個例子。

```
ローカル変数テスト {
	{
		_変数 = 1
	}
	結果 = _変数
}
```

這樣寫的話，`_変数` 從較深的階層移到較淺的階層時就會消失，因此 `結果` 的內容也會變成空值。不過，

```
ローカル変数テスト {
	_変数 = ""
	{
		_変数 = 1
	}
	結果 = _変数
}
```

這樣寫的話，`_変数` 會依序從較淺的階層 → 較深的階層 → 較淺的階層……，因為它最初是在較淺的階層建立的，所以即使從較深的階層移到較淺的階層，也不會消失，而會繼續保留，因此 `結果` 的內容會是 1。關鍵在於 `_変数` 最初建立的位置，是否與 `結果 = _変数` 位於相同或更淺的階層。

也就是說，想讓區域變數存在得久一點時，只要一開始在最淺的階層寫一行 `_○○ = ""` 等指派即可。

#### 變數的指派

以下是送出禮物並設定旗標的例子。將禮物旗標設為數值 1。

Satori:

```
＊プレゼントした
＄プレゼントフラグ＝１
：わーいありがとう！
```

YAYA:

```
プレゼントした
{
	プレゼントフラグ = 1

	"\0\s[0]わーいありがとう！\e"
}
```

與 Satori 的差異如下。

- 開頭不加「＄」
- 對話或計算等內容都要寫在 `{ }` 內（寫在 `{ }` 外會發生錯誤）
- `=` 等計算用符號，以及 `1` 等數值，都要**使用半形字元**

如果你在 Satori 中也習慣使用半形字元書寫運算式或數值，可能會覺得很方便。

```
【ここ】プレゼントフラグ【ここ】=【ここ】1【ここ】
```

【ここ】的部分可以填入空白或定位字元。為了方便閱讀，許多人會在運算符號的左右加上半形空白。

要指派字串時，請如下所示。將「花束」這個字串放入名為「プレゼント」的變數中。

Satori:

```
＊プレゼントした
＄プレゼント【タブ】花束
：わーいありがとう！
```

YAYA:

```
プレゼントした
{
	プレゼント = "花束"

	"\0\s[0]わーいありがとう！\e"
}
```

不是數值時，必須用 `" "` 或 `' '` 括起來。這與撰寫對話時相同。不能像 Satori 那樣寫成「プレゼント【タブ】"花束"」。指派時一定要使用 `=`。

```
プレゼントした
{
	プレゼント = 花束

	"\0\s[0]わーいありがとう！\e"
}
```

不小心這樣寫的話，「プレゼント」的內容就會變成空值。這是因為，**在 YAYA 中，只有 `花束` 而不是 `"花束"` 時，會被視為「名為『花束』的變數」**。因此這會被誤解為「將名為『花束』的變數內容放入名為『プレゼント』的變數」，而由於名為「花束」的變數不存在，內容就會變成空值。

以 Satori 來說，這相當於寫成以下這樣。

```
＊プレゼントした
＄プレゼント【タブ】（花束）
：わーいありがとう！
```

這部分與 Satori 正好相反，因此一開始可能會有點混亂。

#### 變數的計算

Satori:

```
＊好感度アップ
＄好感度＝（好感度）＋１
：ユーザーさんだいすき！
```

YAYA:

```
好感度アップ
{
	好感度 = 好感度 + 1

	"\0\s[0]ユーザーさんだいすき！\e"
}
```

這裡也很簡單。在 Satori 中，必須像 `＄好感度＝（好感度）＋１` 這樣，將右側的變數寫在 `（ ）` 中；YAYA 則不需要加上任何符號。如前所述，沒有用 `" "` 或 `' '` 括起來的字串，會被視為變數或函式名稱（如果只有半形數字，則會被視為數值）。

順帶一提，YAYA 也可以省略部分內容，寫成以下這樣。

```
好感度アップ
{
	好感度++

	"\0\s[0]ユーザーさんだいすき！\e"
}
```

`好感度++` 的意思是「好感度增加 1」，與 `好感度 = 好感度 + 1` 相同。`好感度--`（兩個半形減號）則會減少 1。`好感度 += 2` 與 `好感度 = 好感度 + 2` 相同，`好感度 -= 2` 與 `好感度 = 好感度 - 2` 相同。其他可在 YAYA 中使用的計算符號，請參閱[運算](../grammar/04-arithmetic.md)。

和 Satori 一樣，也可以將字串相加。

```
プレゼント = "花" + "束"
```

這樣寫的話，變數 `プレゼント` 的內容會變成 `"花束"`。

當然，也可以在對話中使用變數。

```
プレゼントした
{
	プレゼント = "花束"

	"\0\s[0]わーい\w6%(プレゼント)だー！\w9\w9ありがとう！\e"
}
```

對話方塊中會顯示「耶，花束！謝謝！」。寫法與上面說明如何在對話中使用詞語群時完全相同。這部分在 Satori 和 YAYA 中沒有差異。

想確認變數是否正確儲存時，請結束人格，並用文字編輯器開啟存檔資料檔案（`yaya_variable.cfg`）。以上述例子來說，如果有以下一行，就表示儲存成功。

```
プレゼント,"花束",",",
```

順帶一提，如果是數值型變數，內容中的數字不會用 `" "` 括起來，例如：

```
プレゼントフラグ,1,",",
```

如需了解儲存格式的詳細資訊，請參閱 [SAVEVAR](../functions/SAVEVAR.md#保存形式)。

### 分支

戳擊反應的範例。`OnMouseDoubleClick` 事件的規格是，戳到 0 號角色（櫻花側）時，`Reference3` 裡會放入「0」。因此，試著寫一份辭典，在確認 `Reference3` 裡放入 0 之後，跳到「戳到 0 號的反應」。

里々：

```
＊OnMouseDoubleClick
＞0番さんがつつかれた【タブ】（R3）＝＝０

＊0番さんがつつかれた
：（７）つつくなっ！
```

YAYA：

```
OnMouseDoubleClick {
	if reference[3] == 0 {
		0番さんがつつかれた
	}
}

0番さんがつつかれた {
	"\0\s[7]つつくなっ！\e"
}
```

這裡新登場的是 `if`。`if` 的意思是，如果後面的條件運算式（此處為 `reference[3] == 0`）成立，就執行接下來 `{ }` 裡的內容。

```
OnMouseDoubleClick {
	if reference[3] == 0 {
		"\0\s[7]つつくなっ！\e"
	}
}
```

當然，也可以像這樣直接在 `{ }` 裡寫對話。請視需要更改寫法。

搭配 `if` 使用 `else`，還可以做到以下的事。

```
OnMouseDoubleClick {
	if reference[3] == 0 {
		"\0\s[7]つつくなっ！\e"
	}
	else {
		"\0\s[7]あたし以外の子もつつくなっ！\e"
	}
}
```

如果不符合 `if 條件運算式 { }`，就會執行後面的 `else { }` 裡的內容。以這個範例來說，戳到 0 號以外的角色時，都會執行 `else { }` 裡的內容。請注意，`else` 只能接在 `if` 後面，單獨寫 `else` 會發生錯誤。

如果只想在戳到 0 號角色的「頭部」時才顯示對話，可以這樣寫。

```
OnMouseDoubleClick {
	if reference[3] == 0 && reference[4] == "Head" {
		"\0\s[7]頭を叩くなっ！\e"
	}
}
```

可以並列兩個以上的條件運算式。除了半形或全形的差異之外，`==` 和 `&&` 符號的用法與里々完全相同。別忘了在 `if` 和 `reference[3] == 0` 之間加上空格或定位字元。

話說回來，里々的戳擊反應應該是這樣寫的。

```
＊0Headつつかれ
：（７）頭を叩くなっ！

＊1つつかれ
：やめれ！
```

在 YAYA 中能不能做類似的事？為了這樣的你，請看以下寫法。

```
OnMouseDoubleClick {
	EVAL( "%(reference[3])%(reference[4])つつかれ" )
}

0Headつつかれ {
	"\0\s[7]頭を叩くなっ！\e"
}

1つつかれ {
	"\1\s[10]やめれ！\e"
}
```

一般來說，如果只寫 `"%(reference[3])%(reference[4])つつかれ"`，戳到 0 號角色的頭時，就會變成名為「0Headつつかれ」的函式對話。將它包在 `EVAL( )` 裡，就會讓「0Headつつかれ」成為函式名稱。

這個 [EVAL](../functions/EVAL.md) 不只適用於這種「可以直接獨立寫出函式的分支」，在許多其他情境中也是很實用的函式。

### Ｒ０、Ｓ０、Ａ０等在 YAYA 中的寫法

全部都用半形字元書寫。

| 里々 | YAYA | 備註 |
|------|------|------|
| `Ｒ０` `Ｒ１` `Ｒ２` … | `reference[0]` `reference[1]` `reference[2]` … | 舊版範本使用的是 `reference0` `reference1` `reference2` …（新版範本也可以透過設定使用這種寫法） |
| `Ｓ０` `Ｓ１` `Ｓ２` … | `valueex0` `valueex1` `valueex2` … | SAORI 的用法請參閱下方的「SAORI」一節 |
| `Ａ０` `Ａ１` `Ａ２` … | `_argv[0]` `_argv[1]` `_argv[2]` … | 如同前面有 `_` 所示，這是區域變數 |

### 類似 ssu 的功能

「條件分支」、「比較」和「計算」會以不同方式處理，但除此之外，幾乎都能用 YAYA 的系統函式做到相同的事。請參閱[系統函式一覽](../system/system-functions-index.md)。

### SAORI

#### 使用方法

里々：

```
（mciaudio,load,鳥の詩.mp3）（mciaudio,play）
```

YAYA：

```
FUNCTIONEX( 'mciaudio.dll' , 'load' , '鳥の詩.mp3' )
FUNCTIONEX( 'mciaudio.dll' , 'play' )
```

不必像里々那樣，事先設定要使用的 SAORI。直接指定從 `yaya.dll` 來看的 SAORI 相對路徑即可。

另外，如果 `mciaudio.dll` 和 `鳥の詩.mp3` 並非位於與 `yaya.dll` 相同的目錄，而是在下一層的 `saori` 目錄中，就像下面這樣寫。

```
FUNCTIONEX( 'saori\mciaudio.dll' , 'load' , '鳥の詩.mp3' )
```

也可以用 `SAORI` 取代 `FUNCTIONEX` 執行（這是系統辭典中的函式，也是 `FUNCTIONEX` 的別名）。如果兩種寫法都可以，請使用 `FUNCTIONEX`。

#### 傳回值 Result

使用 SAORI 執行函式時，傳回值會直接傳回。如果要將傳回值直接顯示在對話方塊中，也可以像下面這樣嵌入對話中使用（但請注意，SAORI 執行函式的引數必須用 `' '` 括住，而非 `" "`。因為不能在 `" "` 之中再寫 `" "`）。

```
"\0\s[0]クリップボードにある文字を取り出します。\n「%(FUNCTIONEX( 'saori\textcopy.dll' , 'コピーする文字' ))」\e"
```

也可以先存入變數再使用。

```
変数 = FUNCTIONEX( 'saori\textpaste.dll' )
```

如果不希望 Result 直接顯示在對話方塊中，也可以將它指派給適當的區域變數。

#### 傳回值 Value[n]

如上所述，在里々中寫作 `Ｓ０` `Ｓ１` `Ｓ２` … 的內容，在 YAYA 中則寫作 `valueex0` `valueex1` `valueex2` …。

詳細說明請參閱以下頁面。

- [播放音效](../tips/play-sound.md)
- [SAORI 的使用方法](../tips/saori-usage.md)

### ☆顯示目前時間

參照[系統辭典/yaya_shiori3.dic](../system/yaya-shiori3-dic.md)中的時間變數（`year` `month` `day` `weekday` `hour` `minute` `second`）。記憶體用量和 Sender 標頭的變數也可以在這裡查看。

```
時間をおしえる
{
	"\0\s[0]ただいま%(hour)時%(minute)分%(second)秒で～す。\e"
}
```

如果你覺得「不能像里々那樣用日文書寫就不方便」，也可以參考範本自行撰寫。

```
年　{ GETTIME[0] }
月　{ GETTIME[1] }
日　{ GETTIME[2] }
分　{ GETTIME[5] }
秒　{ GETTIME[6] }

時間をおしえる
{
	"\0\s[0]ただいま%(時)時%(分)分%(秒)秒で～す。\e"
}
```

將星期轉換為漢字表示的方法，請參閱[判斷星期幾](../tips/detect-weekday.md)（SimpleYAYA 範本中已收錄）。

### ☆計時器（＄○○計時器【Tab】秒數）

- [經過指定秒數後執行事件](../tips/execute-after-seconds.md)

### replace.txt

使用 `#define` 可以達成相同效果。不過，`#define` 會在 SHIORI 執行計算等操作之前，轉換「辭典中原封不動寫下的所有字串」，功能相當強大，因此請小心使用，以免連重要字串也一起被轉換。詳細用法請參閱[縮寫函式、變數與櫻花腳本](../tips/shorthand-writing.md)。

例如，寫下如下內容：

```
#define @r reference
```

如此一來，原本寫成 `reference[0]` 的地方，就能縮寫為 `@r[0]`。

### ☆replace_after.txt

可以透過 `OnTranslate` 或 `OnTranslateInternal` 事件達成。若要用於自動等待時間等用途，建議使用 `OnTranslateInternal`（使用 `OnTranslate` 的話，例如連標題內容也會被轉換）。

自動為對話加上等待時間的範例：

```
OnTranslateInternal
{
	_text = _argv[0]
	_text = REPLACE(_text, "…", "…\w3")
	_text = REPLACE(_text, "、", "、\w5")
	_text = REPLACE(_text, "。", "。\w9")
	_text
}
```

### 停用像 Φ 這類危險符號

和 Satori 一樣，YAYA 也有不能直接寫在對話中的符號。在 Satori 中，會在符號前加上「Φ」來停用它。在 YAYA 中，則使用名為 [CHR](../functions/CHR.md) 的函式來撰寫。

請參考以下網站，查出想輸入的符號的高 3 位元（表格橫軸上的符號）和高 4 位元（縱軸）。

- [[psl] ASCII 碼一覽表](http://www.psl.ne.jp/perl/pdojo00b.html)
- [字元碼表](http://winofsql.jp/VA003334/CprogBase040109013756.htm)

```
CHR(0x(上位3ビット)(上位4ビット))
```

以此方式撰寫。例如，`1` 就是 `CHR(0x31)`。請務必使用半形字元。

在 `" "` 中寫入 `"` 的範例：

```
記号表示テスト
{
	"\0\s[0]記号「%(CHR(0x22))」をバルーンに表示\e"
}
```

在 Tc569-8 以後，也可以連續寫兩個雙引號 `""`（[值與變數](../grammar/03-values-and-variables.md#文字列)）。

### 註解

只要將 `＃` 改成 `//` 即可。

Satori：

```
＃ 起動イベント
＊OnBoot
：こんにちはー。
```

YAYA：

```
// 起動イベント
OnBoot
{
	"\0\s[0]こんにちはー。\e"
}
```

也可以寫在如下位置。也就是說，從 `//` 開始到右側的部分，都會成為註解。

```
OnBoot
{
	"\0\s[0]こんにちはー。\e"// 起動トーク
}
```

用 `/*` 和 `*/` 括起來也能註解。這種方式可以一次括住多行，行數較多時會比較方便。缺點是有時不太容易看出註解的範圍。

```
/*
起動イベント
一番最初に起動したとき呼ばれる
*/
OnBoot
{
	"\0\s[0]こんにちはー。\e"
}
```

YAYA 比 Satori 更容易加入註解，也更方便隨手使用。請多加註解，讓自己日後回頭查看時，能立刻想起各處的用途。

## 從 Satori 移轉到 YAYA 時常見的疑問

### 啟動人格後完全沒有反應！

和 Satori 不同，只要 YAYA 的辭典記述方式有一個字元寫錯，人格就會無法運作。請確認是哪裡寫錯了。

- [使用 Tama 檢查辭典錯誤](../tips/tama-error-check.md)

也可以查看執行記錄確認。請在與 `yaya.dll` 位於同一層的 `yaya.txt` 中加入一行 `log, ayame.log`，再啟動人格，然後用文字編輯器開啟輸出的 `ayame.log`。

### satori_savedata.txt（存檔資料）在哪裡？

全域變數會儲存在 `yaya_variable.cfg` 中（檔名可能因範本而異）。

### 出現別名錯誤，這是什麼？

`descript.txt` 是否仍然是 `shiori,satori.dll`？
