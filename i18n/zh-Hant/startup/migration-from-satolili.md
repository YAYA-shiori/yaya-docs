# 從 Satori 移行

這份說明主要是為只用過 Satori 作為 SHIORI，但也想試用 YAYA 的人而寫。

## 前言

### 從 Satori 換成 YAYA 的優點

YAYA 擅長處理程式相關的內容，因此當人格的對話以外的部分變得複雜、難以撰寫時，使用 YAYA 會輕鬆許多。

不過，這並非 YAYA 獨有的特性，[Kawari](http://www.towano.net/wk_kwr/) 也是一種選擇。若不介意停止更新，也可以考慮其他 SHIORI（但即使發現問題，也不能期待會有人修正）。了解各種 SHIORI 的特性，選擇自己用起來順手的 SHIORI 即可。

### 對 YAYA 的常見疑問

#### 聽說這是專為理工背景的人打造的 SHIORI……

也有幾個人表示：「我是文組出身，以前只用過 Satori，但 YAYA 很適合我，用起來也很順手。」也就是說，YAYA 是否適合你，和你是否有理工背景無關，取決於你和它是否合得來。實際用過才知道。

#### 只有寫過程式或使用過 C 語言的人才能用嗎？

至少，寫下這篇文章的人沒有寫過程式，也沒有使用過 C 語言。

#### 比 Satori 難吧？

要看你想製作什麼樣的人格。以對話為主的簡單人格，用 Satori 比較輕鬆；但如果是動作複雜的人格，Satori 反而有可能比 YAYA 更難理解。特別是大量使用迴圈或陣列時，用 Satori 撰寫的難度很可能會變高。

#### 聽說很耗資源，是真的嗎？

沒聽說 YAYA 特別耗資源。至少比 Satori 輕。明明是簡單的 YAYA 人格，卻覺得很耗資源的話，很可能是開啟了「執行記錄輸出設定」或「不限取得數量地取得已安裝人格清單」。

也許有參考價值的網站：[檔案讀寫到底有多慢（附補充） | すくりや](http://nikolat.herokuapp.com/ukagaka/time-file-io/)（最下方的總結）

#### 只有 YAYA 能操作檔案或使用正規表示式嗎？

其他 SHIORI 也能透過 SAORI 做到。例如，透過 [YAYA as SAORI](../other/yaya-as-saori.md) 將 YAYA 作為 SAORI 使用，就能像使用 YAYA 一樣操作檔案或使用正規表示式。也就是說，不需要只為了這些功能而選擇 YAYA。

#### 能製作出 Satori 絕對無法製作的人格嗎？

如上所述，大部分事情都能透過使用 SAORI 或巧妙安排寫法，在 Satori 中實現。不過，辭典是否容易撰寫、描述會變得多長，以及寫好的辭典日後是否容易閱讀等方面，仍會有所不同。

### 注意事項

- Satori 會自動加入等待、換行、範圍切換標籤等內容，但 YAYA 必須**使用 Sakura Script 自行撰寫所有這些內容**。選項也必須使用 Sakura Script 撰寫
- YAYA 基本上除了對話以外，都使用半形字元撰寫
- Satori 即使沒有範本人格，只要準備好 `satori.dll` 並參閱手冊，通常也能設法完成；但 YAYA 很難從零開始自行製作 SHIORI/3.0 設定腳本等內容（也就是人格運作時的核心部分），因此範本幾乎是必備的。至少，最好沿用 SHIORI/3.0 設定腳本（以 [SimpleYAYA 範本](../other/simple-yaya-template.md) 為例，就是 `yaya_shiori3.dic`）
- Satori 會自動讀取副檔名為 `.txt` 且檔名以 `dic` 開頭的辭典檔案，但 YAYA **只會讀取在 `yaya.txt` 中設定的辭典**。另一方面，YAYA 也有一些優點，例如可以讀取任何副檔名的辭典，也可以將辭典放在任意目錄
- 與 Satori 相同，可以在任何辭典中撰寫任何事件
- 無法依資料夾切換辭典讀取設定（多重人格的做法請參閱[多重人格模式](../tips/multiple-personality-mode.md)，但這並不是切換讀取資料夾的方式）
- Satori 可以直接使用 SAORI-basic，但 YAYA 在 Tc604-1 之前的版本必須透過名為 `proxy_ex.dll` 的 SAORI 才能使用。不需要像在 Satori 中那樣，將 SAORI 定義寫在 `satori_conf.txt` 裡（詳細內容請參閱[SAORI 的使用方式](../tips/saori-usage.md)）

### 建議事先準備的項目

- **文字編輯器**：基本上任何一款都可以，不過建議下載[編輯器語法上色檔](../tips/editor-color-files.md)中介紹的文字編輯器，以及與其相對應的語法上色檔。這樣會更容易閱讀內容。設定成開啟副檔名為 `.dic` 的檔案時會自動上色，使用起來就更方便
- **範本人格**：從[使用 YAYA 製作人格](creating-ghost.md)中選擇適合自己的範本。如前所述，幾乎是必備項目

## 試著撰寫 YAYA 的辭典

以下內容可能不適用於[Hello YAYA World（紺野ややめ (Konnoyayame)）](http://ms.shillest.net/yayame.xhtml)與 SimpleYAYA 範本以外的範本（尤其是標題有「☆」的項目）。

以啟動事件為例。

### 基本

在 Satori 中會這樣寫。

```
＊OnBoot
：いっちばーん。
```

在 YAYA 中則如下所示。

```
OnBoot
{
	"\0\s[0]いっちばーん。\e"
}
```

其中有許多不太容易理解的符號，接下來會逐一說明。

| 符號 | 說明 |
|------|------|
| `OnBoot` | 最先寫下的名稱，表示啟動事件。這部分和 Satori 相同。在 YAYA 中稱為函式名稱。[CROW・SSP 參考資料 - Shiori](http://crow.aqrs.jp/reference/all/Shiori/index.html)中記載的事件名稱，都可以直接寫在 YAYA 中。「啟動」「結束」「初次」等日文事件名稱則是 Satori 獨有的事件名稱，因此即使在 YAYA 中使用，也不會直接被呼叫 |
| `{ }` | 寫下事件名稱後，使用這兩個符號括住事件內容。**在 YAYA 中撰寫 SHIORI Event 時，格式一律為「事件名稱{事件內容}」**。如果沒有確實括起來就會發生錯誤，導致人格無法啟動 |
| `" "` | 對話等字串都必須用這個符號括起來。**和 Satori 不同，沒有用這個符號括起來的文字會被視為變數名稱或函式名稱**。另外，使用 `' '` 取代 `" "` 括起來時，其中的變數不會展開。一般使用 `" "` 即可 |
| `\0` | 表示「接下來由 0 號角色（櫻花側）說話或改變表情」的 Sakura Script。其後寫下的文字會顯示在 0 號角色的對話方塊中。若要讓 1 號搭檔角色說話，則使用 `\1`。在 Satori 中，這兩者只用「：」來切換 |
| `\s[0]` | 顯示 0 號表面的 Sakura Script。在 Satori 中會寫成（０）。Satori 可以省略最前面的（０），但在 YAYA 中若不加上這個指令，對話開始前的表面就會維持原樣 |
| `\e` | 表示對話結束的 Sakura Script。即使不加上似乎也沒有特別問題，但為求保險，請在對話結尾加上 |

與 Satori 不同，不會自動加入等待時間。若要加入，請使用 Sakura Script。Sakura Script 也通用於 YAYA 以外的 SHIORI，因此本手冊不會詳細說明。除此之外還有很多內容，請在參考網站上挑選「實際想試著使用的項目」，「一次學一點點」就好，並搭配 YAYA 一起學習（如果一開始就想全部學會，腦袋會塞不下）。

- [CROW 參考資料 - SakuraScript](http://crow.aqrs.jp/reference/crow/SakuraScript/index.html)
- [Disc-2 SakuraScript 清單](http://disc2.s56.xrea.com/manual/list_sakura_script.htm)

只要遵守先寫事件名稱、再用 `{ }` 括住內容等寫法規則，也可以像下面這樣寫：

```
OnBoot {
"\0\s[0]いっちばーん。\e"
}
```

也可以像下面這樣寫。

```
OnBoot { "\0\s[0]いっちばーん。\e" }
```

`OnBoot` 和 `{` 之間等處的空格、換行，可以加入也可以不加入。也可以加入定位字元。請選擇自己容易閱讀、容易撰寫的寫法。

```
OnBoot{"\0\s[0]いっちばーん。\e"}
```

基本上，位於 `" "` 外的空格、定位字元與換行都會被忽略，所以也可以像下面這樣寫。

```
OnBoot
	{

		"\0\s[0]いっちばーん。\e"

							}
```

也就是說，

```
【ここ】OnBoot【ここ】{【ここ】"\0\s[0]いっちばーん。\e"【ここ】}【ここ】
```

【這裡】的部分可以任意加入空格（半形空格、全形空格、定位字元）或換行。YAYA 可以利用這個機制，自由整理辭典。這是大家認為辭典比 Satori 更容易閱讀的原因之一。

### 換行

在 Satori 中會這樣寫。

```
＊OnBoot
：改行
します。
```

在 Satori 中，辭典內的換行會直接成為對話中的換行，但**YAYA 必須使用 Sakura Script 換行，顯示在對話方塊中時才會換行**。在想換行的位置加入 `\n`。

```
OnBoot
{
	"\0\s[0]改行\nします。\e"
}
```

如果覺得「這樣辭典裡沒有換行，不太容易看懂」，可以像下面這樣寫。

```
OnBoot
{
	"\0\s[0]改行\n/
	します。\e"
}
```

像這樣在行尾加入 `/` 就能換行。請依照需要加入。

```
OnBoot
{
	"\0\s[0]/
	改行\n/
	します。/
	\e"
}
```

錯誤範例:

```
OnBoot
{
	"\0\s[0]改行\n
	します。\e"
}
```

**請注意，如果在以 `" "` 或 `' '` 括住的部分中換行，卻沒有在行尾加入 `/`，就會發生錯誤。**

### 隨機選擇單字或句子

在 Satori 中，如果寫了多個相同的事件，就會從中隨機選出一個。

```
＊OnBoot
：こんにちはー。

＊OnBoot
：おっすー。

＊OnBoot
：やっほー。
```

但在 YAYA 中這樣做會發生錯誤，導致無法啟動。**YAYA 不能寫兩個以上名稱相同的事件。**可以改成在 `{ }` 中以換行分隔排列 `" "`，如下所示。

```
OnBoot
{
	"\0\s[0]こんにちはー。\e"
	"\0\s[0]おっすー。\e"
	"\0\s[0]やっほー。\e"
}
```

**在 YAYA 中，若 `{ }` 內有多個以 `" "` 或 `' '` 括住的字串，就會從中隨機選出一個。**

也可以用 `;` 分隔，取代換行並合併為一行。

```
OnBoot
{
	"\0\s[0]こんにちはー。\e" ; "\0\s[0]おっすー。\e" ; "\0\s[0]やっほー。\e"
}
```

如果覺得重複寫 `\0\s[0]` 或 `\e` 很麻煩，可以像下面這樣寫。

```
OnBoot
{
	"\0\s[0]"
	--
	"こんにちはー。"
	"おっすー。"
	"やっほー。"
	--
	"\e"
}
```

**以 `--` 分隔時，會從各個區段中分別隨機選出一個以 `" "` 或 `' '` 括住的字串，並將它們串接後顯示。**

可能有點難理解，以下舉例說明。

```
てんき
{
	"きょうは"  //←<1>この2つのどっちかが選ばれる
	"明日は"    //←<2>
	--
	"晴れ"      //←(1)この4つの中のどれかが選ばれる
	"雨"        //←(2)
	"曇り"      //←(3)
	"雷"        //←(4)
	--
	"です。"    //←1コしかないので必ずコレが選ばれる
}
```

這樣寫的話，

- 「きょうは雨です。」
- 「明日は曇りです。」
- 「きょうは晴れです。」
- 「明日は雷です。」
- 「明日は晴れです。」

每次呼叫時，都會隨機產生這類句子。

由於是隨機選擇，因此也可能連續選到相同的單字。或許有人會疑惑：「不能像 Satori 一樣避免重複嗎？」答案是可以。

```
OnBoot : nonoverlap
{
	"\0\s[0]"
	--
	"こんにちはー。"
	"おっすー。"
	"やっほー。"
	--
	"\e"
}
```

在事件名稱後面加上 ` : nonoverlap`，就不會連續選到相同的句子。若要依序選擇，則使用 ` : sequential`（[函式的選擇方式](../grammar/02-functions.md#選択方式)）。

順帶一提，在 Satori 中可以像下面這樣寫，將寫在其他位置的單字群呼叫到對話中。

```
＊
：（季節）はいいね～
：どの季節でも言ってるジャン

＠季節
春
夏
秋
冬
```

在 YAYA 中要做相同的事，可以像下面這樣寫。

```
Talk
{
	"\0\s[0]%(季節)はいいね～\w9\1\s[10]どの季節でも言ってるジャン\e"
}

季節
{
	"春"
	"夏"
	"秋"
	"冬"
}
```

在對話中寫成 `%(季節)` 或 `%季節`，就能呼叫名稱為「季節」的函式（[字串內嵌元素的展開](../grammar/06-string-embedding.md)）。

在 Satori 中，單字群要寫成「＠季節」，會插入換行的句子則要寫成「＊季節」；但**YAYA 不區分單字和句子，因此無論是單字或句子，都寫成「季節{ }」**。`OnBoot` 等 SHIORI 事件和單字群都會以「函式」的形式撰寫，因此寫法也完全相同。

當然，也可以像上面的天氣對話一樣，寫成下面這樣。

```
Talk
{
	"\0\s[0]"
	--
	"春"
	"夏"
	"秋"
	"冬"
	--
	"はいいね～\w9\1\s[10]どの季節でも言ってるジャン\e"
}
```

如果也想在其他對話中使用「季節」的單字群，採用一開始介紹的寫法會比較好。

### 變數

變數在 Satori 中也很常見。許多人可能會用它來處理使用者名稱、啟動次數、啟動時間或好感度。在 Satori 中只有一種變數，但 YAYA 有好幾種。首先說明這方面的內容。

#### 字串與數值

YAYA 的變數分為字串和數值兩種（嚴格來說則分為整數、實數、字串三種）。

```
変数 = 1
```

像這樣指派時，變數的內容是數值 `1`。

```
変数 = "1"
```

像這樣用 `" "` 或 `' '` 括住後指派，變數的內容就會是字串 `"1"`。

和 Satori 不同，全形的「１」「２」「３」… 不能作為數值，會被視為字串。**字串變數無法作為數值進行比較或計算。**例如，將數值 `1` 和 `2` 相加會得到 `3`，但將字串 `"1"` 和 `"2"` 相加，兩個字串會接在一起，變成 `"12"`。還有其他各種差異，請多加留意。

變數可以隨時依需求在字串和數值之間轉換，不必擔心。請依照用途進行轉換。

- 將變數轉成字串變數：`変数 = TOSTR(変数)`
- 將變數轉成數值變數：`変数 = TOINT(変数)`

也可以使用 [TOAUTO](../functions/TOAUTO.md)，它會自動判斷並轉換為整數、實數或字串。

#### 全域變數與區域變數的差異

在名稱開頭加上 `_` 就會成為區域變數，不加則會成為全域變數。

```
_変数名
変数名
```

簡單來說，「暫時使用，很快就會消失」的是區域變數，「只要不刪除就會一直保留」的是全域變數。Satori 的變數全都是全域變數。在 YAYA 中，除了使用者名稱、好感度等必須一直保留的變數之外，建議使用區域變數。

區域變數可以使用多久呢？它「只能在目前的 `{ }` 內，以及更深的巢狀階層中使用。離開對應的 `{ }` 時就會失效」（摘自[值與變數](../grammar/03-values-and-variables.md#スコープとライフタイム)）。

用文字不太容易說明，以下舉個例子。

```
ローカル変数テスト {
	{
		_変数 = 1
	}
	結果 = _変数
}
```

這樣寫的話，`_変数` 從較深的階層移到較淺的階層時就會消失，因此 `結果` 的內容也會變成空值。不過，

```
ローカル変数テスト {
	_変数 = ""
	{
		_変数 = 1
	}
	結果 = _変数
}
```

這樣寫的話，`_変数` 會依序經過淺層階層 → 深層階層 → 淺層階層……，而且一開始是在淺層階層建立的，因此即使從深層階層移到淺層階層，也不會消失，會繼續保留，`結果` 的內容便會是 1。重點在於 `_変数` 最初建立的位置，是否與 `結果 = _変数` 位於相同或更淺的階層。

也就是說，若要讓區域變數的生命週期更長，只要一開始就在最淺的階層寫一行 `_○○ = ""` 等內容即可。

#### 變數的指派

以下是送出禮物並設定旗標的例子。將禮物旗標設為數值 1。

Satori:

```
＊プレゼントした
＄プレゼントフラグ＝１
：わーいありがとう！
```

YAYA:

```
プレゼントした
{
	プレゼントフラグ = 1

	"\0\s[0]わーいありがとう！\e"
}
```

與 Satori 的差異如下。

- 開頭不加「＄」
- 對話或計算等內容，都要寫在 `{ }` 裡（寫在 `{ }` 外面會發生錯誤）
- `=` 等計算用符號，以及 `1` 等數值，都必須以**半形書寫**

如果你在 Satori 中也習慣以半形書寫算式或數值，可能會覺得比較容易上手。

```
【ここ】プレゼントフラグ【ここ】=【ここ】1【ここ】
```

【ここ】的部分可以填入空格或定位字元。為了方便閱讀，很多人會在運算符號左右加上半形空格。

指派字串時，請像下面這樣寫。將「花束」這個字串放進名為「プレゼント」的變數中。

Satori:

```
＊プレゼントした
＄プレゼント【タブ】花束
：わーいありがとう！
```

YAYA:

```
プレゼントした
{
	プレゼント = "花束"

	"\0\s[0]わーいありがとう！\e"
}
```

如果不是數值，必須用 `" "` 或 `' '` 括起來，和撰寫對話時一樣。不能像 Satori 那樣寫成「プレゼント【タブ】"花束"」。一定要用 `=` 來指派。

```
プレゼントした
{
	プレゼント = 花束

	"\0\s[0]わーいありがとう！\e"
}
```

不小心這樣寫的話，「プレゼント」的內容就會變成空值。原因是，**在 YAYA 中，只有 `花束` 而不是 `"花束"` 時，會被視為「名為『花束』的變數」**。因此，這會被誤解為「將名為『花束』的變數內容放進名為『プレゼント』的變數」，而由於不存在名為「花束」的變數，內容便會變成空值。

用 Satori 來說，就是不小心寫成下面這樣。

```
＊プレゼントした
＄プレゼント【タブ】（花束）
：わーいありがとう！
```

這一點和 Satori 正好相反，剛開始可能會有些混亂。

#### 變數的計算

Satori:

```
＊好感度アップ
＄好感度＝（好感度）＋１
：ユーザーさんだいすき！
```

YAYA:

```
好感度アップ
{
	好感度 = 好感度 + 1

	"\0\s[0]ユーザーさんだいすき！\e"
}
```

這裡也很簡單。在 Satori 中，必須像 `＄好感度＝（好感度）＋１` 這樣，在右側的變數加上 `（ ）`；但在 YAYA 中不必加上任何符號。如前所述，沒有用 `" "` 或 `' '` 括起來的字串會被視為變數名稱或函式名稱（如果只有半形數字，則會被視為數值）。

另外，YAYA 也可以像下面這樣省略寫法。

```
好感度アップ
{
	好感度++

	"\0\s[0]ユーザーさんだいすき！\e"
}
```

`好感度++` 的意思是「好感度增加 1」，與 `好感度 = 好感度 + 1` 相同。`好感度--`（兩個半形減號）則會減少 1。`好感度 += 2` 與 `好感度 = 好感度 + 2` 相同，`好感度 -= 2` 與 `好感度 = 好感度 - 2` 相同。其他可在 YAYA 中使用的計算符號，請參閱[運算](../grammar/04-arithmetic.md)。

和 Satori 一樣，也可以將字串相加。

```
プレゼント = "花" + "束"
```

這樣寫的話，變數 `プレゼント` 的內容就會是 `"花束"`。

當然，也可以在對話中使用變數。

```
プレゼントした
{
	プレゼント = "花束"

	"\0\s[0]わーい\w6%(プレゼント)だー！\w9\w9ありがとう！\e"
}
```

對話方塊上會顯示「わーい花束だー！ ありがとう！」。寫法與上述在對話中使用單字群時完全相同。這一點在 Satori 和 YAYA 中並沒有差異。

若要確認變數是否已正確儲存，請結束人格，並使用文字編輯器開啟存檔資料檔案（`yaya_variable.cfg`）。以上面的例子來說，只要有以下這一行，就表示儲存成功。

```
プレゼント,"花束",",",
```

另外，如果是數值型變數，變數內容中的數字不會被 `" "` 括起來，例如：

```
プレゼントフラグ,1,",",
```

有關儲存格式的詳細資訊，請參閱 [SAVEVAR](../functions/SAVEVAR.md#保存形式)。

### 條件分支

以下是被戳反應的範例。`OnMouseDoubleClick` 事件的規格是：戳到 0 號角色（櫻花側）時，`Reference3` 裡會放入「0」。因此，試著寫個辭典，確認 `Reference3` 裡放的是 0 時，就跳到「0號被戳反應」。

里々:

```
＊OnMouseDoubleClick
＞0番さんがつつかれた【タブ】（R3）＝＝０

＊0番さんがつつかれた
：（７）つつくなっ！
```

YAYA:

```
OnMouseDoubleClick {
	if reference[3] == 0 {
		0番さんがつつかれた
	}
}

0番さんがつつかれた {
	"\0\s[7]つつくなっ！\e"
}
```

這裡新登場的是 `if`。`if` 的意思是，後面的條件運算式（此處為 `reference[3] == 0`）成立時，就執行接下來 `{ }` 裡的內容。

```
OnMouseDoubleClick {
	if reference[3] == 0 {
		"\0\s[7]つつくなっ！\e"
	}
}
```

當然，也可以像這樣直接在 `{ }` 裡寫對話。請視情況變更寫法。

搭配 `if` 使用 `else`，還可以做到以下的事情。

```
OnMouseDoubleClick {
	if reference[3] == 0 {
		"\0\s[7]つつくなっ！\e"
	}
	else {
		"\0\s[7]あたし以外の子もつつくなっ！\e"
	}
}
```

如果不符合 `if 條件運算式 { }`，就會執行接在後面的 `else { }` 裡的內容。以這個範例來說，戳到 0 號以外的角色時，都會執行 `else { }` 裡的內容。請注意，`else` 只能接在 `if` 後面，單獨寫 `else` 會發生錯誤。

如果只想在戳到 0 號角色的「頭部」時觸發對話，可以這樣寫。

```
OnMouseDoubleClick {
	if reference[3] == 0 && reference[4] == "Head" {
		"\0\s[7]頭を叩くなっ！\e"
	}
}
```

可以並列兩個以上的條件運算式。除了半形或全形的差異以外，`==` 和 `&&` 符號的用法與里々完全相同。別忘了在 `if` 和 `reference[3] == 0` 之間加入空白或 Tab。

話說回來，在里々中，被戳反應應該是這樣寫的。

```
＊0Headつつかれ
：（７）頭を叩くなっ！

＊1つつかれ
：やめれ！
```

YAYA 能不能也做到類似的事情呢？如果你有這個疑問，可以使用以下寫法。

```
OnMouseDoubleClick {
	EVAL( "%(reference[3])%(reference[4])つつかれ" )
}

0Headつつかれ {
	"\0\s[7]頭を叩くなっ！\e"
}

1つつかれ {
	"\1\s[10]やめれ！\e"
}
```

一般來說，如果只寫 `"%(reference[3])%(reference[4])つつかれ"`，在戳到 0 號角色的頭部時，會變成讓人格說出「0Headつつかれ」的對話。將它包在 `EVAL( )` 裡，就會讓「0Headつつかれ」成為函式名稱。

這個 [EVAL](../functions/EVAL.md)，除了這種「可以直接寫出獨立函式的條件分支」之外，在各種情況下也都是很實用的函式。

### Ｒ０等在 YAYA 中的寫法

全部使用半形字元。

| 里々 | YAYA | 備註 |
|------|------|------|
| `Ｒ０` `Ｒ１` `Ｒ２` … | `reference[0]` `reference[1]` `reference[2]` … | 舊版範本使用 `reference0` `reference1` `reference2` …（新版範本也能依設定使用這種寫法） |
| `Ｓ０` `Ｓ１` `Ｓ２` … | `valueex0` `valueex1` `valueex2` … | SAORI 的用法請參閱下方的「SAORI」一節 |
| `Ａ０` `Ａ１` `Ａ２` … | `_argv[0]` `_argv[1]` `_argv[2]` … | 如名稱開頭的 `_` 所示，這是區域變數 |

### 類似 ssu 的功能

「條件分支」、「比較」和「計算」會以不同方式處理，除此之外，幾乎都能使用 YAYA 的系統函式實現相同功能。請參閱[系統函式一覽](../system/system-functions-index.md)。

如果你覺得「這樣很難找到想用的功能！」，也可以參閱[YAYA 系統函式參考](http://navy.nm.land.to/post/y_sysfn.html)（外部網站）。

### SAORI

#### 用法

里々:

```
（mciaudio,load,鳥の詩.mp3）（mciaudio,play）
```

YAYA:

```
FUNCTIONEX( 'mciaudio.dll' , 'load' , '鳥の詩.mp3' )
FUNCTIONEX( 'mciaudio.dll' , 'play' )
```

不需要像里々那樣事先設定要使用的 SAORI。直接指定相對於 `yaya.dll` 的 SAORI 路徑即可。

順帶一提，如果 `mciaudio.dll` 和 `鳥の詩.mp3` 不在與 `yaya.dll` 相同的目錄，而是在其下一層的 `saori` 目錄中，則要像下面這樣寫。

```
FUNCTIONEX( 'saori\mciaudio.dll' , 'load' , '鳥の詩.mp3' )
```

也可以使用 `SAORI` 代替 `FUNCTIONEX` 執行（這是系統辭典中的函式，為 `FUNCTIONEX` 的別名）。兩者都能使用時，請使用 `FUNCTIONEX`。

#### 傳回值 Result

使用 SAORI 執行函式時，結果會直接傳回。如果要將傳回值直接顯示在對話方塊中，也可以像下面這樣嵌入對話中使用（但請注意，SAORI 執行函式的引數必須用 `' '` 而不是 `" "` 括起來，因為不能在 `" "` 中寫入 `" "`）。

```
"\0\s[0]クリップボードにある文字を取り出します。\n「%(FUNCTIONEX( 'saori\textcopy.dll' , 'コピーする文字' ))」\e"
```

也可以先將結果存入變數再使用。

```
変数 = FUNCTIONEX( 'saori\textpaste.dll' )
```

即使不希望 Result 直接顯示在對話方塊中，也可以先將它指派給適當的區域變數。

#### 傳回值 Value[n]

如上所述，在里々中寫作 `Ｓ０` `Ｓ１` `Ｓ２` … 的內容，在 YAYA 中則寫作 `valueex0` `valueex1` `valueex2` …。

詳情請參閱以下頁面。

- [播放音效](../tips/play-sound.md)
- [SAORI 的用法](../tips/saori-usage.md)

### ☆顯示目前時間

參照[系統辭典/yaya_shiori3.dic](../system/yaya-shiori3-dic.md) 的時間變數（`year` `month` `day` `weekday` `hour` `minute` `second`）。也可以在這裡查看記憶體用量及 sender 標頭的變數。

```
時間をおしえる
{
	"\0\s[0]ただいま%(hour)時%(minute)分%(second)秒で～す。\e"
}
```

如果你覺得「不能像 Satori 一樣用日文撰寫就很難受」，也可以參考範本，自己撰寫。

```
年　{ GETTIME[0] }
月　{ GETTIME[1] }
日　{ GETTIME[2] }
分　{ GETTIME[5] }
秒　{ GETTIME[6] }

時間をおしえる
{
	"\0\s[0]ただいま%(時)時%(分)分%(秒)秒で～す。\e"
}
```

將星期以漢字顯示的方法，請參閱[判別星期](../tips/detect-weekday.md)（SimpleYAYA 範本中已有介紹）。

### ☆計時器（＄○○タイマ【タブ】秒数）

### replace.txt

可以用 `#define` 做到相同的事。不過，`#define` 是一種強大的功能，會在 SHIORI 執行計算等操作之前，轉換「辭典中寫入的所有字串原文」，因此請注意不要發生連重要字串也一併轉換等問題。詳細用法請參閱[縮寫函式、變數與 Sakura Script](../tips/shorthand-writing.md)。

例如，加入下列記述後，

```
#define @r reference
```

原本寫作 `reference[0]` 的地方，就可以縮寫成 `@r[0]`。

### ☆replace_after.txt

可以透過 `OnTranslate` 或 `OnTranslateInternal` 事件實現。如果是用於自動加入等待等用途，建議使用 `OnTranslateInternal`（若使用 `OnTranslate`，例如連標題列的內容也會被轉換）。

自動在對話中加入等待的範例：

```
OnTranslateInternal
{
	_text = _argv[0]
	_text = REPLACE(_text, "…", "…\w3")
	_text = REPLACE(_text, "、", "、\w5")
	_text = REPLACE(_text, "。", "。\w9")
	_text
}
```

### 讓 Φ 之類的危險符號失效

和 Satori 一樣，YAYA 也有不能直接寫在對話中的符號。在 Satori 中，會在符號前加上「Φ」來使其失效。在 YAYA 中，則使用名為 [CHR](../functions/CHR.md) 的函式來撰寫。

請參考下列網站，查出想寫的符號的高 3 位元（表格橫軸上的符號）和高 4 位元（縱軸）。

- [[psl] ASCII 碼一覽表](http://www.psl.ne.jp/perl/pdojo00b.html)
- [字元碼表](http://winofsql.jp/VA003334/CprogBase040109013756.htm)

```
CHR(0x(上位3ビット)(上位4ビット))
```

像這樣撰寫。例如 `1` 就是 `CHR(0x31)`。務必使用半形字元。

在 `" "` 中撰寫 `"` 的範例：

```
記号表示テスト
{
	"\0\s[0]記号「%(CHR(0x22))」をバルーンに表示\e"
}
```

如果使用 Tc569-8 以後的版本，也可以將雙引號連續寫兩次，寫成 `""`（[值與變數](../grammar/03-values-and-variables.md#文字列)）。

### 註解

只要將 `＃` 換成 `//` 即可。

Satori：

```
＃ 起動イベント
＊OnBoot
：こんにちはー。
```

YAYA：

```
// 起動イベント
OnBoot
{
	"\0\s[0]こんにちはー。\e"
}
```

也可以放在下列這種位置。也就是說，從 `//` 開始往右的部分都會成為註解。

```
OnBoot
{
	"\0\s[0]こんにちはー。\e"// 起動トーク
}
```

也可以用 `/*` 和 `*/` 包住內容來加上註解。這種方式可以一次包住多行，因此行數較多時會比較方便。缺點是不太容易看出註解的起訖位置。

```
/*
起動イベント
一番最初に起動したとき呼ばれる
*/
OnBoot
{
	"\0\s[0]こんにちはー。\e"
}
```

YAYA 比 Satori 更容易加入註解，也更方便隨手使用。請多加一些註解，讓自己日後回頭查看時，能馬上想起各處的用途。

## 從 Satori 移轉到 YAYA 的人常見的疑問

### 啟動人格後完全沒有反應！

與 Satori 不同，YAYA 的辭典只要有一個字元的記述方式錯誤，人格就會無法運作。請確認是哪一處記述有誤。

- [使用玉檢查辭典錯誤](../tips/tama-error-check.md)

也可以查看執行記錄來確認。在與 `yaya.dll` 相同的資料夾中找到 `yaya.txt`，加入一行 `log, ayame.log` 後啟動人格，再用文字編輯器開啟輸出的 `ayame.log`。

### satori_savedata.txt（存檔資料）在哪裡？

全域變數會儲存在 `yaya_variable.cfg` 中（檔名可能會因範本而異）。

### 出現別名錯誤，這是什麼？

`descript.txt` 是否仍是 `shiori,satori.dll`？

也請參閱[遇到問題時的處理方式](../other/troubleshooting.md)。
