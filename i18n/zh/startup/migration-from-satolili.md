# 从 Satori 迁移

主要面向只用过 Satori 作为 SHIORI、但也想尝试使用 YAYA 的人。

## 前言

### 从 Satori 迁移到 YAYA 的优点

YAYA 擅长处理编程相关的内容，因此当人格的对话以外的部分变得杂乱、编写起来很麻烦时，使用 YAYA 会轻松一些。

不过，这并非 YAYA 独有的特点，[Kawari](http://www.towano.net/wk_kwr/)也是一个选择。如果不介意停止更新，那么其他 SHIORI 也可以考虑（但即使发现了缺陷，也不能指望它们得到修复）。了解各种 SHIORI 的特点，选择适合自己使用的 SHIORI 比较好。

### 关于 YAYA 的常见疑问

#### 听说这是面向理工科人士的 SHIORI……

也有人说：“我学的是文科，以前只用过 Satori，但 YAYA 很适合我，用起来很顺手。”也就是说，YAYA 是否适合某个人，与其是否属于理工科并无关系，关键在于是否合得来。只有实际用过之后才能知道。

#### 只有用过编程或 C 语言的人才能使用吗？

至少，写下这篇文章的人既没有编过程序，也没有用过 C 语言。

#### 它比 Satori 难吧？

这取决于要制作什么样的人格。对于以对话为主的简单人格，Satori 更容易上手；但对于动作复杂的人格，Satori 反而可能比 YAYA 更难懂。尤其是大量使用循环或数组时，用 Satori 编写的难度很可能会变高。

#### 听说它运行起来很占资源，是真的吗？

没听说它特别占资源。至少比 Satori 轻。如果觉得一个简单的 YAYA 人格运行起来很占资源，很可能是开启了“执行日志输出设置”或“无限制获取已安装人格列表”。

也许能作为参考的网站：[文件读写究竟有多慢（附加内容） | すくりや](http://nikolat.herokuapp.com/ukagaka/time-file-io/)（最下方的总结）

#### 文件操作和正则表达式只有 YAYA 才能用吗？

其他 SHIORI 也可以通过使用 SAORI 来实现。例如，[YAYA as SAORI](../other/yaya-as-saori.md) 将 YAYA 用作 SAORI 后，也能像 YAYA 一样进行文件操作和使用正则表达式。也就是说，不必只为了这些功能而选择 YAYA。

#### 能够制作出 Satori 绝对无法制作的人格吗？

如上所述，大多数事情都可以通过使用 SAORI 或改进写法，在 Satori 中实现。不过，词典是否容易编写、写法会变得多长，以及编写好的词典之后是否容易查看等方面，会有所不同。

### 注意事项

- Satori 会自动插入等待、换行、作用域切换标签等内容，而 YAYA 则需要全部**使用 Sakura Script 自行编写**。选项也必须使用 Sakura Script 编写
- YAYA 基本上除了对话以外，都使用半角字符编写
- Satori 即使没有模板人格，只要准备好 `satori.dll` 并查看手册，也能设法上手；但 YAYA 很难从零开始自行制作 SHIORI/3.0 设置脚本等内容（这些是人格运行时的齿轮部分），因此模板几乎是必需的。至少，最好沿用 SHIORI/3.0 设置脚本（[SimpleYAYA模板](../other/simple-yaya-template.md)中的 `yaya_shiori3.dic`）
- Satori 会自动读取扩展名为 `.txt`、文件名以 `dic` 开头的词典文件，而 YAYA **只会读取在 `yaya.txt` 中设置的词典**。另一方面，YAYA 可以读取任意扩展名的词典，也可以将词典放在任意目录中
- 与 Satori 一样，可以在任意词典中编写任意事件
- 无法按文件夹切换词典的读取方式（多重人格的实现方法见[多重人格模式](../tips/multiple-personality-mode.md)，但不是通过切换读取文件夹来实现）
- Satori 可以直接使用 SAORI-basic，而在 YAYA 中，Tc604-1 之前的版本必须通过名为 `proxy_ex.dll` 的 SAORI 才能使用。无需像在 Satori 中那样，在 `satori_conf.txt` 中编写 SAORI 定义（详情请参阅[SAORI的用法](../tips/saori-usage.md)）

### 建议提前准备的内容

- **文本编辑器**：基本上什么都可以，不过建议下载[编辑器语法高亮文件](../tips/editor-color-files.md)中介绍的文本编辑器，以及与之对应的语法高亮文件。这样更容易阅读代码。将其设置为打开扩展名为 `.dic` 的文件时自动应用语法高亮，会更加方便
- **模板人格**：从[使用 YAYA 制作人格](creating-ghost.md)中选择适合自己的模板。如前所述，这几乎是必需的

## 试着编写 YAYA 词典

以下内容可能不适用于[你好 YAYA 世界（紺野ややめ (Konnoyayame)）](http://ms.shillest.net/yayame.xhtml)和 SimpleYAYA 模板以外的模板（尤其是标题带有「☆」的项目）。

下面以启动事件为例。

### 基本

在 Satori 中是这样写的。

```
＊OnBoot
：いっちばーん。
```

在 YAYA 中则这样写。

```
OnBoot
{
	"\0\s[0]いっちばーん。\e"
}
```

其中有各种看起来不太明白的符号，下面逐个说明。

| 符号 | 说明 |
|------|------|
| `OnBoot` | 最先写的、表示启动事件的名称。这一点与 Satori 相同。在 YAYA 中称为函数名。[CROW・SSP 参考手册 - Shiori](http://crow.aqrs.jp/reference/all/Shiori/index.html)中记载的事件名，都可以直接在 YAYA 中使用。「启动」「结束」「初次」等日语事件名是 Satori 独有的事件名，即使在 YAYA 中使用，也不会原样触发 |
| `{ }` | 写好事件名后，用这两个符号将事件内容括起来。**在 YAYA 中编写 SHIORI Event 时，必须遵循「事件名{事件内容}」的格式**。如果没有正确括起来，就会报错，人格也无法启动 |
| `" "` | 对话等字符串必须用这两个符号括起来。**与 Satori 不同，未用这两个符号括起来的文字会被视为变量名或函数名**。另外，用 `' '` 代替 `" "` 括起来时，其中的变量不会展开。通常使用 `" "` 即可 |
| `\0` | 这是表示「接下来由 0 号角色（Sakura 侧）说话或改变表情」的 Sakura Script。此后写入的文本会显示在 0 号角色的对话框中。要让 1 号搭档角色说话，则使用 `\1`。在 Satori 中，这两个角色之间的切换只用「：」来表示 |
| `\s[0]` | 用于显示 0 号表面的 Sakura Script。在 Satori 中写作（０）。在 Satori 中可以省略开头的（０），但在 YAYA 中如果不写这个，开始对话前的表面就会继续显示 |
| `\e` | 表示对话结束的 Sakura Script。不写似乎也没有什么问题，不过为了保险起见，还是在对话末尾加上它 |

与 Satori 不同，YAYA 不会自动添加等待时间。需要添加时，请使用 Sakura Script。Sakura Script 也通用于 YAYA 以外的 SHIORI，因此本手册不作详细说明。除此之外还有很多内容，请在参考网站上挑选「实际想尝试使用的内容」，「一点一点地」学习，并同时学习 YAYA（如果一开始就想全部学会，脑袋会不堪重负）。

- [CROW参考手册 - SakuraScript](http://crow.aqrs.jp/reference/crow/SakuraScript/index.html)
- [Disc-2 SakuraScript列表](http://disc2.s56.xrea.com/manual/list_sakura_script.htm)

只要遵守先写事件名、用 `{ }` 括起内容等书写规则，像下面这样写也可以，

```
OnBoot {
"\0\s[0]いっちばーん。\e"
}
```

也可以像下面这样写。

```
OnBoot { "\0\s[0]いっちばーん。\e" }
```

`OnBoot` 和 `{` 之间等位置的空格、换行可以有，也可以没有。也可以使用制表符。选择自己看起来清楚、写起来方便的写法即可。

```
OnBoot{"\0\s[0]いっちばーん。\e"}
```

基本上，`" "` 以外的空格、制表符和换行都会被忽略，因此也可以写成下面这样。

```
OnBoot
	{

		"\0\s[0]いっちばーん。\e"

							}
```

也就是说，

```
【ここ】OnBoot【ここ】{【ここ】"\0\s[0]いっちばーん。\e"【ここ】}【ここ】
```

其中的【ここ】都可以任意添加空格（半角空格、全角空格、制表符）或换行。YAYA 可以利用这一机制自由整理词典。这也是 YAYA 的词典被认为比 Satori 更易于浏览的原因之一。

### 换行

在 Satori 中是这样写的。

```
＊OnBoot
：改行
します。
```

在 Satori 中，词典里的换行会直接成为对话中的换行，但**在 YAYA 中，必须使用 Sakura Script 换行，否则显示在对话框中时不会换行**。在想要换行的位置加入 `\n`。

```
OnBoot
{
	"\0\s[0]改行\nします。\e"
}
```

如果觉得“这样词典里没有换行，不太容易看懂”，可以像下面这样写。

```
OnBoot
{
	"\0\s[0]改行\n/
	します。\e"
}
```

像这样在行末加上 `/`，就可以换行。可以在喜欢的位置加入它。

```
OnBoot
{
	"\0\s[0]/
	改行\n/
	します。/
	\e"
}
```

错误示例：

```
OnBoot
{
	"\0\s[0]改行\n
	します。\e"
}
```

**如果在用 `" "` 或 `' '` 括起来的部分中换行时，行末没有加 `/`，就会发生错误，请注意。**

### 随机选择单词或句子

在 Satori 中，如果编写多个相同的事件，就会从中随机选出一个。

```
＊OnBoot
：こんにちはー。

＊OnBoot
：おっすー。

＊OnBoot
：やっほー。
```

但是，在 YAYA 中这样做会发生错误，导致无法启动。**YAYA 不能编写两个或更多同名事件。**取而代之的是，像下面这样在 `{ }` 中按换行分隔排列 `" "`。

```
OnBoot
{
	"\0\s[0]こんにちはー。\e"
	"\0\s[0]おっすー。\e"
	"\0\s[0]やっほー。\e"
}
```

**YAYA 中的 `{ }` 内有多个用 `" "` 或 `' '` 括起来的字符串时，会从中随机选择一个。**

也可以用 `;` 分隔来代替换行，写在同一行中。

```
OnBoot
{
	"\0\s[0]こんにちはー。\e" ; "\0\s[0]おっすー。\e" ; "\0\s[0]やっほー。\e"
}
```

如果觉得反复写 `\0\s[0]` 和 `\e` 很麻烦，可以像下面这样写。

```
OnBoot
{
	"\0\s[0]"
	--
	"こんにちはー。"
	"おっすー。"
	"やっほー。"
	--
	"\e"
}
```

**用 `--` 分隔后，会从每个分隔部分中随机选择一个用 `" "` 或 `' '` 括起来的字符串，并将它们连接起来显示。**

可能不太好理解，下面举例说明。

```
てんき
{
	"きょうは"  //←<1>この2つのどっちかが選ばれる
	"明日は"    //←<2>
	--
	"晴れ"      //←(1)この4つの中のどれかが選ばれる
	"雨"        //←(2)
	"曇り"      //←(3)
	"雷"        //←(4)
	--
	"です。"    //←1コしかないので必ずコレが選ばれる
}
```

这样写之后，

- “きょうは雨です。”
- “明日は曇りです。”
- “きょうは晴れです。”
- “明日は雷です。”
- “明日は晴れです。”

之类的句子就会在每次调用时随机生成。

由于是随机选择，也可能连续选中相同的单词。可能有人会想：“不能像 Satori 那样避免重复吗？”这是可以做到的。

```
OnBoot : nonoverlap
{
	"\0\s[0]"
	--
	"こんにちはー。"
	"おっすー。"
	"やっほー。"
	--
	"\e"
}
```

在事件名后面加上 ` : nonoverlap`。这样就不会连续选中相同的句子。想要按从上到下的顺序选择时，则使用 ` : sequential`（[函数的选择方式](../grammar/02-functions.md#選択方式)）。

顺带一提，在 Satori 中，可以像下面这样编写，从对话中调用写在其他位置的一组单词。

```
＊
：（季節）はいいね～
：どの季節でも言ってるジャン

＠季節
春
夏
秋
冬
```

在 YAYA 中实现相同的效果，则如下所示。

```
Talk
{
	"\0\s[0]%(季節)はいいね～\w9\1\s[10]どの季節でも言ってるジャン\e"
}

季節
{
	"春"
	"夏"
	"秋"
	"冬"
}
```

在对话中写上 `%(季節)` 或 `%季節`，就可以调用名为“季節”的函数（[展开字符串内嵌入的元素](../grammar/06-string-embedding.md)）。

在 Satori 中，单词集合要写成“＠季節”，而包含换行的句子则要写成“＊季節”，但**YAYA 不区分单词和句子，因此无论是单词还是句子，都写成“季節{ }”**。像 `OnBoot` 这样的 SHIORI 事件和单词集合都写作“函数”，所以写法也完全相同。

当然，也可以像上面编写天气对话那样，写成下面这样。

```
Talk
{
	"\0\s[0]"
	--
	"春"
	"夏"
	"秋"
	"冬"
	--
	"はいいね～\w9\1\s[10]どの季節でも言ってるジャン\e"
}
```

如果还想在其他对话中使用“季節”这组单词，最好使用最开始介绍的写法。

### 变量

变量在 Satori 中也很常见。可能很多人会用它来保存用户名、启动次数、启动时间和好感度等信息。Satori 中只有一种变量，而 YAYA 中有多种变量。首先来说明这方面的内容。

#### 字符串和数值

YAYA 的变量分为字符串和数值两种（准确来说有整数、实数、字符串三种）。

```
変数 = 1
```

这样赋值后，变量的内容就是数值 `1`。

```
変数 = "1"
```

像这样用 `" "` 或 `' '` 括起来赋值后，变量的内容就是字符串 `"1"`。

与 Satori 不同，全角的“１”“２”“３”……不能作为数值，会被当作字符串。**字符串变量不能作为数值进行比较或计算。**例如，将数值 `1` 和 `2` 相加，结果是 `3`；但将字符串 `"1"` 和 `"2"` 相加，两个字符串会连接起来，变成 `"12"`。还有其他各种区别，请注意。

可以随时将变量从字符串转换为数值，或从数值转换为字符串，不必担心。根据用途进行转换。

- 将变量转换为字符串变量：`変数 = TOSTR(変数)`
- 将变量转换为数值变量：`変数 = TOINT(変数)`

还有 [TOAUTO](../functions/TOAUTO.md)，它会自动判断变量是整数、实数还是字符串，并进行转换。

#### 全局变量与局部变量的区别

名称开头加上 `_` 就是局部变量，不加则是全局变量。

```
_変数名
変数名
```

粗略来说，局部变量是「临时使用、很快就会消失」的变量，全局变量则是「只要不删除就会一直保留」的变量。Satori 的变量全都是全局变量。在 YAYA 中，除了用户名、好感度等必须一直保留的变量以外，建议使用局部变量。

局部变量可以使用多长时间呢？它「只能在当前的 `{ }` 内及更深的嵌套层级中使用。其生命周期到离开对应的 `{ }` 为止」（参见[值与变量](../grammar/03-values-and-variables.md#スコープとライフタイム)）。

光用语言不太容易说明，下面举个例子。

```
ローカル変数テスト {
	{
		_変数 = 1
	}
	結果 = _変数
}
```

这样写的话，`_変数` 从较深层级移到较浅层级时会消失，因此 `結果` 的内容也会变为空。不过，

```
ローカル変数テスト {
	_変数 = ""
	{
		_変数 = 1
	}
	結果 = _変数
}
```

这样写的话，`_変数` 会从较浅层级 → 较深层级 → 较浅层级……由于它最初是在较浅层级创建的，因此即使从较深层级移到较浅层级也不会消失，`結果` 的内容会变成 1。关键在于 `_変数` 最初创建的位置，是否与 `結果 = _変数` 位于相同或更浅的层级。

也就是说，如果想让局部变量的生命周期更长，只要一开始就在最浅的层级写一行 `_○○ = ""` 等代码即可。

#### 变量赋值

下面是送出礼物并设置标志的例子。将礼物标志设为数值 1。

Satori:

```
＊プレゼントした
＄プレゼントフラグ＝１
：わーいありがとう！
```

YAYA:

```
プレゼントした
{
	プレゼントフラグ = 1

	"\0\s[0]わーいありがとう！\e"
}
```

与 Satori 的区别如下。

- 开头不加「＄」
- 对话、计算等都写在 `{ }` 内（写在 `{ }` 外会报错）
- `=` 等计算用符号、`1` 等数值都必须**使用半角字符**

如果你在 Satori 中也习惯用半角字符写计算表达式和数值，可能会觉得比较轻松。

```
【ここ】プレゼントフラグ【ここ】=【ここ】1【ここ】
```

【ここ】部分也可以填入空格或制表符。为了方便阅读，很多人会在运算符左右各加一个半角空格。

赋值字符串时，写法如下。将字符串「花束」放入变量「プレゼント」。

Satori:

```
＊プレゼントした
＄プレゼント【タブ】花束
：わーいありがとう！
```

YAYA:

```
プレゼントした
{
	プレゼント = "花束"

	"\0\s[0]わーいありがとう！\e"
}
```

值不是数值时，必须用 `" "` 或 `' '` 括起来。这和写对话时一样。不能像 Satori 那样写成「プレゼント【タブ】"花束"」。赋值时必须使用 `=`。

```
プレゼントした
{
	プレゼント = 花束

	"\0\s[0]わーいありがとう！\e"
}
```

不小心这样写的话，「プレゼント」的内容就会变为空。原因是，**在 YAYA 中，如果只写 `花束` 而不是 `"花束"`，它就会被视为名为「花束」的变量**。因此，这段代码会被误解为「将名为『花束』的变量的内容放入名为『プレゼント』的变量中」；而由于变量「花束」并不存在，内容就会变为空。

用 Satori 来说，相当于写成了下面这样。

```
＊プレゼントした
＄プレゼント【タブ】（花束）
：わーいありがとう！
```

这一点与 Satori 正好相反，刚开始可能会有些混乱。

#### 变量计算

Satori:

```
＊好感度アップ
＄好感度＝（好感度）＋１
：ユーザーさんだいすき！
```

YAYA:

```
好感度アップ
{
	好感度 = 好感度 + 1

	"\0\s[0]ユーザーさんだいすき！\e"
}
```

这里也很简单。在 Satori 中，需要像 `＄好感度＝（好感度）＋１` 这样给右侧的变量加上 `（ ）`；而在 YAYA 中不需要加任何符号。这是因为，如前所述，没有用 `" "` 或 `' '` 括起来的字符串会被视为变量名或函数名（如果只有半角数字，则会被视为数值）。

顺带一提，YAYA 也可以像下面这样省略写法。

```
好感度アップ
{
	好感度++

	"\0\s[0]ユーザーさんだいすき！\e"
}
```

`好感度++` 表示「将好感度增加 1」，与 `好感度 = 好感度 + 1` 相同。`好感度--`（两个半角减号）会让好感度减少 1。`好感度 += 2` 与 `好感度 = 好感度 + 2` 相同，`好感度 -= 2` 与 `好感度 = 好感度 - 2` 相同。YAYA 中可用的其他计算符号，请参阅[运算](../grammar/04-arithmetic.md)。

和 Satori 一样，也可以将字符串相加。

```
プレゼント = "花" + "束"
```

这样写的话，变量 `プレゼント` 的内容会变成 `"花束"`。

当然，也可以在对话中使用变量。

```
プレゼントした
{
	プレゼント = "花束"

	"\0\s[0]わーい\w6%(プレゼント)だー！\w9\w9ありがとう！\e"
}
```

对话框中会显示「わーい花束だー！ ありがとう！」。写法与上面说明的在对话中使用词组完全相同。这一点上，Satori 和 YAYA 没有区别。

想确认变量是否已正确保存时，先结束人格，再用文本编辑器打开存档数据文件（`yaya_variable.cfg`）。在上面的例子中，如果有如下这一行，就表示保存成功。

```
プレゼント,"花束",",",
```

顺带一提，如果是数值型变量，变量内容中的数字不会用 `" "` 括起来，例如：

```
プレゼントフラグ,1,",",
```

有关保存格式的详细信息，请参阅 [SAVEVAR](../functions/SAVEVAR.md#保存形式)。

### 分支

戳击反应的示例。`OnMouseDoubleClick` 事件有这样的规则：戳到 0 号角色（樱侧）时，`Reference3` 中会放入「0」。因此，可以编写一个词典，在确认 `Reference3` 中放入了 0 后，跳转到「0号被戳反应」。

里々:

```
＊OnMouseDoubleClick
＞0番さんがつつかれた【タブ】（R3）＝＝０

＊0番さんがつつかれた
：（７）つつくなっ！
```

YAYA:

```
OnMouseDoubleClick {
	if reference[3] == 0 {
		0番さんがつつかれた
	}
}

0番さんがつつかれた {
	"\0\s[7]つつくなっ！\e"
}
```

这里新出现了 `if`。`if` 的意思是，如果其后的条件表达式（这里是 `reference[3] == 0`）成立，就执行后面的 `{ }` 中的内容。

```
OnMouseDoubleClick {
	if reference[3] == 0 {
		"\0\s[7]つつくなっ！\e"
	}
}
```

当然，也可以像这样直接在 `{ }` 中写对话。请根据需要更改写法。

配合 `if` 使用 `else`，还可以实现下面这样的效果。

```
OnMouseDoubleClick {
	if reference[3] == 0 {
		"\0\s[7]つつくなっ！\e"
	}
	else {
		"\0\s[7]あたし以外の子もつつくなっ！\e"
	}
}
```

如果没有满足 `if 条件式 { }`，就会执行后面的 `else { }` 中的内容。在这个例子中，如果戳到的角色不是 0 号，就会执行 `else { }` 中的内容。请注意，`else` 只能放在 `if` 后面单独使用；单独写 `else` 会导致错误。

如果只想在戳到 0 号角色的「头部」时触发对话，可以这样写。

```
OnMouseDoubleClick {
	if reference[3] == 0 && reference[4] == "Head" {
		"\0\s[7]頭を叩くなっ！\e"
	}
}
```

可以并列写两个以上的条件表达式。除了半角和全角的区别之外，`==` 和 `&&` 符号的用法与里々完全相同。别忘了在 `if` 和 `reference[3] == 0` 之间加上空格或制表符。

话说回来，里々中的戳击反应应该是这样写的。

```
＊0Headつつかれ
：（７）頭を叩くなっ！

＊1つつかれ
：やめれ！
```

在 YAYA 中，能不能实现类似的效果呢？为此，可以使用下面这种写法。

```
OnMouseDoubleClick {
	EVAL( "%(reference[3])%(reference[4])つつかれ" )
}

0Headつつかれ {
	"\0\s[7]頭を叩くなっ！\e"
}

1つつかれ {
	"\1\s[10]やめれ！\e"
}
```

通常，如果只写 `"%(reference[3])%(reference[4])つつかれ"`，戳到 0 号角色的头部时，就会变成说出「0Headつつかれ」的人格对话。用 `EVAL( )` 将它包起来后，「0Headつつかれ」就会成为函数名。

这个 [EVAL](../functions/EVAL.md) 不仅能用于这种「可以直接写独立函数的分支」，在很多其他场合也很有用。

### Ｒ０、Ｓ０、Ａ０等在 YAYA 中的写法

全部使用半角字符书写。

| 里々 | YAYA | 备注 |
|------|------|------|
| `Ｒ０` `Ｒ１` `Ｒ２` … | `reference[0]` `reference[1]` `reference[2]` … | 旧版模板中使用的是 `reference0` `reference1` `reference2` …（新版模板也可以通过设置使用这种写法） |
| `Ｓ０` `Ｓ１` `Ｓ２` … | `valueex0` `valueex1` `valueex2` … | SAORI 的用法请参阅下文「SAORI」一节 |
| `Ａ０` `Ａ１` `Ａ２` … | `_argv[0]` `_argv[1]` `_argv[2]` … | 如变量名前带有 `_` 所示，这是局部变量 |

### 类似 ssu 的功能

「条件分支」「比较」和「计算」分别使用不同的方法实现，除此之外，几乎都可以通过 YAYA 的系统函数实现相同的功能。请参阅[系统函数一览](../system/system-functions-index.md)。

### SAORI

#### 用法

里々:

```
（mciaudio,load,鳥の詩.mp3）（mciaudio,play）
```

YAYA:

```
FUNCTIONEX( 'mciaudio.dll' , 'load' , '鳥の詩.mp3' )
FUNCTIONEX( 'mciaudio.dll' , 'play' )
```

不像里々那样需要事先设置要使用的 SAORI。直接指定相对于 `yaya.dll` 的 SAORI 路径即可。

顺带一提，如果 `mciaudio.dll` 和 `鳥の詩.mp3` 不在与 `yaya.dll` 相同的目录下，而是在它下面的 `saori` 目录中，则应这样写。

```
FUNCTIONEX( 'saori\mciaudio.dll' , 'load' , '鳥の詩.mp3' )
```

也可以不用 `FUNCTIONEX`，而改用 `SAORI` 执行（它是系统词典中的函数，是 `FUNCTIONEX` 的别名）。如果两种写法都可以，建议使用 `FUNCTIONEX`。

#### 返回值 Result

使用 SAORI 执行函数时，返回值会直接返回。如果想将返回值直接显示在对话框中，也可以像下面这样嵌入对话中使用（但请注意，SAORI 执行函数的参数必须用 `' '` 而不是 `" "` 括起来，因为不能在 `" "` 中写入 `" "`）。

```
"\0\s[0]クリップボードにある文字を取り出します。\n「%(FUNCTIONEX( 'saori\textcopy.dll' , 'コピーする文字' ))」\e"
```

也可以先将其保存到变量中再使用。

```
変数 = FUNCTIONEX( 'saori\textpaste.dll' )
```

如果不希望 Result 直接显示在对话框中，也可以将其赋值给适当的局部变量。

#### 返回值 Value[n]

如上所述，里々中写作 `Ｓ０` `Ｓ１` `Ｓ２` … 的内容，在 YAYA 中写作 `valueex0` `valueex1` `valueex2` …。

详情请参阅以下页面。

- [播放声音](../tips/play-sound.md)
- [SAORI 的用法](../tips/saori-usage.md)

### ☆显示当前时间

请参照[系统词典/yaya_shiori3.dic](../system/yaya-shiori3-dic.md)中的时间变量（`year` `month` `day` `weekday` `hour` `minute` `second`）。内存量和发送方标头的变量也可以在这里查看。

```
時間をおしえる
{
	"\0\s[0]ただいま%(hour)時%(minute)分%(second)秒で～す。\e"
}
```

如果你觉得「不能像里々那样用日语书写就不行」，也可以参考模板，自己编写。

年　{ GETTIME[0] }

秒　{ GETTIME[6] }

時間をおしえる

	"\0\s[0]ただいま%(時)時%(分)分%(秒)秒で～す。\e"

将星期转换为汉字表示的方法，请参阅[判断星期](../tips/detect-weekday.md)（SimpleYAYA 模板中已有介绍）。

### replace.txt

可以用 `#define` 实现相同的功能。不过，`#define` 会在 SHIORI 执行计算等操作之前，转换“词典中所写的全部原始字符串”，功能很强大，因此要注意避免连重要字符串也被转换等问题。详细用法请参阅[缩写书写函数、变量和 Sakura Script](../tips/shorthand-writing.md)。

例如，写入如下内容后，

```
#define @r reference
```

之前写作 `reference[0]` 的地方，就可以缩写为 `@r[0]`。

### ☆replace_after.txt

可以通过 `OnTranslate` 或 `OnTranslateInternal` 事件实现。如果是用于自动添加等待时间等用途，推荐使用 `OnTranslateInternal`（如果使用 `OnTranslate`，例如连标题栏的内容也会被转换）。

自动为对话添加等待时间的示例：

```
OnTranslateInternal
{
	_text = _argv[0]
	_text = REPLACE(_text, "…", "…\w3")
	_text = REPLACE(_text, "、", "、\w5")
	_text = REPLACE(_text, "。", "。\w9")
	_text
}
```

### 禁用像 Φ 这样危险的符号

和 Satori 一样，YAYA 中也有不能直接写入对话的符号。在 Satori 中，会在符号前加上「Φ」来禁用它。在 YAYA 中，则使用名为 [CHR](../functions/CHR.md) 的函数来书写。

请参考以下网站，查找要书写的符号的高 3 位（表格横轴上的符号）和高 4 位（纵轴）。

- [[psl] ASCII 代码一览表](http://www.psl.ne.jp/perl/pdojo00b.html)
- [字符代码表](http://winofsql.jp/VA003334/CprogBase040109013756.htm)

```
CHR(0x(上位3ビット)(上位4ビット))
```

像这样书写。例如，`1` 应写作 `CHR(0x31)`。必须使用半角字符。

在 `" "` 中书写 `"` 的示例：

```
記号表示テスト
{
	"\0\s[0]記号「%(CHR(0x22))」をバルーンに表示\e"
}
```

从 Tc569-8 起，也可以连续写两个双引号，即 `""`（[值与变量](../grammar/03-values-and-variables.md#文字列)）。

### 注释

只需将 `＃` 改为 `//`。

Satori：

```
＃ 起動イベント
＊OnBoot
：こんにちはー。
```

YAYA：

```
// 起動イベント
OnBoot
{
	"\0\s[0]こんにちはー。\e"
}
```

也可以写在如下位置。也就是说，从 `//` 开始到右侧的部分都会被注释掉。

```
OnBoot
{
	"\0\s[0]こんにちはー。\e"// 起動トーク
}
```

用 `/*` 和 `*/` 括起来也可以注释。它可以将多行一起括起来，因此行数较多时用这种方式更方便。缺点是稍微不容易看出注释的起止位置。

```
/*
起動イベント
一番最初に起動したとき呼ばれる
*/
OnBoot
{
	"\0\s[0]こんにちはー。\e"
}
```

YAYA 比 Satori 更容易添加注释，也更适合随手使用。为了日后回看时能立刻想起各处的用途，请多添加注释。

## 从 Satori 迁移到 YAYA 的人常见的问题

### 启动人格后完全没有反应！

与 Satori 不同，在 YAYA 中，只要词典的书写方式有一个字符错误，人格就无法运行。请检查具体哪些地方写错了。

- [使用玉检查词典错误](../tips/tama-error-check.md)

也可以查看运行日志。先在与 `yaya.dll` 同一层级的 `yaya.txt` 中添加一行 `log, ayame.log`，然后启动人格，再用文本编辑器打开生成的 `ayame.log`。

### satori_savedata.txt（存档数据）在哪里？

全局变量保存在 `yaya_variable.cfg` 中（不同模板使用的文件名可能不同）。

### 出现别名错误，这是怎么回事？

`descript.txt` 是否仍然是 `shiori,satori.dll`？
