# 从里々迁移

主要面向只用过里々作为 SHIORI，但也想尝试使用 YAYA 的人。

## 前言

### 从里々迁移到 YAYA 的优点

YAYA 擅长处理编程相关的内容，因此当人格的对话以外的部分变得杂乱、难以编写时，使用 YAYA 会轻松一些。

不过，这并非 YAYA 独有的特性，[華和梨](http://www.towano.net/wk_kwr/)也是一种选择。如果不介意停止更新，也可以考虑其他 SHIORI（但即使发现了缺陷，也无法期待它们得到修复）。了解各个 SHIORI 的特点，选择自己用起来顺手的 SHIORI 比较好。

### 关于 YAYA 的一些常见疑问

#### 听说这是面向理工科人士的 SHIORI……

也有人说：“我是文科生，以前只用过里々，但 YAYA 很适合我，用起来很顺手。”也就是说，是否适合使用 YAYA 与是不是理工科人士无关，取决于个人是否适应。实际用过之后才能知道。

#### 只有学过编程或 C 语言的人才能用吗？

至少，写下这篇文章的人既没学过编程，也没学过 C 语言。

#### 比里々更难吧？

这取决于要制作什么样的人格。以对话为主的简单人格，用里々会更轻松；但对于行为复杂的人格，里々反而有时会比 YAYA 更难理解。尤其是大量使用循环或数组时，用里々编写的难度很可能会变高。

#### 真的很占资源吗？

没听说 YAYA 特别占资源。至少比里々轻。如果觉得简单的 YAYA 人格运行起来很慢，很可能是开启了“执行日志输出设置”或“无限制获取已安装人格列表”。

可能有参考价值的网站：[ファイル読み書きはどれくらい遅いのか（追記あり） | すくりや](http://nikolat.herokuapp.com/ukagaka/time-file-io/)（最下方的总结）

#### 只有 YAYA 才能进行文件操作或使用正则表达式吗？

其他 SHIORI 也可以通过使用 SAORI 来实现。例如，通过 [YAYA as SAORI](../other/yaya-as-saori.md) 将 YAYA 用作 SAORI，就能像使用 YAYA 一样进行文件操作或使用正则表达式。也就是说，不必仅仅为了这些功能而选择 YAYA。

#### 能制作出里々绝对做不出来的人格吗？

如上所述，大多数功能都可以通过在里々中使用 SAORI 或改进写法来实现。不过，在词典是否容易编写、描述会变得多长，以及编写的词典之后是否容易阅读等方面，还是会有所不同。

### 注意事项

- 里々会自动添加等待、换行、切换作用域的标签等内容，而 YAYA 则需要**全部使用 Sakura Script 自行编写**。选项也必须使用 Sakura Script 编写
- YAYA 中除对话以外的内容基本上都使用半角字符编写
- 里々即使没有模板人格，也可以通过准备 `satori.dll` 并查看手册来应付；但 YAYA 很难从零开始自行编写 SHIORI/3.0 设置脚本等内容（也就是人格运行时的齿轮部分），因此模板几乎是必需的。至少，最好沿用 SHIORI/3.0 设置脚本（即 [SimpleYAYAテンプレート](../other/simple-yaya-template.md)中的 `yaya_shiori3.dic`）
- 里々会自动读取扩展名为 `.txt`、文件名以 `dic` 开头的词典文件，而 YAYA **只会读取在 `yaya.txt` 中设置的词典**。但作为交换，YAYA 也有可以读取任何扩展名的词典、可以将词典放在任意目录等优点
- 可以像里々一样，在任意词典中编写任意事件
- 无法按文件夹切换词典读取方式（[多重人格模式](../tips/multiple-personality-mode.md)中介绍了实现多重人格的方法，但不是通过切换读取文件夹来实现）
- 里々可以直接使用 SAORI-basic，但在 YAYA 中，Tc604-1 之前的版本必须通过名为 `proxy_ex.dll` 的 SAORI 才能使用。无需像在里々的 `satori_conf.txt` 中那样编写 saori 定义（详情请参阅[SAORIの使い方](../tips/saori-usage.md)）

### 建议事先准备的东西

- **文本编辑器**：基本上任何编辑器都可以，但建议下载[エディタ色分けファイル](../tips/editor-color-files.md)中提到的文本编辑器，以及与之对应的语法高亮文件。这样能让描述更容易阅读。设置为打开扩展名为 `.dic` 的文件时自动应用语法高亮，会更加方便
- **模板人格**：从[用 YAYA 制作人格](creating-ghost.md)中选择适合自己的模板。如前所述，模板几乎是必需的

## 试着编写 YAYA 词典

以下内容可能不适用于[はろーYAYAわーるど（紺野ややめ）](http://ms.shillest.net/yayame.xhtml)和 SimpleYAYA模板以外的模板（特别是标题中带有“☆”的项目）。

以启动事件为例。

### 基本

在里々中是这样写的。

```
＊OnBoot
：いっちばーん。
```

在 YAYA 中则这样写。

```
OnBoot
{
	"\0\s[0]いっちばーん。\e"
}
```

里面有许多不太明白的符号，下面逐一说明。

| 符号 | 说明 |
|------|------|
| `OnBoot` | 首先写的、表示启动事件的名称。这一点和里々差不多。在 YAYA 中称为函数名。[CROW・SSPリファレンス - Shiori](http://crow.aqrs.jp/reference/all/Shiori/index.html)中记载的事件名都可以直接写在 YAYA 中。“启动”“结束”“首次”等日语事件名是里々独有的事件名，即使在 YAYA 中使用，也不会直接触发 |
| `{ }` | 写完事件名后，用这两个符号括起事件的内容。**在 YAYA 中编写 SHIORI Event 时，必须使用“事件名{事件内容}”的格式**。如果没有正确括起来，就会发生错误，导致人格无法启动 |
| `" "` | 对话等字符串必须用这两个符号括起来。**与里々不同，不用它们括起来的内容会被视为变量名或函数名**。另外，如果用 `' '` 代替 `" "`，内部的变量就不会展开。通常使用 `" "` 即可 |
| `\0` | 这是 Sakura Script，表示“接下来由 0 号角色（樱花一侧）说话或改变表情”。之后写的文本会显示在 0 号角色的对话框中。若要让 1 号搭档角色说话，则使用 `\1`。在里々中，只用“：”就能切换这两者 |
| `\s[0]` | 这是显示 0 号 surface 的 Sakura Script。在里々中写作（０）。在里々中可以省略开头的（０），但在 YAYA 中如果不写这个，进行对话前显示的 surface 就会原样保留 |
| `\e` | 这是表示对话结束的 Sakura Script。不写似乎也没什么问题，但为了保险起见，最好在对话末尾加上 |

与里々不同，等待不会自动添加。需要时请使用 Sakura Script 添加。Sakura Script 也能在 YAYA 以外的 SHIORI 中通用，因此本手册不作详细说明。除此之外还有很多内容，请在参考资料网站上选择“想实际试用的内容”，一点一点地和 YAYA 一起学习即可（试图一下子全部记住会让人头脑发胀）。

- [CROWリファレンス - SakuraScript](http://crow.aqrs.jp/reference/crow/SakuraScript/index.html)
- [Disc-2 SakuraScriptリスト](http://disc2.s56.xrea.com/manual/list_sakura_script.htm)

只要遵守先写事件名、用 `{ }` 括起事件内容等格式规则，写成下面这样也可以，

```
OnBoot {
"\0\s[0]いっちばーん。\e"
}
```

写成下面这样也没问题。

```
OnBoot { "\0\s[0]いっちばーん。\e" }
```

`OnBoot` 和 `{` 之间的空格、换行等，可以添加也可以不添加。也可以使用制表符。选择自己看起来舒服、写起来方便的格式即可。

```
OnBoot{"\0\s[0]いっちばーん。\e"}
```

基本上，`" "` 外部的空格、制表符和换行都会被忽略，因此也可以写成下面这样。

```
OnBoot
	{

		"\0\s[0]いっちばーん。\e"

							}
```

也就是说，

```
【ここ】OnBoot【ここ】{【ここ】"\0\s[0]いっちばーん。\e"【ここ】}【ここ】
```

【ここ】的位置可以任意插入空格（半角空格、全角空格、制表符）或换行。这种机制让 YAYA 能够自由整理词典。这也是 YAYA 的词典被认为比里々更容易浏览的原因之一。

### 换行

在 Satori 中是这样写的。

```
＊OnBoot
：改行
します。
```

在 Satori 中，词典中的换行会直接变成对话中的换行，但**在 YAYA 中，如果不使用 Sakura Script 换行，显示在对话框中时就不会换行**。在想要换行的位置加入 `\n`。

```
OnBoot
{
	"\0\s[0]改行\nします。\e"
}
```

如果觉得「这样在词典中没有换行，不太容易看懂」，可以像下面这样写。

```
OnBoot
{
	"\0\s[0]改行\n/
	します。\e"
}
```

像这样在行末加入 `/` 就可以换行。可以在想要的位置加入使用。

```
OnBoot
{
	"\0\s[0]/
	改行\n/
	します。/
	\e"
}
```

错误示例：

```
OnBoot
{
	"\0\s[0]改行\n
	します。\e"
}
```

**请注意，如果在用 `" "` 或 `' '` 括起来的部分中换行，却没有在行末加入 `/`，就会发生错误。**

### 随机选择单词或句子

在 Satori 中，如果编写多个相同的事件，就会从中随机选择一个。

```
＊OnBoot
：こんにちはー。

＊OnBoot
：おっすー。

＊OnBoot
：やっほー。
```

但是在 YAYA 中这样做会发生错误，导致无法启动。**YAYA 不能编写两个以上名称相同的事件。**可以改为像下面这样，在 `{ }` 中按换行分隔排列 `" "`。

```
OnBoot
{
	"\0\s[0]こんにちはー。\e"
	"\0\s[0]おっすー。\e"
	"\0\s[0]やっほー。\e"
}
```

**在 YAYA 中，如果 `{ }` 内有多个用 `" "` 或 `' '` 括起来的字符串，就会从中随机选择一个。**

也可以用 `;` 分隔来代替换行，合并为一行。

```
OnBoot
{
	"\0\s[0]こんにちはー。\e" ; "\0\s[0]おっすー。\e" ; "\0\s[0]やっほー。\e"
}
```

如果觉得反复写 `\0\s[0]` 和 `\e` 很麻烦，可以像下面这样写。

```
OnBoot
{
	"\0\s[0]"
	--
	"こんにちはー。"
	"おっすー。"
	"やっほー。"
	--
	"\e"
}
```

**用 `--` 分隔时，会分别从每一段中随机选择一个用 `" "` 或 `' '` 括起来的字符串，并将它们连接起来显示。**

可能有些难以理解，下面举例说明。

```
てんき
{
	"きょうは"  //←<1>この2つのどっちかが選ばれる
	"明日は"    //←<2>
	--
	"晴れ"      //←(1)この4つの中のどれかが選ばれる
	"雨"        //←(2)
	"曇り"      //←(3)
	"雷"        //←(4)
	--
	"です。"    //←1コしかないので必ずコレが選ばれる
}
```

这样写的话，

- 「今天下雨。」
- 「明天阴天。」
- 「今天晴天。」
- 「明天打雷。」
- 「明天晴天。」

之类的句子，就会在每次调用时随机生成。

因为是随机选择，所以也可能连续选中相同的单词。可能有人会想「不能像 Satori 那样避免重复吗？」，这是可以做到的。

```
OnBoot : nonoverlap
{
	"\0\s[0]"
	--
	"こんにちはー。"
	"おっすー。"
	"やっほー。"
	--
	"\e"
}
```

在事件名后面加上 ` : nonoverlap`，就不会连续选中相同的句子。想让它按从上到下的顺序选择时，则使用 ` : sequential`（[函数的选择方式](../grammar/02-functions.md#選択方式)）。

顺便一提，在 Satori 中，可以像下面这样编写，以便在对话中调用写在其他位置的单词组。

```
＊
：（季節）はいいね～
：どの季節でも言ってるジャン

＠季節
春
夏
秋
冬
```

在 YAYA 中做同样的事，可以这样写。

```
Talk
{
	"\0\s[0]%(季節)はいいね～\w9\1\s[10]どの季節でも言ってるジャン\e"
}

季節
{
	"春"
	"夏"
	"秋"
	"冬"
}
```

在对话中写成 `%(季節)` 或 `%季節`，就可以调用名为「季節」的函数（[展开字符串内嵌入元素](../grammar/06-string-embedding.md)）。

在 Satori 中，单词组使用「＠季節」这样的写法，而会包含换行的句子则使用「＊季節」这样的写法。但**YAYA 不区分单词和句子，因此无论是单词还是句子，都写成「季節{ }」**。无论是 `OnBoot` 等 SHIORI 事件，还是单词组，都是作为「函数」编写，所以写法也完全相同。

当然，也可以像上面编写天气对话那样，写成下面这样。

```
Talk
{
	"\0\s[0]"
	--
	"春"
	"夏"
	"秋"
	"冬"
	--
	"はいいね～\w9\1\s[10]どの季節でも言ってるジャン\e"
}
```

如果还想在其他对话中使用「季節」这个单词组，最好采用最初介绍的写法。

### 变量

变量在 Satori 中也很常见。可能很多人会用它来处理用户名、启动次数、启动时间和好感度。Satori 中只有一种变量，而 YAYA 中有多种变量。先来介绍一下这方面的内容。

#### 字符串和数值

YAYA 的变量有字符串和数值两种（准确来说，有整数、实数、字符串三种）。

```
変数 = 1
```

这样赋值后，变量中的内容是数值 `1`。

```
変数 = "1"
```

像这样用 `" "` 或 `' '` 括起来赋值后，变量中的内容就会变成字符串 `"1"`。

与 Satori 不同，全角的「１」「２」「３」……不能作为数值，会被当作字符串处理。**如果变量是字符串，就不能将其作为数值进行比较或计算。**例如，数值 `1` 和 `2` 相加的结果是 `3`，但字符串 `"1"` 和 `"2"` 相加，会把 1 和 2 连在一起，变成 `"12"`。还有许多其他区别，请注意。

变量可以随时按需在字符串和数值之间转换，因此不用担心。根据用途进行转换即可。

- 将变量转换为字符串变量：`変数 = TOSTR(変数)`
- 将变量转换为数值变量：`変数 = TOINT(変数)`

还有会自动判断并转换为整数、实数或字符串的函数 [TOAUTO](../functions/TOAUTO.md)。

#### 全局变量与局部变量的区别

在名称开头加上 `_`，就是局部变量；不加则是全局变量。

```
_変数名
変数名
```

简单来说，局部变量是“临时使用、很快就会消失”的变量，全局变量则是“只要不删除就会一直保留”的变量。Satori 的变量全部都是全局变量。在 YAYA 中，除了用户名、好感度等必须一直保留的变量以外，建议使用局部变量。

局部变量可以使用多久呢？它“只能在当前的 `{ }` 内，以及比当前更深的嵌套层级中使用。其生命周期会持续到离开对应的 `{ }` 为止”（摘自[值与变量](../grammar/03-values-and-variables.md#スコープとライフタイム)）。

单靠文字不太容易说明，下面举个例子。

```
ローカル変数テスト {
	{
		_変数 = 1
	}
	結果 = _変数
}
```

这样写的话，`_変数` 从较深层级移到较浅层级时就会消失，因此 `結果` 的内容也会变为空。不过，

```
ローカル変数テスト {
	_変数 = ""
	{
		_変数 = 1
	}
	結果 = _変数
}
```

这样写的话，`_変数` 会按较浅层级 → 较深层级 → 较浅层级……的顺序变化；由于它最初是在较浅层级创建的，因此从较深层级移到较浅层级时不会消失，而是会继续保留，`結果` 的内容也会变成 1。关键在于，`_変数` 最初创建的位置是否与 `結果 = _変数` 位于同一层级或更浅的层级。

也就是说，如果想让局部变量的生命周期更长，只要一开始就在最浅的层级写一行 `_○○ = ""` 等内容即可。

#### 变量赋值

这是一个送出礼物并设置标志的例子。将礼物标志设为数值 1。

Satori:

```
＊プレゼントした
＄プレゼントフラグ＝１
：わーいありがとう！
```

YAYA:

```
プレゼントした
{
	プレゼントフラグ = 1

	"\0\s[0]わーいありがとう！\e"
}
```

与 Satori 的区别如下。

- 开头不加「＄」
- 对话、计算等内容都要写在 `{ }` 内（写在 `{ }` 外会出错）
- `=` 等用于计算的符号，以及 `1` 等数值，都要用**半角字符书写**

如果你在 Satori 中就习惯用半角字符书写计算表达式和数值，可能会觉得比较轻松。

```
【ここ】プレゼントフラグ【ここ】=【ここ】1【ここ】
```

【ここ】的部分可以填写空格或制表符。为了便于阅读，很多人会在运算符左右两边加半角空格。

要赋值字符串时，按下面这样写。将「花束」这个字符串放入名为「プレゼント」的变量中。

Satori:

```
＊プレゼントした
＄プレゼント【タブ】花束
：わーいありがとう！
```

YAYA:

```
プレゼントした
{
	プレゼント = "花束"

	"\0\s[0]わーいありがとう！\e"
}
```

如果不是数值，就必须用 `" "` 或 `' '` 括起来。这与写对话时相同。不能像 Satori 那样写成「プレゼント【タブ】"花束"」。赋值时必须使用 `=`。

```
プレゼントした
{
	プレゼント = 花束

	"\0\s[0]わーいありがとう！\e"
}
```

如果不小心这样写，「プレゼント」的内容就会变为空。原因是，**在 YAYA 中，不写 `"花束"` 而只写 `花束` 时，它会被视为“名为『花束』的变量”**。因此，这会被误解为“将名为『花束』的变量的内容放入名为『プレゼント』的变量中”；而由于名为「花束」的变量并不存在，其内容就会变为空。

用 Satori 来说，就相当于这样写了：

```
＊プレゼントした
＄プレゼント【タブ】（花束）
：わーいありがとう！
```

这一点与 Satori 正好相反，因此刚开始可能会有些混乱。

#### 变量计算

Satori:

```
＊好感度アップ
＄好感度＝（好感度）＋１
：ユーザーさんだいすき！
```

YAYA:

```
好感度アップ
{
	好感度 = 好感度 + 1

	"\0\s[0]ユーザーさんだいすき！\e"
}
```

这里也很简单。在 Satori 中，右侧的变量必须像 `＄好感度＝（好感度）＋１` 这样写成 `（ ）` 括起来的形式，而在 YAYA 中则不需要加任何符号。如前所述，没有用 `" "` 或 `' '` 括起来的字符串会被视为变量名或函数名（如果只有半角数字，则会被视为数值）。

顺带一提，YAYA 也可以像下面这样省略写法。

```
好感度アップ
{
	好感度++

	"\0\s[0]ユーザーさんだいすき！\e"
}
```

`好感度++` 表示“将好感度增加 1”，与 `好感度 = 好感度 + 1` 相同。`好感度--`（两个半角减号）则会减少 1。`好感度 += 2` 与 `好感度 = 好感度 + 2` 相同，`好感度 -= 2` 与 `好感度 = 好感度 - 2` 相同。关于 YAYA 中可用的其他计算符号，请参阅[运算](../grammar/04-arithmetic.md)。

与 Satori 一样，字符串之间也可以相加。

```
プレゼント = "花" + "束"
```

这样写的话，变量 `プレゼント` 的内容就会变成 `"花束"`。

当然，也可以在对话中使用变量。

```
プレゼントした
{
	プレゼント = "花束"

	"\0\s[0]わーい\w6%(プレゼント)だー！\w9\w9ありがとう！\e"
}
```

对话框中会显示「わーい花束だー！ ありがとう！」。写法与上文说明的在对话中使用词组时完全相同。这一点上，Satori 和 YAYA 没有区别。

如果想确认变量是否已正确保存，可以结束人格，然后用文本编辑器打开存档数据文件（`yaya_variable.cfg`）。以上面的例子来说，如果文件中有下面这一行，就表示保存成功。

```
プレゼント,"花束",",",
```

顺带一提，如果是数值型变量，变量内容中的数字不会被 `" "` 括起来，例如：

```
プレゼントフラグ,1,",",
```

关于保存格式的详细信息，请参阅 [SAVEVAR](../functions/SAVEVAR.md#保存形式)。

### 分支

以下是一个被戳反应的例子。`OnMouseDoubleClick` 事件有这样的规格：当 0 号角色（樱花侧）被戳时，`Reference3` 中会放入「0」。因此，试着编写一个词典，在确认 `Reference3` 中放入了 0 后，跳转到「0号被戳反应」。

Satori：

```
＊OnMouseDoubleClick
＞0番さんがつつかれた【タブ】（R3）＝＝０

＊0番さんがつつかれた
：（７）つつくなっ！
```

YAYA：

```
OnMouseDoubleClick {
	if reference[3] == 0 {
		0番さんがつつかれた
	}
}

0番さんがつつかれた {
	"\0\s[7]つつくなっ！\e"
}
```

这里新出现了 `if`。`if` 的意思是：如果其后条件表达式（这里是 `reference[3] == 0`）成立，就执行下一个 `{ }` 中的内容。

```
OnMouseDoubleClick {
	if reference[3] == 0 {
		"\0\s[7]つつくなっ！\e"
	}
}
```

当然，也可以像这样直接在 `{ }` 中写对话。请根据需要改变写法。

配合 `if` 使用 `else`，还可以实现以下效果。

```
OnMouseDoubleClick {
	if reference[3] == 0 {
		"\0\s[7]つつくなっ！\e"
	}
	else {
		"\0\s[7]あたし以外の子もつつくなっ！\e"
	}
}
```

如果不符合 `if 条件式 { }`，就执行其后 `else { }` 中的内容。在这个例子中，如果被戳的是 0 号以外的角色，就会执行 `else { }` 中的内容。请注意，`else` 只能写在 `if` 之后，单独写 `else` 会导致错误。

如果想只在 0 号角色的「头部」被戳时触发对话，可以这样写。

```
OnMouseDoubleClick {
	if reference[3] == 0 && reference[4] == "Head" {
		"\0\s[7]頭を叩くなっ！\e"
	}
}
```

可以并列写两个以上的条件表达式。除了半角和全角的区别，`==` 和 `&&` 符号的用法与 Satori 完全相同。别忘了在 `if` 和 `reference[3] == 0` 之间加上空格或制表符。

顺便说一下，在 Satori 中，被戳反应应该是这样写的。

```
＊0Headつつかれ
：（７）頭を叩くなっ！

＊1つつかれ
：やめれ！
```

在 YAYA 中，能不能实现类似的效果呢？如果你有这样的疑问，可以使用下面这种写法。

```
OnMouseDoubleClick {
	EVAL( "%(reference[3])%(reference[4])つつかれ" )
}

0Headつつかれ {
	"\0\s[7]頭を叩くなっ！\e"
}

1つつかれ {
	"\1\s[10]やめれ！\e"
}
```

通常，如果只写 `"%(reference[3])%(reference[4])つつかれ"`，那么 0 号角色的头部被戳时，会变成让人格说出「0Headつつかれ」的对话。用 `EVAL( )` 包起来后，「0Headつつかれ」就会成为函数名。

这个 [EVAL](../functions/EVAL.md) 不仅适用于这种「可以直接写独立函数的分支」，在许多其他场合也很有用。

### Ｒ０、Ｓ０、Ａ０ 在 YAYA 中的写法

全部使用半角字符。

| Satori | YAYA | 备注 |
|------|------|------|
| `Ｒ０` `Ｒ１` `Ｒ２` … | `reference[0]` `reference[1]` `reference[2]` … | 旧模板中使用的是 `reference0` `reference1` `reference2` …（新模板也可以通过设置这样写） |
| `Ｓ０` `Ｓ１` `Ｓ２` … | `valueex0` `valueex1` `valueex2` … | SAORI 的用法请参阅下面的「SAORI」一节 |
| `Ａ０` `Ａ１` `Ａ２` … | `_argv[0]` `_argv[1]` `_argv[2]` … | 从变量名前有 `_` 可以看出，这是局部变量 |

### 类似 ssu 的功能

「条件分支」「比较」和「计算」分别通过不同的方法进行，除此之外，基本上都可以用 YAYA 的系统函数实现。请参阅[系统函数一览](../system/system-functions-index.md)。

如果你觉得「这样很难找到想用的功能！」，还可以参考[YAYA 系统函数参考](http://navy.nm.land.to/post/y_sysfn.html)（外部网站）。

### SAORI

#### 用法

Satori：

```
（mciaudio,load,鳥の詩.mp3）（mciaudio,play）
```

YAYA：

```
FUNCTIONEX( 'mciaudio.dll' , 'load' , '鳥の詩.mp3' )
FUNCTIONEX( 'mciaudio.dll' , 'play' )
```

不需要像 Satori 那样事先设置要使用的 SAORI。直接指定相对于 `yaya.dll` 的 SAORI 路径即可。

顺便一提，如果 `mciaudio.dll` 和 `鳥の詩.mp3` 不在与 `yaya.dll` 相同的目录，而是在其下一级的 `saori` 目录中，则按如下方式编写。

```
FUNCTIONEX( 'saori\mciaudio.dll' , 'load' , '鳥の詩.mp3' )
```

也可以用 `SAORI` 代替 `FUNCTIONEX` 执行（它是系统词典中的函数，也是 `FUNCTIONEX` 的别名）。如果两种写法都可以，请使用 `FUNCTIONEX`。

#### 返回值 Result

使用 SAORI 执行函数时，返回值会直接传回。如果想将返回值直接显示在对话框中，也可以像下面这样嵌入对话中使用（但请注意，SAORI 执行函数的参数必须用 `' '` 而不是 `" "` 括起来，因为不能在 `" "` 中写 `" "`）。

```
"\0\s[0]クリップボードにある文字を取り出します。\n「%(FUNCTIONEX( 'saori\textcopy.dll' , 'コピーする文字' ))」\e"
```

也可以先保存到变量中再使用。

```
変数 = FUNCTIONEX( 'saori\textpaste.dll' )
```

如果不希望 Result 直接显示在对话框中，也可以将它赋给适当的局部变量。

#### 返回值 Value[n]

如上所述，在 Satori 中写作 `Ｓ０` `Ｓ１` `Ｓ２` … 的内容，在 YAYA 中写作 `valueex0` `valueex1` `valueex2` …。

详情请参阅以下页面。

- [播放声音](../tips/play-sound.md)
- [SAORI 的用法](../tips/saori-usage.md)

### ☆显示当前时间

参照[系统词典/yaya_shiori3.dic](../system/yaya-shiori3-dic.md)中的时间变量（`year` `month` `day` `weekday` `hour` `minute` `second`）。这里也可以查看内存用量和发送方标头变量。

```
時間をおしえる
{
	"\0\s[0]ただいま%(hour)時%(minute)分%(second)秒で～す。\e"
}
```

如果你觉得「不能像 Satori 那样用日语编写就不行」，也可以参考模板，自己编写。

```
年　{ GETTIME[0] }
月　{ GETTIME[1] }
日　{ GETTIME[2] }
分　{ GETTIME[5] }
秒　{ GETTIME[6] }

時間をおしえる
{
	"\0\s[0]ただいま%(時)時%(分)分%(秒)秒で～す。\e"
}
```

要将星期显示为汉字，请参照[判断星期](../tips/detect-weekday.md)（SimpleYAYA 模板中已有相关内容）。

### replace.txt

可以通过 `#define` 实现相同的功能。但 `#define` 会在 SHIORI 执行计算等操作之前，将「词典中原样写下的所有字符串」进行替换，因此要注意避免连重要字符串也被替换等问题。详细用法请参照[缩写函数、变量和 Sakura Script](../tips/shorthand-writing.md)。

例如，写下如下内容后，

```
#define @r reference
```

原本写作 `reference[0]` 的位置，就可以缩写为 `@r[0]`。

### ☆replace_after.txt

可以通过 `OnTranslate` 或 `OnTranslateInternal` 事件实现。如果用于自动等待等用途，更推荐使用 `OnTranslateInternal`（如果使用 `OnTranslate`，例如连头条内容也会被转换）。

自动为对话添加等待的示例：

```
OnTranslateInternal
{
	_text = _argv[0]
	_text = REPLACE(_text, "…", "…\w3")
	_text = REPLACE(_text, "、", "、\w5")
	_text = REPLACE(_text, "。", "。\w9")
	_text
}
```

### 像 Φ 一样使危险符号无效

和 Satori 一样，YAYA 中也有不能直接写入对话的符号。在 Satori 中，可以在符号前加上「Φ」使其无效。在 YAYA 中，则使用名为 [CHR](../functions/CHR.md) 的函数来编写。

请参考以下网站，查找想要编写的符号的高 3 位（表格横轴上的符号）和高 4 位（纵轴）。

- [[psl] ASCII代码一览表](http://www.psl.ne.jp/perl/pdojo00b.html)
- [字符代码表](http://winofsql.jp/VA003334/CprogBase040109013756.htm)

```
CHR(0x(上位3ビット)(上位4ビット))
```

像这样编写。例如，`1` 对应 `CHR(0x31)`。必须使用半角字符。

在 `" "` 中编写 `"` 的示例：

```
記号表示テスト
{
	"\0\s[0]記号「%(CHR(0x22))」をバルーンに表示\e"
}
```

从 Tc569-8 开始，也可以连续写两个双引号 `""`（[值与变量](../grammar/03-values-and-variables.md#文字列)）。

### 注释

只需将 `＃` 改为 `//`。

Satori：

```
＃ 起動イベント
＊OnBoot
：こんにちはー。
```

YAYA：

```
// 起動イベント
OnBoot
{
	"\0\s[0]こんにちはー。\e"
}
```

也可以放在如下位置。也就是说，从 `//` 开始直到右侧的所有内容都会被注释掉。

```
OnBoot
{
	"\0\s[0]こんにちはー。\e"// 起動トーク
}
```

也可以用 `/*` 和 `*/` 括起来进行注释。因为可以一次括起多行，如果行数较多，这种方式会更方便。缺点是有时不太容易看清注释的起止位置。

```
/*
起動イベント
一番最初に起動したとき呼ばれる
*/
OnBoot
{
	"\0\s[0]こんにちはー。\e"
}
```

YAYA 比 Satori 更容易添加注释，也更方便随手使用。请多添加注释，以便日后回看时能立刻想起各处内容的用途。

## 从 Satori 迁移到 YAYA 时常见的问题

### 启动人格后完全没有反应！

与 Satori 不同，在 YAYA 中，词典的编写方式只要有一个字符出错，人格就无法运行。请确认具体是哪里写错了。

- [使用玉检查词典错误](../tips/tama-error-check.md)

也可以查看运行日志。在与 `yaya.dll` 相同的目录下的 `yaya.txt` 中添加一行 `log, ayame.log`，然后启动人格，再用文本编辑器打开生成的 `ayame.log`。

### satori_savedata.txt（存档数据）在哪里？

全局变量保存在 `yaya_variable.cfg` 中（不同模板使用的文件名可能不同）。

### 出现了别名错误，这是怎么回事？

`descript.txt` 中是不是仍然写着 `shiori,satori.dll`？
