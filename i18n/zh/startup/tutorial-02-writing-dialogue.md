# 教程2：试着编写对话

## 打开词典文件所在的文件夹

在模板人格运行的状态下，点击开发面板最下方的“打开”按钮。然后选择“GHOST”，就会打开一个装有 yaya.dll 等各种文件的文件夹。里面扩展名为“.dic”的文件就是 YAYA 的词典文件。

词典文件中写着“人格要说什么话、做什么动作”。接下来，我们会逐步编辑这些内容，尝试制作人格。

## 查看词典内容

首先用文本编辑器打开主词典 `dic_main.dic`。在大约第 150 行的位置，应该能看到如下内容：

```
//起動
OnBoot
{
	"\1\s[10]\0\s[0]こんにちは。\e"
}
```

这里写的是“人格启动时说的台词”。第一次看到时，除了“こんにちは。”之外，可能都不知道是什么意思，所以我们来逐个弄清楚这些神秘符号。

| 要素 | 说明 |
|------|------|
| `OnBoot` | 函数名。这个例子中填写的是“人格启动时会被调用”的 SHIORI 事件名称。也就是说，这表示“后面的 `{ }` 中的内容是人格启动时的事件”。改成 `OnClose` 后，含义就变为“人格结束时的事件” |
| `{ }` | 函数的内容。写好函数名后，用这两个符号括起来，组成“函数名{函数的内容}” |
| `" "` | 对话和 Sakura Script 都必须用这些符号括起来。没有用 `" "` 或 `' '` 括起来的字符串会被当作变量名或函数名，而不是对话（`" "` 和 `' '` 的区别、变量名的含义会在后面说明） |
| `\0` | 这是 Sakura Script，表示“接下来由 0 号主角色（也称为 Sakura 侧）说话或改变表情”。后面写的文本会显示在 0 号角色的对话框中。写在 `\1` 后面的文本会显示在 1 号搭档角色（也称为 Unyū 侧）的对话框中 |
| `\s[0]` | 这是显示 0 号 surface 的 Sakura Script。surface 指的是立绘的种类。像 `\s[1]` 或 `\s[2]` 这样更改编号来写，就能让角色露出悲伤的表情或笑脸（不过，这个模板的默认外壳只有 0 号和 10 号图像，所以即使写成 `\s[1]` 或 `\s[2]`，也不会有任何变化） |
| `\e` | 这是表示对话结束的 Sakura Script。即使不写似乎也没有什么问题，但为了保险起见，还是把它放在对话末尾。它几乎就像一种咒语 |

关于 OnBoot 这类事件的详细信息，请参阅[CROW・SSP参考资料](http://crow.aqrs.jp/reference/all/Shiori/index.html)。基本上，这份参考资料中列出的 SHIORI Event 都可以用和 OnBoot 类似的写法来实现。

### 关于 Sakura Script

Sakura Script 也通用于 YAYA 以外的 SHIORI，因此本手册不再进一步详细说明。Sakura Script 还有很多其他内容，请在参考网站上逐步学习“自己想要实际使用的内容”（如果一上来就想全部记住，脑子会不堪重负）。

- [CROW参考资料 - SakuraScript](http://crow.aqrs.jp/reference/crow/SakuraScript/index.html)
- [UKADOC Project Sakura Script列表](https://ssp.shillest.net/ukadoc/manual/list_sakura_script.html)
- [Disc-2 SakuraScript列表](http://disc2.s56.xrea.com/manual/list_sakura_script.htm)（信息有些过时）

可以通过开发面板中的“脚本输入”编写并发送对话，练习编写 Sakura Script。

![通过脚本输入发送 `\0\s[0]やっほー！\e` 的效果](../attachment/img_tutorial_02_001.png)
发送后如果看起来没有问题，就在词典中实际编写，并确认能否正常说话（要确认 OnBoot 事件中的对话，需要先结束人格，再重新启动）。

## 尝试编写各种对话

### 让对话随机选出

每次启动都说同样的问候语会很无聊，所以试着把问候语增加到 3 种。

```
OnBoot
{
	"\0\s[0]こんにちはー。\e"
	"\0\s[0]おっすー。\e"
	"\0\s[0]やっほー。\e"
}
```

**YAYA 在 `{ }` 中有多个用 `" "` 或 `' '` 括起来的字符串时，会从中随机选出一个。**

如果想把内容合并到一行，可以用 `;` 代替换行。

```
OnBoot
{
	"\0\s[0]こんにちはー。\e" ; "\0\s[0]おっすー。\e" ; "\0\s[0]やっほー。\e"
}
```

如果觉得反复写 `\0\s[0]` 和 `\e` 很麻烦，可以这样写。

```
OnBoot
{
	"\0\s[0]"
	--
	"こんにちはー。"
	"おっすー。"
	"やっほー。"
	--
	"\e"
}
```

**用 `--` 分隔后，每个分隔段中都会随机选出一个用 `" "` 或 `' '` 括起来的字符串，再将它们拼接起来显示。**

也可以用 `;` 分隔，把这些内容写在一行中（不过不太容易看清）。

```
OnBoot
{
	"\0\s[0]" ; -- ; "こんにちはー。" ; "おっすー。" ; "やっほー。" ; -- ; "\e"
}
```

!!! warning "`--` 的写法"
    `--` 要么单独写在一行，要么用 `;` 分隔开来。如果像 `"こんにちは。" -- "おっすー。"` 这样既没有 `;` 也没有换行就连续写，会导致错误。

再举一个例子。

```
OnBoot
{
	"きょうは"  //←<1>この2つのどっちかが選ばれる
	"明日は"    //←<2>
	--
	"晴れ"      //←(1)この4つの中のどれかが選ばれる
	"雨"        //←(2)
	"曇り"      //←(3)
	"雷"        //←(4)
	--
	"です。"    //←1コしかないので必ずコレが選ばれる
}
```

这样写之后，会随机生成以下这些对话：

- “今天下雨。”
- “明天多云。”
- “今天晴天。”
- “明天有雷。”
- “明天晴天。”

对话的变化就丰富起来了。

不过，这样是真正的随机，同一个词也可能连续被选中。如果想避免这种情况，可以在函数名后面加上 ` : nonoverlap`。这样就不会连续选中同一句话。

```
OnBoot : nonoverlap
{
	"\0\s[0]"
	--
	"こんにちはー。"
	"おっすー。"
	"やっほー。"
	--
	"\e"
}
```

如果想让内容按顺序选出，可以加上 ` : sequential`。详情请参阅[函数的选择方式](../grammar/02-functions.md#選択方式)。

### 尝试创建自定义函数

上面写的、

```
OnBoot
{
	"\0\s[0]きょうは"
	"\0\s[0]明日は"
	--
	"晴れ"
	"雨"
	"曇り"
	"雷"
	--
	"です。\e"
}
```

可以改写成下面这样。

```
OnBoot
{
	"\0\s[0]きょうは"
	"\0\s[0]明日は"
	--
	天気一覧
	--
	"です。\e"
}

天気一覧
{
	"晴れ"
	"雨"
	"曇り"
	"雷"
}
```

像这样，也可以创建独立的自定义函数，然后调用它来编写内容。这样做有什么好处呢？

```
OnBoot
{
	"\0\s[0]きょうは"
	"\0\s[0]明日は"
	--
	天気一覧
	--
	"です。\e"
}

OnGhostChanged
{
	"\0\s[0]昨日は"
	--
	天気一覧
	--
	"だったよ。\e"
}

天気一覧
{
	"晴れ"
	"雨"
	"曇り"
	"雷"
}
```

像这样，可以从多个函数中调用，因此能够重复使用。

```
OnBoot
{
	"\0\s[0]きょうは%(天気一覧)です。\e"
}

天気一覧
{
	"晴れ"
	"雨"
	"曇り"
	"雷"
}
```

如果想在 `" "` 的内容中调用函数，可以像这样写成 `%(関数名)`（[展开字符串内嵌入元素](../grammar/06-string-embedding.md)）。

### 创建自定义函数时的注意事项

函数名（上例中的「天気一覧」）可以使用英文，也可以使用日文，但必须遵守以下规则。

- 函数名不能以半角数字开头（`5test` 不行，`test5` 和 `te5st` 可以）
- 不能在开头加上 `_`（否则会与局部变量混淆）
- 不能包含空格　`!`　`"`　`#`　`$`　`%`　`&`　`(`　`)`　`*`　`+`　`,`　`-`　`/`　`:`　`;`　`<`　`=`　`>`　`?`　`@`　`[`　`]`　`` ` ``　`{`　`|`　`}` 中的任何字符
- 等等

详情请参阅[函数的用户自定义函数定义与执行](../grammar/02-functions.md#ユーザー関数の定義と実行)。

## 让词典更易读

### 尝试添加空格和换行

只要遵守先写函数名，再用 `{ }` 括起内容的书写规则，

```
OnBoot {
	"\1\s[10]\0\s[0]こんにちは。\e"
}
```

这样写也可以，

```
OnBoot { "\1\s[10]\0\s[0]こんにちは。\e" }
```

这样写也可以，

```
OnBoot{"\1\s[10]\0\s[0]こんにちは。\e"}
```

`OnBoot` 和 `{` 之间等位置的空格、换行可以添加，也可以不添加。也可以使用制表符。请整理成自己觉得易读、易写的形式。

基本上，`" "` 之外的空格、制表符和换行都会被忽略，因此也可以这样写。

```
OnBoot
	{

		"\1\s[10]\0\s[0]こんにちは。\e"

							}
```

也就是说，

```
【ここ】OnBoot【ここ】{【ここ】"\0\s[0]いっちばーん。\e"【ここ】}【ここ】
```

其中的【ここ】部分，可以任意添加空格（半角空格、全角空格、制表符）或换行。YAYA 的词典可以利用这一机制整理得清晰易读。

### 注释

使用注释后，对应部分就不会作为词典内容加载。适用于「想添加备忘或注释」或「想暂时隔离已写好的词典中的一部分」等情况。用法很简单，只需在要注释的行首加入 `//`。

```
// 起動イベント
OnBoot
{
	"\0\s[0]こんにちはー。\e"
}
```

也可以放在下面这样的位置。也就是说，从 `//` 开始到行尾的所有内容都会成为注释。

```
OnBoot
{
	"\0\s[0]こんにちはー。\e"// 起動トーク
}
```

用 `/*` 和 `*/` 括起来也可以注释。由于可以一次注释多行，行数较多时这种方法更方便。缺点是，不容易看出注释部分的范围。

```
/*
起動イベント
一番最初に起動したとき呼ばれる
*/
OnBoot
{
	"\0\s[0]こんにちはー。\e"
}
```

请多添加注释，以便以后回头查看词典时，能马上想起各部分的用途。

### 不要这样做

请注意，进行下面这样的操作会导致错误，使人格完全无法运行。

```
OnBoot
{
	"\0\s[0]改行\n
	します。\e"
}
```

如果在用 `" "` 或 `' '` 括起来的字符串中途换行，就会导致错误。这种情况下，只要在行末添加 `/` 就可以换行。

```
OnBoot
{
	"\0\s[0]改行\n/
	します。\e"
}
```

此外，从 YAYA Tc535-1 开始，也可以使用[文档字符串](../grammar/03-values-and-variables.md#ヒアドキュメント)这种写法。

同名函数不能写两个或更多。务必只写一个。

```
//起動
OnBoot
{
	"\1\s[10]\0\s[0]こんにちは。\e"
}

OnBoot
{
	"\1\s[10]\0\s[0]やっほー！\e"
}
```

只要严格遵守这些规则，无论在什么词典文件的什么位置编写函数都没有问题（不过，最好尽量不要写在系统词典 `yaya_shiori3.dic` 中）。

## 人格完全不运行！这是错误吗？怎么办！

先冷静下来，查找错误的原因。

### 自己排查

之前人格还可以正常运行，因此错误原因当然在之后编写的词典中。仔细检查词典中自己修改过的部分。常见的问题是忘记闭合括号等。

如果还是找不到，就暂时注释掉可疑部分，然后重新启动人格。如果人格能够正常启动，原因就在被注释的部分。

### 使用 YAYA 调试工具

之前准备的「玉」。详情请参阅[使用玉检查词典错误](../tips/tama-error-check.md)。

### 查看运行日志

打开与 yaya.dll 位于同一目录的 `yaya.txt`。其中有如下项目。

```
//log, ayame.log	// ログを指定されたファイルに記録
```

将其改为：

```
log, ayame.log	// ログを指定されたファイルに記録
```

删除最左侧的 `//`，然后覆盖保存。再次启动人格后，会输出 `ayame.log`，请查看该文件。

### 查看脚本日志

当你想知道发送给人格的 Sakura Script 内容时，这个功能很有用。使用方法是「在 SSP 中右键单击人格 → 功能 → 脚本日志」。
