# 运算

## 基本

可以使用与 C 语言相同的格式进行四则运算、比较运算、赋值等操作。运算顺序根据各运算符的优先级确定。另外，括号 `( )` 内的部分会最优先进行运算。

## 运算符优先级（从高到低）

| 优先级 | 运算符 | 说明 |
|--------|--------|------|
| 1 | `( )` `[ ]` | 括号 |
| 2 | `!` | 否定 |
| 3 | `++` `--` | 加 1 / 减 1 |
| 4 | `*` `/` `%` | 乘除、取余 |
| 5 | `+` `-` | 加减 |
| 6 | `==` `!=` `>=` `<=` `>` `<` `_in_` `!_in_` | 比较 |
| 7 | `&&` | 逻辑与 |
| 8 | `\|\|` | 逻辑或 |
| 9 | `=` `:=` | 赋值 |
| 10 | `+=` `-=` `*=` `/=` `%=` `+:=` `-:=` `*:=` `/:=` `%:=` `,=` | 运算并赋值 |
| 11 | `,` | 枚举通用数组元素（优先级最低） |

- 带冒号（`:`）的赋值运算符是为保持向后兼容而保留的，在功能上与不带冒号的运算符相同
- `++` `--` `!` 是一元运算符
- `&` 是加在函数参数前的符号（[反馈运算符](#フィードバック演算子)），并非二元运算符，因此不包含在此表中
- 逗号运算符（`,`）和方括号 `[ ]` 的详细说明请参阅[数组](05-arrays.md)

## 比较与真假

`_in_` 和 `!_in_` 是用于检查字符串包含关系的运算符。`_in_` 在左侧字符串包含于右侧字符串时返回 1，否则返回 0。`!_in_` 则相反。

```
foo
{
    "or" _in_ "World"
}
```

上面的函数 `foo` 返回 1。

比较运算符在结果为真时返回整数 1，为假时返回 0。这些运算符也能正确作用于字符串，值的大小通过字典顺序比较来确定。

逻辑真假按以下规则判断。

- 假：整数 0、实数 0.0、空字符串、空通用数组
- 真：除此之外的所有值

非赋值运算的结果会直接作为输出。

```
foo
{
    (3+2)*4
}
```

此函数 `foo` 输出 20。

## 左结合

当相同优先级的运算符连续出现时，始终从左向右结合。例如：

```
1+2-3
```

会按 `1+2` → `3-3` 的顺序计算。

```
i = j = 10
```

这会产生什么结果？在 C 语言中，赋值运算符从右向左结合，因此会将 10 赋给 `i` 和 `j`。但在 YAYA 中，运算符始终从左向右结合，因此会按 `i = j` → `j = 10` 的顺序计算。所以 `i` 不会被赋值为 10。

```
i = (j = 10)
```

这样写的话，`i` 也会被赋值为 10。

## 类型强制转换（Type Coercion）

参与运算的项类型不一致时，结果类型如下。

- 整数与实数运算：结果为实数
- 整数 / 实数与字符串相加：数值转换为字符串后，与另一字符串拼接
- 整数 / 实数与字符串进行大小比较：数值转换为字符串后，按字典顺序比较大小
- 整数 / 实数与字符串进行运算（加法、大小比较以外）：无法运算，但不会出错。结果为空字符串

同一个运算表达式中可以混用不同类型。必要时，会根据上述规则进行类型转换。

```
"10+2は" + (10+2) + "です。"
```

首先将 `10+2` 作为整数计算，得到结果 12。其余部分都是与字符串相加，因此 12 会转换为字符串，并作为字符串进行拼接。

### 哈希运算（Tc600-3以降）

- `+`：如果另一方是标量或哈希，则将两者转换为字符串后拼接（`IHASH("a",1) + 1` 为 `"a=11"`）。如果另一方是数组，则对数组的每个元素分别进行拼接
- `-` `*` `/` `%`（包括复合赋值）：会发出警告 W0024。结果没有实际意义
- `==`：如果两者都是哈希，则当元素数量、键和值全部一致时为真。哈希与非哈希比较时始终为假

详情请参阅[哈希](12-hash.md#値としての振る舞い)。

## 使用括号( )控制运算顺序

用括号 `( )` 括起来的部分，运算优先级最高。`( )` 可以嵌套任意层数，嵌套越深，优先级越高。简单来说，就是“先计算括号里的部分”。这是理所当然的规则，但根据公式的写法，有时也会变得复杂。请看下面的例子。

```
answer = (_i = 10) + (2*(_i + 10))
```

如果不充分理解运算规则，就很难准确回答 `answer` 中会被赋什么值。`answer` 中存入的不是预期的 50，而是 30。

最先计算的是括号最深处，也就是 `_i + 10`。此时变量 `_i` 尚不存在。未定义的变量在与数值进行运算时会被视为 0，因此 `_i + 10` 的结果是 10，`2*(_i + 10)` 的结果是 20。之后，`(_i = 10)` 被求值，结果为 10，合计 30 被存入 `answer`。

按照我们的意图，希望先执行 `_i = 10` 赋值。在这种情况下，可以像下面这样多加几层括号，以控制运算顺序。

```
answer = (((_i = 10))) + (2*(_i + 10))
```

这样一来，赋值部分的优先级便会大幅提高，这次就会得到正确的结果（50）。

另外，你可能会认为，包住赋值部分的括号只要两层就足够了，但这是错误的。两层括号的深度与 `_i + 10` 相同，而在 `=` 和 `+` 之间，`+` 的优先级更高，因此 `_i + 10` 会先被计算。

## 反馈运算符

反馈运算符 `&` 是一种用法与其他运算符完全不同的独特运算符。

```
request
{
    _i = 1
    foo(&_i)
}

foo
{
    _argv[0] = 100
}
```

调用函数时，如果要将变量作为参数传入，可以在变量前写上 `&`。加上 `&` 的变量会与被调用函数 `_argv` 中对应的元素关联。也就是说，改写 `_argv` 时，调用方对应变量的值也会随之改写。在上面的例子中，执行 `foo` 后，`_i` 的值会被改写为 100。

反馈运算符可以在任意位置使用任意多个。

```
request
{
    foo(1, 2, &_value, "Hello", &_value2)

    _value + _value2
}

foo
{
    _argv[2] = _argv[0] + _argv[1]
    _argv[4] = _argv[3] + " World"
}
```

函数 `request` 会输出 `"3Hello World"`。当然，反馈运算符只能加在变量上。

也可以传入数组的元素。Tc600-4 及更高版本还可以传入哈希或嵌套元素中的元素（[多维赋值](13-nesting.md#多次元代入)）。

```
func(&_a[1])            // func の中で _argv[0] を書き換えると _a[1] が変わる
func(&_h["sub"]["x"])   // 同じく _h["sub"]["x"] が変わる（Tc600-4以降）
```

将数组变量作为参数传入时，`_argv` 中会展开并排列数组元素。写回时以展开后的所在位置为基准。

```
_a = (1, 2)
func(_a, &_x)           // _argv は (1, 2, _x の値)。_argv[2] を書き換えると _x が変わる
func(&_a)               // _argv の _a の要素数ぶんが、配列として _a に戻る
```

在 Tc603-3 及更早版本中，写回位置仍以参数所在位置（第几个参数）为准，因此在前面传入数组时，可能会写回其他元素，或者因 `_argv` 越界而中断执行。如果被调用的函数缩短了 `_argv`，则不会写回已不存在的参数。

即使第 1 个参数被括号括起来（`func((1, 2), &_x)` 或 `func((_a), &_x)`），其行为也与未加括号时相同（Tc603-5 及更高版本）。在 Tc603-4 及更早版本中，此时无法正确识别参数分隔符，因此 `&` 的写回不会生效。此外，传给系统函数的参数也会像未加括号时一样，分别作为独立参数处理。例如，`ARRAYSIZE((_a), 1)` 会返回 `_a` 的元素数，`TOSTR((1), (2))` 会变成 `"12"`（在此之前，第 1 个参数和第 2 个参数会合并为一个数组，`ARRAYSIZE` 的返回值会比元素数多 1，`TOSTR` 则会变成 `"1,2"`）。

## 向后兼容性

带冒号的赋值运算符（`":="`）为保持向后兼容而保留，但其行为与不带冒号的赋值运算符相同。
