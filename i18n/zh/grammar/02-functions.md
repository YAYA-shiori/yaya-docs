# 函数

## 概要

YAYA 中的“函数”是指，

- 接受 0 个或多个参数
- 从 0 个或多个“输出候选项”中选择一个输出并返回

这样的处理集合。

参数个数存储在变量 `_argc` 中，各个参数存储在变量 `_argv[n]` 中。n 是从 0 开始的参数编号。

输出候选项是函数内直接写入的字符串、数值、变量名等没有左值（`=` 左侧）的内容。如果存在多个输出候选项，YAYA 会从中选择一个作为函数的输出（返回值）。

存在多个同名函数时会发生错误（尤其是在基于已有的人格进行改编时要注意）。

下面的“基本结构”介绍的是作为通用语言 DLL 的 YAYA 中的“函数”。如果不太明白，可以跳过。

## 基本结构

下面展示一个程序代码整体，它会在执行 `request` 时返回字符串 `"Hello World"`。

```
request
{
    "Hello World"
}
```

加载了 YAYA 的模块执行 `HGLOBAL request(HGLOBAL h, long *len)` 时，会执行此脚本并返回 `"Hello World"`。`load` 和 `unload` 也一样。不过，`load` 和 `unload` 不会返回值，因此即使写了输出字符串也没有意义。在 `load` 中编写初始化处理，例如为变量设置初始值；在 `unload` 中则编写相应的清理代码。

只需编写需要的函数，不需要的函数可以省略。例如，在上面的示例中没有编写 `load` 和 `unload`，但这不会导致错误，只是什么也不做。极端而言，即使完全没有词典文件，也不会发生错误。在这种情况下，`load` 和 `unload` 什么也不做，`request` 则返回空字符串。

`load` 和 `request` 各有一个参数，可以通过变量取出。变量名为 `_argc` 和 `_argv`，与 C 语言 `main` 函数的接口类似。

### _argc

参数个数。在 `load` 和 `request` 中，参数是一个字符串，因此值为 1。`unload` 没有参数，因此此值为 0。

### _argv

存储参数的实际内容。它是一个包含 `_argc` 个元素的数组，各元素通过运算符 `[i]` 访问。序号 i 从 0 开始。例如，当 `_argc` 为 1 时，可以使用 `_argv[0]`，参数就存储在其中。

下面作为基础篇的总结，展示一段程序代码：在 `load` 中将 `"Hello"` 存入变量 `str`，在 `request` 中将作为参数传入的字符串与 `str` 连接后返回。

```
load
{
    str = "Hello"
}

request
{
    str + " " + _argv[0] + "!"
}
```

将处理对象字符串设为 `"World"` 并执行 `request`，结果会得到 `"Hello World!"`。

## 格式

需要遵循以下规则。

- 空行（只有换行符的行）、`//` 之后的内容，以及由 `/*` 和 `*/` 括起来的区域，都会被视为注释
- 如果一行以斜杠（`/`）结尾，则下一行会连接到该行末尾
- 行首以及单词之间可以自由插入空白字符。空白字符包括空格和制表符
- 如果想把多条语句挤在一行中编写，可以用分号（`;`）分隔

也就是说，前面列出的 Hello World 代码可以挤在一行中编写，如下所示。

```
request{"Hello World"}
```

写成下面这样也能运行（不过不建议这样写）。

```
req/
uest          {
"/
Hello World"  }
```

`/` 后一行（新连接的行）开头的空白字符会被视为缩进字符，并被删除。因此，下面的字符串连接结果是 `"ABCDEFG"`，而不是 `"ABCD　　EFG"`。

```
"ABCD/
    EFG"
```

关于第 4 条规则。下面的 `request` 会计算 1+2 的答案，并将其作为日语句子返回。

```
request
{
    answer = 1 + 2
    "答えは" + answer + "です。"
}
```

使用分号可以写成下面这样。

```
request
{
    answer = 1 + 2; "答えは" + answer + "です。"
}
```

分号写得过多也没有问题。多余的分号会被忽略，不会影响运行。因此，如果你习惯 C 语言的格式，也可以在每行末尾都写上分号。

## 用户自定义函数的定义与执行

除了 `load`、`unload` 和 `request` 之外，也可以创建任意名称的函数。只需写出创建的函数名称，就可以执行它。

```
request
{
    hello
}

hello
{
    "Hello World"
}
```

上面展示的是最简单的示例，`request` 最终会返回 `"Hello World"`。下面再展示一个稍复杂、但会得到相同结果的示例。

```
request
{
    combine("Hello", "World")
}

combine
{
    _argv[0] + " " + _argv[1]
}
```

在函数名后面加上 `( )`，并在其中用逗号列出数值，这些数值就会作为参数传递给对应的函数。也就是说，这些值会存入变量 `_argv` 和 `_argc`，并可以在该函数内引用。在这里的示例中，`combine` 函数内的 `_argc` 为 2，`_argv[0]` 为 `"Hello"`，`_argv[1]` 为 `"World"`。

### 不能用于函数名的名称

函数名可以自由命名，但与以下情况冲突的名称会导致错误。

- 以数字 0〜9 开头
    - 可能会被解释为数值常量
- 以下划线（`_`）开头
    - 以下划线开头的名称用于局部变量
- 包含以下字符：空格　`!`　`"`　`#`　`$`　`%`　`&`　`(`　`)`　`*`　`+`　`,`　`-`　`/`　`:`　`;`　`<`　`=`　`>`　`?`　`@`　`[`　`]`　`` ` ``　`{`　`|`　`}`　`~`
    - 最好不要使用下划线以外的符号
- 与保留字完全一致
    - 英文大写字母加下划线的名称用于系统函数
    - 还应避免使用 `for`、`while`、`if` 等用于控制结构的名称

### 递归调用

函数可以递归调用。下面给出一个最常见的例子：计算阶乘。

```
request
{
    factorial(5)
}

factorial
{
    if !_argv[0]
        1
    else
        factorial(_argv[0] - 1)*_argv[0]
}
```

`request` 会返回 120。

## 选择方式

```
request
{
    "Hello World"
    "こんにちは世界"
    "Hallo Welt"
}
```

像这样列举时，这些内容会被视为平等的“输出候选”，输出结果会是其中任意一个。可以指定以下任意一种选择方式。不过，`void` 和 `array` / `pool_array` 仅用于特殊用途。

| 方式 | 说明 |
|------|------|
| 未指定 / `random` | 随机选择（默认） |
| `nonoverlap` | 尽量不选择与紧邻上次相同的候选 |
| `sequential` | 按照记述顺序输出，输出到最后一项后回到开头 |
| `array` | 返回合并了所有输出候选的通用数组 |
| `void` | 不输出任何内容 |
| `all`（Tc567-1） | 将所有候选合并为一个字符串 |
| `last`（Tc567-1） | 选择最后一个候选 |

选择方式可以像 `: nonoverlap` 这样添加在函数名后面指定。

```
request : nonoverlap
{
    "Hello World"
    "こんにちは世界"
    "Hallo Welt"
}
```

```
request : sequential
{
    "Hello World"
    "こんにちは世界"
    "Hallo Welt"
}
```

有些函数每次执行时，输出候选的数量都会变化。例如，下面的函数会根据变量 `i` 的值，在 2 个或 4 个候选之间变化。

```
request : sequential
{
    if i {
        "1"
        "2"
    }
    "3"
    "4"
}
```

候选数量发生变化时，`nonoverlap` 和 `sequential` 的循环顺序会被初始化，并从头开始。只有在这种情况下，才可能重复输出与上次相同的值。

### array

将合并了所有输出候选的通用数组作为函数的返回值。

```
request : array
{
    "This is a pen."
    ("A","B","C")
    3.14
}
```

输出结果是通用数组 `("This is a pen.", "A", "B", "C", 3.14)`。

### void

不输出任何内容。对于下面的例子，`request` 不会输出 3 个候选中的任何一个。

```
request : void
{
    "Hello World"
    "こんにちは世界"
    "Hallo Welt"
}
```

请注意，这表示“什么也不输出”，而不是“什么也不执行”。内部写入的函数和数学表达式仍会被处理。

```
increment_i : void
{
    i++
    i
}
```

上面的函数 `increment_i` 会给 `i` 加 1。不指定 `void` 时，该函数会返回加法结果；指定 `void` 后则不会返回值，只会执行加法。

### all

在 Tc567-1 中实现。将所有选择候选合并为一个字符串。

### last

在 Tc567-1 中实现。从选择候选中选出最后一个候选作为输出。

## 修饰符

**`_pool`**：将带有 `_pool` 的代码块内部代码块中的候选，与外部候选放在同一层级进行选择。它既可以添加到函数本身（`OnTest : _pool`），也可以添加到代码块（`_pool : {`）。

通常，嵌套代码块整体会被视为一个候选。在下面的例子中，`"x"` 的概率为 1/2，`"y"` 和 `"z"` 的概率各为 1/4：

```
OnTest
{
  "x"
  {
    "y"
    "z"
  }
}
```

添加 `_pool` 后，内部代码块中的候选会被拆分，`"x"`、`"y"`、`"z"` 的概率都会变为 1/3：

```
OnTest : _pool
{
  "x"
  {
    "y"
    "z"
  }
}
```

- 无论嵌套多少层，候选都会被拆分（如果在第三层添加 `"z"`、`"w"`，则 4 个候选的概率各为 1/4）
- `if`、`elseif`、`else` 中的内容也会被拆分。条件为假、不会执行的代码块中的候选不会计入。写成 `if 条件 { "b" "c" }` 时，只有条件为真时，`"b"`、`"c"` 才会以与外部候选相同的概率被选中
- `while`、`for`、`foreach` 中的候选会在每次循环时各计入一个（循环 2 次的 `for` 中的 `"y"` 会计入 2 个候选）
- 像 `nonoverlap : {` 这样写明选择方式的代码块不会被拆分，仍作为一个候选
- 与选择方式组合时，写作 `_pool_nonoverlap`、`_pool_sequential`（可以省略 `_`）。未写选择方式时使用 `random_pool`（也可以只写 `pool`），并随机选择。也可以写成 `nonoverlap_pool`、`sequential_pool`、`array_pool`。重复回避和顺序选择会作用于拆分后的所有候选
- 添加到代码块时，只作用于该代码块内部。外部代码块中的候选仍会将该代码块视为一个候选
- 同一个代码块或函数不能同时指定 `_pool` 和 `melt_`

```
OnTest : _pool_nonoverlap
{
  "通常のセリフ"
  if is_rainy {
    "雨の日のセリフ1"
    "雨の日のセリフ2"
  }
}
```

当 `is_rainy` 为真时，会以相同的概率从 3 句对话中进行选择，并避免连续重复。为假时，只会选择 `"通常のセリフ"`。

**`melt_`**：使用通用数组生成并行输出效果。添加到代码块时，如果该代码块选出的输出是通用数组，就会拆分其元素，并将这些元素添加到紧邻外部代码块的输出候选中（效果与 [`parallel`](05-arrays.md) 相同）。它可以与选择方式组合，例如 `melt_nonoverlap`。如果内部代码块没有写选择方式，也会继承该选择方式。

```
OnTest
{
    "test"
    "test2"
    melt_nonoverlap : {
        ("red","green","blue")
    }
}
```

结果：输出 "test"、"test2"、"red"、"green"、"blue" 中的任意一个。

添加到函数本身时，由于没有外部代码块，会先拆分通用数组候选，再进行选择（Tc574-9 / Tc603-2 及以后版本）。通过 `return` 返回的通用数组不会被拆分。

```
OnTest : melt_nonoverlap
{
    "test"
    "test2"
    ("red","green","blue")
}
```

结果：与上面相同，从 5 个候选中选择，并避免重复。

在 Tc574-8 / Tc603-1 及更早版本中，添加到函数本身的 `melt_` 不起作用，通用数组仍会作为一个候选。此外，添加到两层以上内部代码块的 `melt_`，会将候选添加到函数最外层的代码块中，而不是紧邻的外部代码块。

## 嵌套

```
request
{
    {
        "Hello World"
        "こんにちは世界"
    }

    "Hallo Welt"
}
```

`{ }` 可以按层级任意嵌套。其行为与最外层的 `{ }` 相同，会从包含的候选项中选择一个并输出。不过，选择方式只能是随机抽取，不能像最外层那样指定 `nonoverlap` 或 `sequential`（Tc564-1 及之后的版本可以通过下文的“嵌套内的选择方式”指定）。

在上面的示例中，你可能会觉得无论有没有 `{ }`，结果都一样，但事实并非如此。没有 `{ }` 时，每项输出的概率都是 1/3。而在上面的示例中，首先会从 `"Hello World"` 和 `"こんにちは世界"` 中选择一项，然后再从该结果和剩下的 `"Hallo Welt"` 中抽取并输出。也就是说，`"Hello World"` 和 `"こんにちは世界"` 的出现率为 1/4，`"Hallo Welt"` 的出现率为 1/2。

### 嵌套内的选择方式

Tc564-1 及之后的版本可以为每个嵌套项添加前一节介绍的选择方式。

```
request
{
    nonoverlap : {
        "Hello World"
        "こんにちは世界"
    }

    "Hallo Welt"
}
```

要为紧跟在 `if` 语句等之后的 `{ }` 指定选择方式，可以用 `;` 分隔，如下所示，也可以添加换行。

```
request
{
    if 1 ; nonoverlap : {
        "Hello World"
        "こんにちは世界"
    }

    "Hallo Welt"
}
```

```
request
{
    if 1
    nonoverlap : {
        "Hello World"
        "こんにちは世界"
    }

    "Hallo Welt"
}
```

## 输出确定符

```
request
{
    "Hello"
    "Perfect"
    "Peaceful"
    --
    " Wor"
    --
    "ld"
    "th"
}
```

`--` 称为输出确定符，候选项会以此为分隔符分组。然后，将每组所选出的结果合并为一个字符串。因此，执行上面的 `request` 时，会输出以下任意一项。

```
"Hello World"
"Perfect World"
"Peaceful World"
"Hello Worth"
"Perfect Worth"
"Peaceful Worth"
```

`--` 必须单独写在一行。不能像 `"Hello" / "Perfect" -- …` 这样写在同一行，因为 `/` 会被视为除法。

与 `nonoverlap`、`sequential`、`array` 组合使用时，它会针对函数可能产生的所有组合执行（而不是以组为单位）。

例如，`sequential`：

```
request : sequential
{
    "1"
    "2"
    "3"
    --
    "A"
    "B"
}
```

会按以下顺序产生输出。

```
"1A" "2A" "3A" "1B" "2B" "3B" "1A" "2A" …
```

`array`：

```
request : array
{
    "1"
    "2"
    "3"
    --
    "A"
    "B"
}
```

会输出通用数组 `("1A","1B","2A","2B","3A","3B")`。

YAYA 除字符串外还可以处理数值等类型，但输出确定符在合并时会将它们全部转换为字符串，并作为字符串进行合并。
