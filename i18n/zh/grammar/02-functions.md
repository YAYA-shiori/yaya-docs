# 函数

## 概要

YAYA 中的「函数」是指，

- 接收 0 个或多个参数
- 从 0 个或多个「输出候选」中选择一个输出并返回

的一组处理。

参数数量存储在变量 `_argc` 中，各个参数存储在变量 `_argv[n]` 中。n 是从 0 开始的参数编号。

输出候选是指直接写在函数内的字符串、数值、变量名等没有左值（`=` 左侧）的内容。如果存在多个输出候选，YAYA 会从中选择一个，作为函数的输出（返回值）。

存在多个同名函数时会发生错误（尤其是在以已有的人格为基础进行改编时，请注意）。

下面的「基本结构」介绍的是作为通用语言 DLL 的 YAYA 中的「函数」。如果不太明白，可以跳过。

## 基本结构

下面展示一段完整的程序代码：执行 `request` 时返回字符串 `"Hello World"`。

```
request
{
    "Hello World"
}
```

加载了 YAYA 的模块执行 `HGLOBAL request(HGLOBAL h, long *len)` 时，会执行这段脚本并返回 `"Hello World"`。`load` 和 `unload` 也是如此。不过，`load` 和 `unload` 不会返回值，因此即使写了输出字符串也没有意义。可以在 `load` 中编写向变量赋初值等初始化处理，在 `unload` 中则编写相反的清理代码。

只需编写必要的函数，不需要的函数可以省略。例如，上面的示例没有编写 `load` 和 `unload`，这不会导致错误，只是什么也不做。举个极端的例子，即使完全没有词典文件，也不会发生错误。在这种情况下，`load` 和 `unload` 什么也不做，`request` 会返回空字符串。

`load` 和 `request` 各有一个参数，可以通过变量取出。变量名为 `_argc` 和 `_argv`，与 C 语言 `main` 函数的接口类似。

### _argc

参数数量。`load` 和 `request` 的参数是一个字符串，因此值为 1。`unload` 没有参数，因此值为 0。

### _argv

存储参数本身。它是一个包含 `_argc` 个元素的数组，通过运算符 `[i]` 访问各个元素。序号 i 从 0 开始。例如，当 `_argc` 为 1 时，可以使用 `_argv[0]`，参数就存储在其中。

作为基础篇的总结，下面展示一段程序代码：在 `load` 中将 `"Hello"` 存入变量 `str`，在 `request` 中将作为参数传入的字符串与 `str` 拼接后返回。

```
load
{
    str = "Hello"
}

request
{
    str + " " + _argv[0] + "!"
}
```

将处理对象字符串设为 `"World"` 并执行 `request` 后，结果为 `"Hello World!"`。

## 格式

规则如下。

- 空行（只有换行符的行）、`//` 之后的内容，以及由 `/*` 和 `*/` 括起来的部分都会被视为注释
- 如果一行以斜杠（`/`）结尾，则下一行会接到该行的后面
- 行首以及单词之间可以自由加入空白字符。空白字符包括空格和制表符
- 如果想把多个语句挤在一行中书写，可以用分号（`;`）分隔

也就是说，前面提到的 Hello World 代码可以挤在一行中写成下面这样。

```
request{"Hello World"}
```

写成下面这样也能运行（不过不建议这样写）。

```
req/
uest          {
"/
Hello World"  }
```

`/` 后面一行（新拼接的行）开头的空白字符会被视为缩进字符并删除。因此，下面字符串的拼接结果是 `"ABCDEFG"`，而不是 `"ABCD　　EFG"`。

```
"ABCD/
    EFG"
```

关于第 4 条规则。下面的 `request` 会计算 1+2，并以日语句子的形式返回结果。

```
request
{
    answer = 1 + 2
    "答えは" + answer + "です。"
}
```

使用分号后，可以写成下面这样。

```
request
{
    answer = 1 + 2; "答えは" + answer + "です。"
}
```

即使写入过多分号也没有问题。多余的分号会被忽略，不会影响运行。因此，如果熟悉 C 语言的格式，也可以在每行末尾都写上分号。

## 用户自定义函数的定义与执行

除了 `load`、`unload`、`request` 以外，也可以创建任意名称的函数。只要写出创建的函数名称，就可以执行它。

```
request
{
    hello
}

hello
{
    "Hello World"
}
```

上面是最简单的示例，`request` 最终会返回 `"Hello World"`。下面展示一个稍复杂、但结果相同的示例。

```
request
{
    combine("Hello", "World")
}

combine
{
    _argv[0] + " " + _argv[1]
}
```

在函数名后加上 `( )`，并在其中用逗号列出值，这些值就会作为参数传递给相应的函数。也就是说，值会存储在变量 `_argv` 和 `_argc` 中，并可在函数内引用。在这里的示例中，`combine` 函数内的 `_argc` 为 2，`_argv[0]` 为 `"Hello"`，`_argv[1]` 为 `"World"`。

### 不能用作函数名的名称

函数名可以自由指定，但与以下规则冲突的名称会导致错误。

- 以数字 0〜9 开头
    - 可能会被解释为数值常量
- 以下划线（`_`）开头
    - 以下划线开头的名称用于局部变量
- 包含以下字符：空格　`!`　`"`　`#`　`$`　`%`　`&`　`(`　`)`　`*`　`+`　`,`　`-`　`/`　`:`　`;`　`<`　`=`　`>`　`?`　`@`　`[`　`]`　`` ` ``　`{`　`|`　`}`　`~`
    - 最好不要使用下划线以外的符号
- 与保留字完全一致
    - 英文大写字母加下划线的名称用于系统函数
    - 也应避免使用 `for`、`while`、`if` 等用于控制结构的名称

### 递归调用

函数可以递归调用。下面给出一个最常见的例子：计算阶乘。

```
request
{
    factorial(5)
}

factorial
{
    if !_argv[0]
        1
    else
        factorial(_argv[0] - 1)*_argv[0]
}
```

`request` 返回 120。

## 选择方式

```
request
{
    "Hello World"
    "こんにちは世界"
    "Hallo Welt"
}
```

像这样列出时，它们会被视为平等的「输出候选」，输出结果是其中任意一个。可以指定以下任一种选择方式。不过，`void` 和 `array` / `pool_array` 仅用于特殊用途。

| 方式 | 说明 |
|------|------|
| 未指定 / `random` | 随机选择（默认） |
| `nonoverlap` | 尽可能不选择与紧邻上次相同的候选 |
| `sequential` | 按照记述顺序输出，到末尾后返回开头 |
| `array` | 返回将所有输出候选合并而成的通用数组 |
| `void` | 不输出任何内容 |
| `all`（Tc567-1） | 将所有候选合并为一个字符串 |
| `last`（Tc567-1） | 选择最后一个候选 |

在函数名后添加 `: nonoverlap` 这样的内容，即可指定选择方式。

```
request : nonoverlap
{
    "Hello World"
    "こんにちは世界"
    "Hallo Welt"
}
```

```
request : sequential
{
    "Hello World"
    "こんにちは世界"
    "Hallo Welt"
}
```

有些函数的输出候选数会随每次执行而变化。例如，下面的函数中，候选数会根据变量 `i` 的值变为 2 个或 4 个。

```
request : sequential
{
    if i {
        "1"
        "2"
    }
    "3"
    "4"
}
```

候选数发生变化时，`nonoverlap` 和 `sequential` 的循环顺序会被重置，并从头开始。在这种情况下，前后两次可能会输出相同的值。

### array

将所有输出候选合并而成的通用数组作为函数的返回值。

```
request : array
{
    "This is a pen."
    ("A","B","C")
    3.14
}
```

输出结果为通用数组 `("This is a pen.", "A", "B", "C", 3.14)`。

### void

不输出任何内容。在下面的例子中，`request` 不会输出 3 个候选中的任何一个。

```
request : void
{
    "Hello World"
    "こんにちは世界"
    "Hallo Welt"
}
```

请注意，这表示「不输出任何内容」，而不是「不执行任何操作」。其中写入的函数和数学表达式仍会被处理。

```
increment_i : void
{
    i++
    i
}
```

上面的函数 `increment_i` 会将 `i` 加 1。不指定 `void` 时，该函数会返回加算结果；指定 `void` 后，则不会返回值，只会执行加算。

### all

在 Tc567-1 中实现。将所有选择候选合并为一个字符串。

### last

在 Tc567-1 中实现。从选择候选中选取最后一个候选作为输出。

## 修饰符

**`_pool`**：将带有 `_pool` 的块内部块的候选，与外部候选放在同一层级进行选择。可以添加到函数本身（`OnTest : _pool`），也可以添加到块（`_pool : {`）。

通常，嵌套块整体会被视为一个候选。下面的例子中，`"x"` 的概率为 1/2，`"y"` 和 `"z"` 的概率各为 1/4：

```
OnTest
{
  "x"
  {
    "y"
    "z"
  }
}
```

添加 `_pool` 后，内部块的候选会被拆开，`"x"`、`"y"`、`"z"` 的概率均为 1/3：

```
OnTest : _pool
{
  "x"
  {
    "y"
    "z"
  }
}
```

- 无论嵌套多少层，都会拆开（如果在第 3 层添加 `"z"`、`"w"`，则 4 个候选的概率各为 1/4）
- `if`、`elseif`、`else` 中的内容也会被拆开。条件为假、不执行的块中的候选不会加入。写成 `if 条件 { "b" "c" }` 时，只有条件为真，`"b"`、`"c"` 才会以与外部候选相同的概率被选中
- `while`、`for`、`foreach` 中的候选会在每次循环时各加入一个（循环 2 次的 `for` 中的 `"y"` 会计为 2 个候选）
- 像 `nonoverlap : {` 这样写了选择方式的块不会被拆开，仍作为一个候选
- 与选择方式组合时，写作 `_pool_nonoverlap`、`_pool_sequential` 等（可以省略 `_`）。未指定方式时，使用 `random_pool`（也可以只写 `pool`），并随机选择。也可以写作 `nonoverlap_pool`、`sequential_pool`、`array_pool` 等。拆分后的候选整体适用避免重复或顺序选择
- 添加到块时，仅作用于该块内部。外部块的候选仍会将该块视为一个候选
- 同一个块或函数不能同时指定 `_pool` 和 `melt_`

下面举例说明有无 `_pool` 时选择概率的变化。在下面的函数中，不添加 `_pool` 时，`"Hello World"` 的概率为 50%，`"こんにちは世界"` 和 `"Hallo Welt"` 的概率各为 25%。写成 `: random_pool`（也可以只写 `_pool`）时，3 个候选的概率各为 33.3%。`if 1` 始终为真。

```
request : random
{
    "Hello World"
    if 1 {
        "こんにちは世界"
        "Hallo Welt"
    }
}
```

```
OnTest : _pool_nonoverlap
{
  "通常のセリフ"
  if is_rainy {
    "雨の日のセリフ1"
    "雨の日のセリフ2"
  }
}
```

当 `is_rainy` 为真时，会以相同的概率选择 3 句对话，并避免连续重复。为假时，只会选择 `"通常のセリフ"`。

**`melt_`**：使用通用数组生成并行输出效果。添加到块时，如果该块选中的输出是通用数组，就会拆分其元素，并将它们加入紧邻外层块的输出候选中（效果与 [`parallel`](05-arrays.md) 相同）。也可以与选择方式组合，例如 `melt_nonoverlap`。未指定选择方式的内部块也会继承该方式。

```
OnTest
{
    "test"
    "test2"
    melt_nonoverlap : {
        ("red","green","blue")
    }
}
```

结果："test"、"test2"、"red"、"green"、"blue" 中的任意一个。

添加到函数本身时，由于没有外层块，会先拆分通用数组候选，再进行选择（Tc574-9 / Tc603-2 及之后版本）。通过 `return` 返回的通用数组不会被拆分。

```
OnTest : melt_nonoverlap
{
    "test"
    "test2"
    ("red","green","blue")
}
```

结果：从与上面相同的 5 个候选中选择，并避免重复。

在 Tc574-8 / Tc603-1 及之前版本中，添加到函数本身的 `melt_` 不会生效，通用数组会原样作为一个候选。此外，添加到内侧两层或更多层块的 `melt_`，会将候选加入函数最外层的块，而不是紧邻的外层块。

## 嵌套

```
request
{
    {
        "Hello World"
        "こんにちは世界"
    }

    "Hallo Welt"
}
```

`{ }` 可以按层级嵌套任意多层。其行为与最外层的 `{ }` 相同，会从包含的候选项中选择一个并输出。不过，选择方式仅支持随机抽取，不能像最外层那样指定 `nonoverlap` 或 `sequential`（Tc564-1 及之后的版本可以通过下文的“嵌套内的选择方式”进行指定）。

在上面的例子中，无论有没有 `{ }`，结果似乎都一样，但事实并非如此。没有 `{ }` 时，每个选项被输出的概率都相同，为 1/3。而在上面的例子中，首先会从 `"Hello World"` 和 `"こんにちは世界"` 中选择一个，然后再从该结果和剩下的 `"Hallo Welt"` 中抽取一个输出。也就是说，`"Hello World"` 和 `"こんにちは世界"` 的出现率为 1/4，`"Hallo Welt"` 的出现率为 1/2。

### 嵌套内的选择方式

从 Tc564-1 开始，可以为每个嵌套添加上一节所述的选择方式。

```
request
{
    nonoverlap : {
        "Hello World"
        "こんにちは世界"
    }

    "Hallo Welt"
}
```

要为紧跟在 `if` 语句等之后的 `{ }` 指定选择方式，可以用 `;` 分隔，如下所示；也可以添加换行。

```
request
{
    if 1 ; nonoverlap : {
        "Hello World"
        "こんにちは世界"
    }

    "Hallo Welt"
}
```

```
request
{
    if 1
    nonoverlap : {
        "Hello World"
        "こんにちは世界"
    }

    "Hallo Welt"
}
```

## 输出确定符

```
request
{
    "Hello"
    "Perfect"
    "Peaceful"
    --
    " Wor"
    --
    "ld"
    "th"
}
```

`--` 称为输出确定符，候选项会以它为分隔符进行分组。然后，将每组中选出的结果合并为一个字符串。因此，执行上面的 `request` 时，会输出以下任意一种结果。

```
"Hello World"
"Perfect World"
"Peaceful World"
"Hello Worth"
"Perfect Worth"
"Peaceful Worth"
```

`--` 必须单独写在一行中。不能像 `"Hello" / "Perfect" -- …` 这样写在同一行中，因为 `/` 会被解释为除法。

与 `nonoverlap`、`sequential`、`array` 组合使用时，它会对函数可能产生的所有组合生效，而不是对每个分组单独生效。

例如，`sequential`：

```
request : sequential
{
    "1"
    "2"
    "3"
    --
    "A"
    "B"
}
```

会按以下顺序产生输出。

```
"1A" "2A" "3A" "1B" "2B" "3B" "1A" "2A" …
```

`array`：

```
request : array
{
    "1"
    "2"
    "3"
    --
    "A"
    "B"
}
```

会输出一个通用数组 `("1A","1B","2A","2B","3A","3B")`。

YAYA 除字符串外也可以处理数值等类型，但输出确定符在合并时会将它们全部转换为字符串，再作为字符串进行合并。
