# 字符串内嵌入元素的展开

## 概要

可以在字符串中嵌入变量或函数，并将它们的执行结果插入相应位置。嵌入方式有「带范围展开」和「名称最长匹配展开」两种。

## 带范围展开

将元素用 `%( )` 括起来嵌入。

```
request
{
    _i = "pen"
    "This is a %(_i)."
}
```

执行 `request` 后，会输出 `"This is a pen."`。`%( )` 的行为类似于所谓的 eval（将字符串解释为脚本代码并执行）。不仅可以嵌入单个函数或变量，也可以嵌入数学表达式。

```
request
{
    "1+2+3は%(1+2+3)です。"
}
```

`request` 会输出 `"1+2+3は6です。"`。

`%( )` 中不能包含双引号。因此，不能嵌入包含字符串的表达式。以下写法会导致错误。

```
request
{
    "This is a %(_i = "pen")."
}
```

这种情况下，不使用嵌入，而是将其作为普通表达式进行连接。

```
request
{
    "This is a " + (_i = "pen") + "."
}
```

使用括号 `( )` 控制运算顺序，在带范围展开中也同样有效。请看下面的例子。

```
request
{
    "遊星「%(_i = planet)」は遠い。この遊星は%(color(_i))色をしている。"
}

planet
{
    "mars"
    "saturn"
    "pluto"
}

color
{
    case _argv[0] {
    when "mars";   "red"
    when "saturn"; "yerrow"
    when "pluto";  "blue"
    others;        "unknown"
    }
}
```

最深层的 `( )` 是 `color(_i)` 的参数，因此会在 `_i = planet` 之前调用 `color`，而此时 `_i` 仍为空，所以结果会是 `"unknown"`。可以添加多层括号来调整运算顺序。

```
"遊星「%((_i = planet))」は遠い。この遊星は%(color(_i))色をしている。"
```

这样就能得到前后连贯的字符串。

**特点：**

- 支持复杂表达式和数学运算
- 字符串内不能包含双引号
- 由于会在读取词典时进行静态解析，因此无法识别通过 [DICLOAD](../functions/DICLOAD.md) 等方式后来定义的函数。如果确实需要这样使用，请考虑使用 [EVAL](../functions/EVAL.md)

## 名称最长匹配展开

即使不添加 `( )`，只使用 `%` 也能进行嵌入展开。

```
request
{
   o      = "pen"
   obj    = "eraser"
   object = "world"
   "This is a %object."
}

obje
{
    "television"
}
```

展开对象是 `%` 后面的字符串中名称最长的匹配变量 / 函数。上例中，匹配度最高的是变量 `object`，因此会采用它。结果为 `"This is a world."`。

变量会不断地被创建或删除，因此展开对象会随情况而变化。这是带范围展开所没有的特点。

```
request
{
   val   = "red"
   trans
   --
   value = "blue"
   trans
}

trans
{
    "%value"
}
```

`trans` 会执行两次，但第一次和第二次执行时，`"%value"` 的行为会有所不同。第一次会被解释为变量 `val` + `"ue"`，第二次则会被解释为变量 `value`。`request` 的输出为 `"redueblue"`。

### 重用展开结果

使用 `%[ ]` 格式，可以重用之前的展开结果。

```
request
{
    "「%planet」は遠い。「%city」も遠い。もっとも%[1]になら行けなくもない。"
}

planet
{
    "mars"
    "saturn"
    "pluto"
}

city
{
    "newyork"
    "moscow"
    "madrid"
}
```

`%[i]` 会获取第 i 个展开结果，索引从 0 开始。上例中，`%[0]` 表示 `%planet` 的展开结果，`%[1]` 表示 `%city` 的展开结果。

`%[ ]` 不能用于带范围展开。如果要在带范围展开中重用之前的结果，请先将其存入变量。

### 速度

名称最长匹配展开每次执行时都会重新搜索展开对象，因此与带范围展开相比，运行速度会大幅降低。除非确实需要使用，否则通常应使用带范围展开。

### 在读取时确定名称

名称最长匹配展开会根据执行时存在的变量来搜索名称。因此，包含 `%` 的字符串（例如 URL）可能会从某个时刻开始突然被替换。

```
"https://example.com/?p=100%off"  // 変数 o や of が作られると、その値に置き換わる
```

在配置文件中写入 `embed.lazy, off` 后（Tc604-1 及以后版本），不带括号的 `%` 后面的名称会在读取词典时确定。

- 名称通过用户自定义函数、系统函数，以及在词典表达式中写明名称的全局变量进行最长匹配来确定（也包括通过 `EVAL` 等执行的表达式）。仅从存档文件恢复的变量，或仅通过 `LETTONAME` 创建的变量，不会作为匹配对象。要嵌入这类变量时，请写作 `%(名称)`
- 如果已确定的变量尚无值，则结果为空字符串（不会保留为 `%名称`）
- 与任何名称都不匹配的内容会连同 `%` 一起作为原字符串处理。以英文字母或全角字符开头的内容会产生警告 W0031。像 `%E3` 这样的两位十六进制数（URL 编码），以及以数字或符号开头的内容不会产生警告
- 局部变量（`%_name`）仍会像以前一样在运行时搜索名称
- `%[i]` 的编号也会将仍作为原字符串保留的内容计为一个（`embed.lazy` 的设置不会改变编号）
