# 值的嵌套与多维赋值（Tc600-3 及以后）

Tc600-3 及以后，可以在数组元素、哈希值和哈希键中放入数组或哈希（**嵌套**）。要读写嵌套的内部内容，可以连续写 `[ ]`。直接给元素的元素赋值称为**多维赋值**。

在 500 系列中，数组元素只能是标量，`a[x][y] = v` 会在读取时产生错误 E0029。有关 500 系列的变更，请参阅 [600 中的变更](../other/changes-600.md)。

关于哈希本身，请参阅 [哈希](12-hash.md)。

## 创建嵌套结构

### 放入哈希值中

给哈希元素赋值时，数组和哈希都会直接成为其值。

```
_h = IHASH()
_h["list"] = (1, 2, 3)        // 値に配列
_h["sub"] = IHASH("x", 1)     // 値にハッシュ
```

在 [IHASH](../functions/IHASH.md) 的参数中写入数组时，数组会像其他函数中一样展开。`IHASH("list", (1, 2, 3))` 会变成与 `IHASH("list", 1, 2, 3)` 相同的内容，数组不会作为值放入其中。若要将数组作为值，请像上面那样在之后赋值。哈希不会展开，因此可以写成 `IHASH("sub", IHASH("x", 1))`。

### 将哈希放入数组元素

哈希不会通过 `,` 运算符或赋值给元素而展开，而是成为一个元素。

```
_h = IHASH("x", 1)
_a = (0, _h, 2)     // 要素数 3。_a[1] はハッシュ
_a[2] = _h          // 同上
_a ,= _h            // 末尾に追加
```

### 将数组放入数组元素

没有在数组中放入新数组的语法。无论是 `,` 运算符、`,=`，还是赋值给元素（`_a[1] = (8, 9)`），都会**展开右侧数组并插入**（与 500 系相同）。

```
_a = (1, 2)
_a[1] = (8, 9)      // 1,8,9 （要素数 3）
_a[1] = IARRAY()    // 1,9 （空の配列を差し込むと要素が消える）
```

但是，当赋值目标元素已经是数组或哈希时，不会展开，而是整体替换（Tc603-1 及以后。[整体改写内部的数组或哈希](#内側の配列やハッシュを丸ごと書き換える)）。

以下这类函数会返回包含数组的数组值。

- [HASH_VALUES](../functions/HASH_VALUES.md)：传入值为数组的哈希时，返回一个将该数组作为单个元素包含在内的数组
- [PARSEJSON](../functions/PARSEJSON.md) / [PARSEYAML](../functions/PARSEYAML.md) / [PARSETOML](../functions/PARSETOML.md) / [PARSEXML](../functions/PARSEXML.md)，以及从文件读取的 [FREADJSON](../functions/FREADJSON.md) 等函数
- [RESTOREVAR](../functions/RESTOREVAR.md)：恢复以嵌套形式保存的变量

```
_v = PARSEJSON('[[1,2,3],[4]]')   // 要素数 2。_v[0] は配列 (1,2,3)
```

如此得到的数组中的数组，也可以通过多维赋值来改写（Tc602-7 及以后。[中间值的行为](#途中の値ごとの動作)）。

### 逐步构建

内部哈希不会自动创建。先用 [IHASH](../functions/IHASH.md) 创建中间哈希，再向其中赋值。

```
_m = IHASH()
_m["a"] = IHASH()
_m["a"]["b"] = 1
_m["a"]["list"] = IARRAY()
_m["a"]["list"] ,= "p"
_m["a"]["list"] ,= "q"
DUMPJSON(_m)   // {"a":{"b":1,"list":["p","q"]}}
```

如果不创建中间哈希而写作 `_m["c"]["d"] = 1`，`_m["c"]` 就会变成数组 `(1)`，而不是哈希（[中间值的行为](#途中の値ごとの動作)）。

## 读取

连续书写 `[ ]` 时，会依次将第二个 `[ ]` 应用于第一个 `[ ]` 的结果，再将第三个应用于该结果……

```
_h = IHASH()
_h["list"] = (1, 2, 3)
_h["sub"] = IHASH("x", 1)
_a = (0, _h, 2)

_h["sub"]["x"]      // 1
_h["list"][1]       // 2
_a[1]["sub"]["x"]   // 1
_a[1]["list"]       // (1,2,3) そのものが返る
```

每个 `[ ]` 都会根据当时的值的类型，按以下方式运行。无论在哪一步，如果不存在对应的元素，就会变成与未定义变量相同的 VOID，后续的 `[ ]` 也会得到 VOID（不会报错。[超出范围的元素](05-arrays.md#範囲外の要素)）。

| 值 | `[x]` 的结果 |
|---|---|
| 数组 | 第 x 个元素。如果元素是数组或哈希，则原样返回 |
| 哈希 | 键 x 对应的值（[键的匹配](12-hash.md#キーの一致)） |
| 字符串 | 作为简易数组，返回第 x 个元素 |
| 数值 | 如果 x 为 0，则返回该值；否则返回 VOID |
| VOID（例如未定义的变量） | VOID |

在 Tc602-13 之前，超出数组范围、不存在的哈希键以及对 VOID 使用 `[ ]` 时，结果为空字符串（字符串和数值超出范围时，原本就会得到 VOID）。

也可以使用范围指定。数组的范围指定 `[a, b]` 会返回一个数组，其中包含原样保留的嵌套元素。如果超出范围，则返回空数组。哈希的范围指定会返回空字符串。

```
_v = PARSEJSON('[[1,2],[3,4],[5,6]]')
_v[0, 1]     // 要素数 2 の配列。どちらの要素も配列のまま
```

### 简易数组的分隔符

通过 [SETDELIM](../functions/SETDELIM.md) 为变量设置的分隔符，只对直接附加到该变量的第1层 `[ ]` 生效。将嵌套中的字符串作为简易数组读取时，需要在第2层及之后的 `[ ]` 中指定分隔符。

```
_s = "a|b"
SETDELIM(_s, "|")
_t = (_s, "c")
_t[0][1]         // VOID （2段目は "," で区切られるので範囲外）
_t[0][1, "|"]    // "b"
```

### 嵌入字符串

在字符串中也可以连续书写 `[ ]`。

```
"値は %_h['sub']['x'] です"      // 値は 1 です
"値は %(_h['list'][1]) です"     // 値は 2 です
```

嵌入嵌套数组或哈希本身时，会得到[字符串化](#文字列化と保存)后的结果。

## 函数的参数与 `,` 运算符

函数参数和 `,` 运算符只会展开**最外层数组**，其中的数组或哈希不会展开，而是作为一个元素保留。即使哈希位于最外层，也不会展开。

```
_v = PARSEJSON('[[1,2,3],[4]]')

func(_v)        // _argc は 2。_argv[0] は配列 (1,2,3)
func(_v[0])     // _argc は 3。_argv は 1,2,3
func(_v, 9)     // _argc は 3。_argv[0] は配列 (1,2,3)
_c = (_v, 9)    // 要素数 3。_c[0] は配列 (1,2,3)

ARRAYSIZE(_v)      // 2
ARRAYSIZE(_v[0])   // 3
```

将嵌套数组传给函数时，最外层数组本身会成为 `_argv`。接收方无法区分“一个数组参数”和“多个参数”，因此将嵌套数组传给函数时，最好将它包在哈希中，或者逐个传递数组元素。

将只有一个元素的数组传给 [GETTYPE](../functions/GETTYPE.md) 时，返回的是该元素的类型，而不是数组类型（与 500 系相同）。在上面的例子中，`GETTYPE(_v[1])` 返回的是 1，而不是 4。

## foreach

也可以用 foreach 遍历嵌套数组或哈希。循环变量会直接取得元素的值，因此如果元素是数组或哈希，也可以继续用 foreach 遍历，或者用 `[ ]` 读取。

```
_h = PARSEJSON('{"a":{"x":1,"y":2},"b":{"x":3}}')
foreach _h ; _k, _sub {
  foreach _sub ; _k2, _v {
    // _k/_k2 = _v の順に a/x=1, a/y=2, b/x=3
  }
}

foreach _h["a"] ; _k, _v { ... }   // 内側だけを回す
```

关于带两个变量的 foreach，请参阅[哈希](12-hash.md#foreach)和[流程控制](07-flow-control.md#foreach-ループ)。

## 值的复制

赋值和传递参数都会复制值。包括嵌套的内部值在内，源值和目标值互不影响。

```
_h = IHASH("a", 1)
_h["self"] = _h
_h["self"]["a"] = 2
_h["a"]             // 1 のまま
```

即使取出内部值并修改，原值也不会改变。要修改原值，需重新赋入修改后的值，或使用多维赋值。

```
_sub = _h["self"]
_sub["a"] = 3        // _h["self"]["a"] は 2 のまま
_h["self"] = _sub    // これで _h["self"]["a"] が 3 になる
```

## 比较

比较两个数组或两个哈希的 `==` 时，会比较其内容。嵌套的内部值也会按照相同规则递归比较。

- 两个数组：元素数量相同，且各元素依次相等时为真
- 两个哈希：元素数量、键和值全部一致时为真（[作为值时的行为](12-hash.md#値としての振る舞い)）

```
PARSEJSON('{"a":[1,2]}') == PARSEJSON('{"a":[1,2]}')   // 1
```

用 [ASEARCH](../functions/ASEARCH.md) 搜索元素为哈希的数组时，也会按照相同规则进行比较。但是，将数组作为要搜索的值传入时，它会被展开为参数，因此无法搜索数组本身。

[ASORT](../functions/ASORT.md) 会将数组或哈希元素转换为字符串后进行排序（在 `int` / `double` 中视为 0）（[元素为数组或哈希时](../functions/ASORT.md#要素が配列やハッシュのときtc600-3以降)）。

## 多维赋值

可以直接赋值给元素的元素。除 `=` 外，也可以使用 `+=`、`,=` 等所有赋值运算符。

```
_h["sub"]["x"] = 5
_h["list"][0] += 10
_h["list"] ,= 4               // 内側の配列の末尾に追加
_a[1]["sub"]["y"] = "new"
```

与一维赋值相同，右侧的值会放入最后一个 `[ ]` 所在的位置。因此，如果该位置的元素是标量，右侧的数组会展开并插入。要整体替换内部数组时，应赋值给前一层。

```
_h["list"] = (1, 2, 3)
_h["list"][0] = (7, 8)    // _h["list"] は 7,8,2,3
_h["list"] = (7, 8)       // _h["list"] を (7,8) に置き換える
```

范围赋值（`_h["list"][0, 1] = "R"`）也可以像一维赋值一样使用。

### 整体改写内部数组或哈希

使用非范围赋值，且赋值目标元素当前是**数组或哈希**时，不展开右侧的值，而是整体替换该元素（Tc603-1 及之后版本）。对于数组中的数组，也可以像赋值给前一层一样进行替换、追加和逐元素计算。

```
_v = PARSEJSON('[[1,2],[3,4]]')
_v[0] = (7, 8, 9)     // _v は (7,8,9),(3,4)   丸ごと置き換える
_v[0] ,= 5            // _v は (7,8,9,5),(3,4) 内側の末尾に追加する
_v[0] += 1            // _v は (8,9,10,6),(3,4) 内側の要素ごとに計算する
_v[0] = _v[0]         // 変わらない
_v[0] = IARRAY        // _v は (),(3,4)        空の配列に置き換える（要素は消えない）
_v[0, 0] = IARRAY     // _v は (3,4)           範囲指定なら展開して差し込む（要素を消す）
```

- 赋值目标元素为标量或超出范围（尚不存在）时，仍按以往方式展开并插入右侧数组（插入 `_a[1] = (8, 9)`，删除 `_a[1] = IARRAY`）
- 范围赋值无论元素类型如何，都会展开并插入（与 Python 的切片赋值相同）。要删除内部数组本身，请写作 `_v[0, 0] = IARRAY`
- 根为哈希时（`_h["list"] = ...`），本来就会整体替换
- 500 系没有嵌套数组，因此 500 系词典的行为不会改变

在 Tc602-13 及之前的版本中，当根为数组时，内部数组会被展开，导致嵌套结构被破坏（`_v[0] = _v[0]` 会使 `_v` 变成 `1`、`2`、`(3,4)` 这 3 个元素；`_v[0] ,= 5` 会使其变成 `1`、`2`、`5`、`(3,4)` 这 4 个元素）。

### 中间值各自的行为

多维赋值会从最后一层开始，逐层改写每一层的值，再将其放回前一层，直到根变量。各层的值会根据其类型按如下方式处理。

| 中间值 | 行为 |
|---|---|
| 哈希 | 添加或覆盖键的值 |
| 数组 | 改写元素。超出范围时，用 VOID 填补缺少的部分，并追加到末尾 |
| 字符串 | 作为简易数组改写 |
| 数值 | 转换为数组后改写。第 0 个元素会变成 VOID，原数值会丢失 |
| 不存在（超出范围或键不存在） | 与未定义变量相同，创建通用数组后改写 |

```
_a = ("p,q", 1)
_a[0][1] = "Q"        // _a[0] は "p,Q"

_h = IHASH("l", (1, 2))
_h["l"][4] = 9        // _h["l"] は 1,2,VOID,VOID,9

_n = (1, 2.5)
_n[1][2] = 9          // _n[1] は配列 (VOID,VOID,9)

_e = IHASH()
_e["n"]["x"] = 5      // _e["n"] は配列 (5) （ハッシュは作られない）
_e["m"][2] = 5        // _e["m"] は配列 (VOID,VOID,5)
```

`_e["n"]["x"] = 5` 会使 `_e["n"]` 变成 `(5)`，这是因为将键 `"x"` 作为数组序数读取时，它对应第 0 个元素。结果与对未定义变量执行 `_x["x"] = 5` 相同。

在 Tc602-13 及之前的版本中，不存在的层会作为空字符串的简易数组进行改写，因此 `_e["n"]` 会变成字符串 `"5"`，`_e["m"]` 会变成字符串 `",,5"`。

将改写后的值放回前一层时，即使该值是数组，也不会展开，而是作为一个元素整体替换。右侧数组只会在最后一层展开，因此数组中的数组也能保持嵌套结构进行改写。

```
_v = PARSEJSON('[[1,2],[3,4]]')
_v[0][0] = "A"        // _v は ("A",2),(3,4)
_v[1][0] = (7, 8)     // _v は ("A",2),(7,8,4)
```

但是，如果中间层使用范围指定（`_v[0, 1][0] = 9`），则会先改写取出的范围数组，再将其展开并放回原范围。

在 Tc602-6 及之前的版本中，对数组中的数组进行多维赋值时，改写后的内部数组会展开到外层数组中，导致嵌套结构被破坏（在上面的 `_v[0][0] = "A"` 中，`_v` 会变成 `"A"`、`2`、`(3,4)` 这 3 个元素）。中间值为数值时，创建的数组也会展开到外层。引用传递（`&_v[0][0]`）的写回也一样。

### 赋值的根

赋值的根必须是变量。`(式)[0] = 1` 或 `func()[0] = 1` 等都会导致错误 E0029。

### 引用传递

[反馈运算符](04-arithmetic.md#フィードバック演算子)（引用传递）也可以传递元素的元素（Tc600-4 及以后版本）。在 `func(&_h["sub"]["x"])` 中改写 `_argv[0]`，`_h["sub"]["x"]` 也会改变。在 Tc600-3 中，前面的维度会被忽略，值会被写入 `_h["x"]`。

## 字符串化与保存

将嵌套值转换为字符串时（[TOSTR](../functions/TOSTR.md)、与字符串连接、嵌入等），内部的值也会原样用 `,` 或 `=` 连接起来，因此无法分辨哪些部分属于内部值。

```
_h = IHASH()
_h["l"] = (1, 2)
_h["m"] = IHASH("x", 1)
TOSTR(_h)    // "l=1,2,m=x=1"
```

需要保留嵌套结构进行处理时，请使用以下方法。

| 目的 | 方法 |
|---|---|
| 将变量保存到文件并恢复 | [SAVEVAR](../functions/SAVEVAR.md) / [RESTOREVAR](../functions/RESTOREVAR.md)。嵌套值会以 `IARRAY{...}` / `IHASH{...}` 的形式保存（[保存格式](../functions/SAVEVAR.md#保存形式)） |
| 查看内容 | [DUMPVAR](../functions/DUMPVAR.md)（Tc600-4 及以后版本）。嵌套值会以 `(array)[ ... ]` / `(hash){ ... }` 的形式显示。[LOGGING](../functions/LOGGING.md)（Tc602-8 及以后版本）也会将嵌套数组用 `( )`、哈希用 `{ }` 括起来输出 |
| 转换为字符串后传递 | [DUMPJSON](../functions/DUMPJSON.md) 和 [PARSEJSON](../functions/PARSEJSON.md)。但 JSON 无法表示的区别（整数键和字符串键、VOID 和空字符串等）会丢失。若要保留这些区别，请使用 [SERIALIZEVAR](../functions/SERIALIZEVAR.md) 和 [DESERIALIZEVAR](../functions/DESERIALIZEVAR.md)（Tc607-3 及以后版本）。生成的字符串与存档文件使用相同格式 |

## 限制

- 键为数组的哈希，由于 `h[キー]` 的序数的第 1 个元素会成为键，因此无法以数组作为键进行查找（可以通过 foreach 或 [HASH_KEYS](../functions/HASH_KEYS.md) 取出）。键为哈希时，则可以通过 `h[キー]` 查找
