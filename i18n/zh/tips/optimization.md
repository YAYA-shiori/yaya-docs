## 高速化调优

**警告！**即使不进行这里介绍的修改，通常也完全没有问题。<br>
由于可能导致意料之外的问题，请谨慎使用。

### 前言

献给不怕当小白鼠的人：AYAv5 的高速化调优。<br>
非常适合急性子。

### 加快启动速度

使用 AYA 的人格往往都有启动速度慢这一共同缺点，这也让很多人颇为烦恼。这里介绍一些简单的启动加速调优方法。

#### 安装了很多人格的环境中启动缓慢

如今安装的人格总数膨胀到四位数左右，安装数量达到三位数的环境也应该不少。
……这倒没什么，但 baseware 通知的人格信息也变得很庞大，AYA 解析这些信息时会很费劲，这是个棘手的问题。

#### 简单的 Tips

**小白鼠指数**：★★☆☆☆

解决方法很简单，只要把 aya_shiori3.dic 开头部分的一些 #define

```
#define IGLIST_MAX 0
#define REQUEST_LINES_LIMIT 30
```

修改成这样即可。

**IGLIST_MAX**：AYA 有一项功能，可以不依赖 baseware，自行在内部搜索已安装人格的信息。此项设置用于指定是否启用该功能，设为 0 时禁用，设为 -1 时不限制。若不需要此功能，禁用即可，完全没有问题。

**REQUEST_LINES_LIMIT**：baseware 和人格之间通过多行字符串进行通信。此设置的设计初衷是限制解析这些字符串的行数，从而避免因通知信息过多而导致解析费时。

另外，对于需要处理已安装的人格/对话框等信息的人格来说，修改这些设置可能会引发问题。

#### 给想再多尝试一些的人看的 Tips

**小白鼠指数**：★★★★☆

……那么，给还是忍无可忍！的人准备的 Tips。直接禁用获取人格信息的功能吧。

### 随机对话出现得很慢

终于完成了呕心沥血之作！随机对话居然有几百条！！<br>
……但是，它怎么这么慢……

这是为某些特殊情况准备的加速 Tips。

这是在支持论坛或日记中 umeici 提到的 Tips 的扩展版。现在可以在最新版 AYA 中使用。

#### 使用单引号加速

**小白鼠指数**：★★★★☆

随机对话大概是写在 aya_aitalk.dic 里的吧。

```
RandomTalk
{
   "ごにょごにょ"
}
```

大概就是这样。

用 " " 括起来，直接写一大串 Sakura Script，不过实际上在新版 AYA 中，除了 " " 之外，还可以使用 ' '。

这和加速有什么关系！在解释之前，先来看修改示例。<br>
总之，先别管原理、想马上用起来的人，把下面的内容复制粘贴过去就行。

```
RandomTalk
{
    TOSTR(EVAL(CHR(0x22)+RandomTalkEx()+CHR(0x22)))
}

RandomTalkEx
{
    'ごにょごにょ'
}
```

没错，只是把原来的 RandomTalk 随便改了个名字（这里改成了 RandomTalkEx），把正文的包围符改成 ' '，再加上一个带着奇怪命令的 RandomTalk 而已。((外层的 TOSTR 大概不需要，不过为了保险起见还是加上了。介意的话就把它删掉吧。))

……接下来说明其中的原理。

AYA5 新版本中引入的 ' ' 表示**不展开 %()**。<br>
详情请参阅 AYA 手册；使用 %hogehoge、%(hogehoge) 等形式，可以嵌入变量、函数或表达式，而用 ' ' 括起来后，这些嵌入都会失效。

原来的 " " 形式需要解析所有嵌入处理并计算结果，而使用 ' ' 时，被括起来的部分只会被当作普通字符串，因此几乎不需要进行任何处理。

请回想一下 AYA 的行为：函数中的所有内容都会被求值，然后从中取一个结果作为随机结果（或者根据选项取其中一个）。

……先不管这番复杂的解释，总之，**写了几百条随机对话，就得执行几百次 %() 处理**，因此可以想象这会让运行变慢。((熟悉 AYA 实际内部处理方式的人可能会提出异议，不过这里仅作易于理解的说明))

那么，RandomTalkEx 改名部分的说明到此为止，但如果只这样修改，%() 中的内容就不会被正确嵌入。解决这个问题的方法是：

```
TOSTR(EVAL(CHR(0x22)+RandomTalkEx()+CHR(0x22)))
```

TOSTR 是“作为字符串处理”的命令，不过在这里没有什么特别的意义。**关键是 EVAL 及其括号中的内容**。

EVAL 是“将括号括起来传入的内容作为 AYA 脚本执行”的命令。而 CHR(0x22) 就是 "。

……大概已经能看出它在做什么了。EVAL 执行的脚本会是：

```
" + RandomTalkExの結果 + "
```

这样就构造出了执行 %() 嵌入处理的表达式。<br>
原本必须反复执行几百次的 %() 处理，现在只需执行这段 EVAL 括起来的内容一次，这就是它能变快的诀窍。
